## 3. 바꾸는 것 (안)

### 3.1 고객센터 화면

- 제출하면 서버에 문의를 저장한다. 성공하면 접수 안내, 실패하면 오류 안내를 띄우고 폼을 그대로 둔다.
- 문의 유형은 서버의 코드 목록에서 받아 보인다.
- 로그인한 고객이면 이름·이메일을 회원 정보로 채우고 문의를 회원과 묶는다.
- 공통 틀(components/layout/)은 고치지 않는다.

### 3.2 관리자 알림

- 문의가 저장되면 관리자에게 메일을 보낸다. 받는 주소는 설정값(system_settings)에 두고, 비어 있으면 관리자 계정 전원에게 보낸다.
- 메일 발송 실패가 문의 접수를 막지 않는다. 문의는 저장되고 발송 결과는 알림 이력에 남는다.

### 3.3 관리자 문의 화면 (컨셉)

- 메뉴: 관리자 왼쪽 메뉴에 "1:1 문의" 를 더한다.
- 목록 `/inquiries`
  - 위: 상태 거르기(전체, 미답변, 답변완료), 유형 거르기, 미답변 건수
  - 표: 접수 일시, 유형, 제목, 이름, 이메일, 회원 여부, 상태. 최근 접수가 위
  - 누를 것: 행을 누르면 상세로. 상세에서 돌아오면 보던 거르기와 스크롤 위치 그대로
- 상세 `/inquiries/{id}`
  - 문의 영역: 유형, 제목, 본문, 이름, 이메일, 회원이면 회원 표시, 접수 일시, 관리자 알림 발송 결과
  - 답변 영역: 4.2 의 결정에 따른다. ①이면 답변 입력 칸과 "답변 보내기" 단추, 보낸 뒤에는 답변 본문·보낸 시각·보낸 관리자를 보인다

### 3.4 데이터·API (안)

- 테이블: inquiries (유형, 제목, 본문, 이름, 이메일, 회원, 상태, 답변, 답변 시각, 답변 관리자, 접수 시각), inquiry_types (코드 목록, 순서, 사용 여부). Flyway 로 넣고 운영에는 백엔드 배포 때 들어간다.
- 고객: 문의 유형 목록 조회, 문의 등록
- 관리자: 문의 목록, 문의 상세, 답변 보내기(4.2 ①일 때)
- 설정: 문의 알림 받는 주소

### 4.2 비로그인 문의

1. 비로그인도 문의 가능, 로그인 고객은 회원과 묶음 (권장). 지금 고객센터가 로그인 없이 열리고 이름·이메일을 받는다. 가입 전 문의가 가장 많을 곳이다
2. 로그인한 고객만 문의 (잃는 것: 가입 전 문의, 고객센터에서 로그인 화면으로 보내야 함)

### 4.3 고객에게 답 돌려주기

1. 관리자가 콘솔에서 답변을 쓰면 시스템이 고객 이메일로 보내고 답변을 남긴다 (권장). 비로그인 고객에게 닿는 길은 메일뿐이고, 누가 언제 무엇을 답했는지가 남는다
2. 관리자가 자기 메일로 직접 회신하고 콘솔에서는 답변완료 표시만 (잃는 것: 답변 기록, 누가 답했는지)

### 4.4 알림 메일 틀

1. bp-notification 에 문의용 메일 틀을 새로 등록 (권장). 관리자 접수 알림 하나, 4.3 ①이면 고객 답변 메일 하나. 등록은 bp-notification 관리자 계정으로 하는 운영 작업이라 따로 허락을 받고 한다
2. 있는 틀(입찰 신청 알림)을 빌려 씀 (잃는 것: 메일 제목·본문이 "새 입찰 신청" 으로 나가 문의 내용이 제대로 안 보임, 고객 답변 메일은 쓸 틀이 없음)

## 6. CR-133 과의 계약

CR-133 의 상담형 화면이 문의 단추를 누르면 고객센터 1:1 문의를 유형과 제목을 채워 연다.

- 주소: `/support?type=<유형코드>&title=<제목>`. 두 값 모두 URL 인코딩, 둘 다 생략 가능
- 열리면: 1:1 문의 폼으로 내려가고 유형과 제목이 채워진다. 고객이 고칠 수 있다
- 모르는 유형 코드이거나 사용하지 않는 유형이면 무시하고 기본 유형(목록 첫 번째)을 고른다
- 유형 코드 (DB 코드 목록 inquiry_types 가 정본, `GET /api/inquiries/types`)

| 순서 | 코드 | 이름 |
|------|------|------|
| 1 | SERVICE | 서비스 이용 문의 |
| 2 | CONSULTING | 서비스 상담 |
| 3 | SAM_REGISTRATION | SAM.gov 등록 문의 |
| 4 | PROPOSAL | 제안서 자문·검토 문의 |
| 5 | PAYMENT | 결제·환불 문의 |
| 6 | ETC | 기타 |

- 접수 API: `POST /api/inquiries` `{ typeCode, title, content, name, email }`. 비로그인 가능, 로그인 상태면 회원과 묶는다

- 고객 화면 "새 문의 쓰기" 는 이름과 이메일을 남기고 나머지만 비운다
- 관리자 목록의 기본 거르기는 미답변이다(목업 기준)

### 7.3 로컬 확인 (도커 MariaDB·Redis, 가짜 알림 수신기, bootRun 8183, 관리자 3184, 고객 3183)

- 서버 시험 전체 206건 통과(새 시험 TC-INQ-001~012 포함)
