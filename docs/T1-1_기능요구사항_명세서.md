## 기능 상세

### A. 인증

#### BID-AUTH-001 | 회원가입
- **모듈**: A. 인증 > A1. 회원가입
- **설명**: 이메일/비밀번호로 회원가입. 고객은 회사 정보 포함
- **입력**: 이메일, 비밀번호, 이름, 회사명, 전화번호
- **출력**: JWT 토큰, 회원 정보
- **제약조건**: 이메일 중복 불가, 비밀번호 8자 이상
- **우선순위**: High | **MVP**: Y | **상태**: 구현완료(기존)

#### BID-AUTH-002 | 로그인
- **모듈**: A. 인증 > A2. 로그인
- **설명**: 이메일/비밀번호로 로그인하여 JWT 토큰 발급
- **입력**: 이메일, 비밀번호
- **출력**: Access Token (15min) + Refresh Token (7day)
- **제약조건**: —
- **우선순위**: High | **MVP**: Y | **상태**: 구현완료(기존)

#### BID-AUTH-003 | 토큰 갱신
- **모듈**: A. 인증 > A3. 토큰
- **설명**: Refresh Token으로 Access Token 재발급
- **입력**: Refresh Token
- **출력**: 새 Access Token
- **제약조건**: 만료된 Refresh Token은 거부
- **우선순위**: High | **MVP**: Y | **상태**: 구현완료(기존)

#### BID-AUTH-004 | 로그아웃
- **모듈**: A. 인증 > A3. 토큰
- **설명**: 현재 세션 무효화
- **입력**: Access Token
- **출력**: 성공 응답
- **제약조건**: —
- **우선순위**: Medium | **MVP**: N | **상태**:

### B. 공고 수집

#### BID-OPP-001 | SAM.gov 스케줄 수집
- **모듈**: B. 공고 수집 > B1. 자동 수집
- **설명**: SAM.gov API를 주기적으로 호출하여 USFK 관련 공고를 수집. 증분 동기화(최신 게시일 - 1일) 또는 fallback 7일. 콘텐츠 해시 기반 중복 검출. Raw JSON 원본 보존
- **입력**: 키워드 목록 (설정), 수집 주기 (cron)
- **출력**: 신규/갱신된 공고 목록
- **제약조건**: SAM.gov API Key 필요. 페이지당 1000건 제한
- **우선순위**: High | **MVP**: Y | **상태**: 구현완료(기존)

#### BID-OPP-002 | 수동 수집 트리거
- **모듈**: B. 공고 수집 > B2. 수동 수집
- **설명**: 관리자가 즉시 수집을 실행할 수 있는 기능
- **입력**: (선택) 키워드, 기간
- **출력**: 수집 결과 (건수, 신규/갱신)
- **제약조건**: ADMIN 역할만 가능
- **우선순위**: Medium | **MVP**: N | **상태**: 구현완료(기존)

#### BID-OPP-003 | 첨부문서 자동 획득
- **모듈**: B. 공고 수집 > B3. 첨부문서
- **설명**: SAM.gov 공고에 포함된 첨부문서를 자동 다운로드. 링크 형태인 경우 해당 링크를 따라가서 다운로드. 다운로드 불가 시 링크만 저장하여 사용자에게 제공
- **입력**: 공고 ID (수집 시 자동)
- **출력**: 다운로드된 첨부파일 (MinIO) 또는 링크 URL
- **제약조건**: 파일 크기 제한 (50MB), 지원 형식 (PDF, DOCX, XLSX, ZIP 등)
- **우선순위**: High | **MVP**: Y | **상태**: **신규**

#### BID-OPP-004 | 수집 완료 이메일 알림
- **모듈**: B. 공고 수집 > B4. 알림
- **설명**: 새로운 공고가 수집되면 관리자에게 이메일로 알림. 신규 공고 건수, 주요 공고 제목 요약 포함
- **입력**: 수집 결과
- **출력**: 이메일 발송
- **제약조건**: 신규 공고가 0건이면 알림 미발송 (정책으로 관리)
- **우선순위**: High | **MVP**: Y | **상태**: **신규**

#### BID-OPP-005 | 수집 통계 조회
- **모듈**: B. 공고 수집 > B5. 통계
- **설명**: 수집 이력, 성공/실패 건수, 마지막 수집 시각 등 통계 조회
- **입력**: 기간 필터
- **출력**: 수집 통계 데이터
- **제약조건**: ADMIN 역할
- **우선순위**: Low | **MVP**: N | **상태**: 구현완료(기존)

#### BID-OPP-006 | 공고 사전 분석 (CR-003)
- **모듈**: B. 공고 수집 > B6. 사전 분석
- **설명**: 공고 첨부파일(PWS/RFP 등) 다운로드 완료 시 자동으로 LLM 분석을 트리거하여, 공고 단위로 1회만 분석 결과를 생성한다. 분석 결과: ①공고 요약본, ②문서 양식(어떤 문서를 어떤 구조로 작성해야 하는지), ③필요 서류 목록(사용자가 준비해야 할 서류), ④LLM 프롬프트 프리셋(추후 문서 작성 시 LLM에게 전달할 컨텍스트). 관리자가 수동 업로드(BID-OPP-007) 후에도 동일하게 트리거
- **입력**: 공고 ID (첨부파일 다운로드 완료 이벤트 또는 관리자 수동 트리거)
- **출력**: OpportunityAnalysis 엔티티 (요약, 양식, 필요서류, 프롬프트 프리셋)
- **제약조건**: 공고당 1회 분석 (이미 분석 완료된 공고는 스킵 또는 재분석 선택). Aimbase Workflow 연동
- **우선순위**: High | **MVP**: Y | **상태**: **신규** (CR-003)

#### BID-OPP-007 | 관리자 첨부파일 수동 업로드 (CR-003)
- **모듈**: B. 공고 수집 > B7. 수동 업로드
- **설명**: SAM.gov에서 첨부파일이 없거나 다운로드 실패한 공고에 대해, 관리자가 직접 첨부파일(PWS/RFP 등)을 업로드. 업로드 완료 시 BID-OPP-006 사전 분석이 자동 트리거됨
- **입력**: 공고 ID, 파일 (multipart)
- **출력**: OpportunityAttachment 생성 + 사전 분석 트리거
- **제약조건**: ADMIN 역할. 파일 크기 50MB 이하
- **우선순위**: High | **MVP**: Y | **상태**: **신규** (CR-003)

#### BID-OPP-008 | 공고 노출 승인 (CR-003)
- **모듈**: B. 공고 수집 > B8. 노출 관리
- **설명**: 공고 사전 분석 완료 후, 관리자가 분석 결과를 검수하고 승인하면 사용자 페이지에 노출(VISIBLE). 승인 전까지는 비노출(HIDDEN) 상태. 관리자는 분석 결과를 보정할 수 있음
- **입력**: 공고 ID, 승인/반려
- **출력**: Opportunity.visibility → VISIBLE
- **제약조건**: ADMIN 역할. 사전 분석이 COMPLETED 상태여야 승인 가능
- **우선순위**: High | **MVP**: Y | **상태**: **신규** (CR-003)

### C. 공고 열람

#### BID-BROWSE-001 | 공고 목록 조회
- **모듈**: C. 공고 열람 > C1. 목록
- **설명**: 수집된 공고를 페이징/필터/검색으로 조회
- **입력**: 검색어, 필터 조건 (날짜, 상태 등), 페이지 정보
- **출력**: 공고 목록, 총 건수
- **제약조건**: 사용자 페이지에서는 visibility=VISIBLE인 공고만 노출 (CR-003). 관리자는 전체 조회 가능
- **우선순위**: High | **MVP**: Y | **상태**: 구현완료(기존), **개선** (CR-003: visibility 필터)

#### BID-BROWSE-002 | 공고 상세 조회
- **모듈**: C. 공고 열람 > C2. 상세
- **설명**: 공고의 전체 정보 + 추출된 요구사항 목록 + 첨부문서 목록 표시
- **입력**: 공고 ID
- **출력**: 공고 상세 정보, 요구사항 목록, 첨부파일 목록
- **제약조건**: —
- **우선순위**: High | **MVP**: Y | **상태**: 구현완료(기존), 개선 필요

#### BID-BROWSE-003 | 필요 문서 목록 표시
- **모듈**: C. 공고 열람 > C3. 필요 문서
- **설명**: 입찰 시 제출해야 하는 필요 문서 목록을 공고 요구사항에서 추출하여 보기 좋게 정리. 카테고리별 분류 (DOCUMENT, CERTIFICATION, EXPERIENCE 등), BLOCKER 표시
- **입력**: 공고 ID
- **출력**: 카테고리별로 정리된 필요 문서 목록, BLOCKER 여부
- **제약조건**: AI 요구사항 추출이 선행되어야 함
- **우선순위**: High | **MVP**: Y | **상태**: **신규** (기존 요구사항 데이터를 활용한 FE 개선)

#### BID-BROWSE-004 | 북마크 (즐겨찾기)
- **모듈**: C. 공고 열람 > C4. 북마크
- **설명**: 관심 공고를 즐겨찾기에 등록/해제/목록 조회
- **입력**: 공고 ID
- **출력**: 북마크 상태
- **제약조건**: 로그인 사용자만
- **우선순위**: Low | **MVP**: N | **상태**: 구현완료(기존)

### D. 입찰 접수

#### BID-REQ-001 | 입찰 참여 신청
- **모듈**: D. 입찰 접수 > D1. 신청
- **설명**: 고객이 공고에 대해 입찰 참여 의사를 밝힘. 입찰 요청(BidRequest)이 CREATED 상태로 생성됨
- **입력**: 공고 ID, (선택) 메모
- **출력**: 생성된 입찰 요청 정보
- **제약조건**: 동일 공고에 중복 신청 불가 (정책으로 관리)
- **우선순위**: High | **MVP**: Y | **상태**: 구현완료(기존), 단순화

#### BID-REQ-002 | 필요 문서 업로드
- **모듈**: D. 입찰 접수 > D2. 문서 제출
- **설명**: 고객이 입찰에 필요한 문서를 업로드. 필요 문서 체크리스트 기반으로 각 항목에 파일 첨부
- **입력**: 입찰 요청 ID, 문서 타입, 파일
- **출력**: 업로드 결과, 체크리스트 진행률
- **제약조건**: 파일 크기 50MB 이하, 지원 형식 (PDF, DOCX, XLSX, JPG, PNG)
- **우선순위**: High | **MVP**: Y | **상태**: **개선** (기존 워크플로우 단순화)

#### BID-REQ-003 | 내 입찰 목록 조회
- **모듈**: D. 입찰 접수 > D3. 조회
- **설명**: 고객이 자신의 입찰 요청 목록을 조회 (상태별 필터)

### P. 성공 제안서 패턴 (CR-013)

#### BID-RFP-001 | 성공 제안서 등록
- **모듈**: P. 성공 제안서 패턴 > P1. 등록
- **설명**: 관리자가 과거 성공/낙찰 제안서 1건(RfpSample)을 등록. 메타데이터(공고번호/사업유형/결과)와 원본 파일들, 선택적으로 PWS 공고문을 업로드. 업로드 시 파일 텍스트를 1회 추출해 저장(패턴 추출·검색용). 원본 파일은 로컬 디스크에 불변 보관
- **입력**: 메타(필수: 공고번호, 사업유형, 결과 WON·SUBMITTED·OTHER / 선택: 업체, 발주처, 낙찰액, 회계연도), 원본 파일들(pdf/xlsx/docx), 선택 PWS
- **출력**: 등록된 RfpSample + 파일 목록 (텍스트 추출 상태 포함)
- **제약조건**: ADMIN 역할. 파일 50MB 제한. 텍스트 추출 실패(브로슈어형 PDF)는 허용 — extraction_status=FAILED로 표시 후 수동 보정
- **우선순위**: High | **MVP**: Y | **상태**: **신규** (CR-013)

#### BID-RFP-002 | 7슬롯 배치
- **모듈**: P. 성공 제안서 패턴 > P2. 슬롯 배치
- **설명**: 등록된 제안서의 각 파일/섹션을 표준 7슬롯(사업자자격/과거경험/핵심인력/인력배치/장비/실적/가격 + 기타) 중 하나에 배치. 시스템이 파일명/내용으로 슬롯 자동추정(관리자 확인 토글), 빈 슬롯은 "이 데이터 어디 있어? 넣어줘"로 역요구하여 누락 방지. 슬롯 정의는 DB 시드(slot_definition)로 관리 — 코드 하드코딩 아님
- **입력**: RfpSample ID, 슬롯 코드, 파일 ID 또는 섹션 텍스트, (기타 슬롯 시)라벨
- **출력**: 슬롯별 배치 현황 + 빈 슬롯 목록
- **제약조건**: ADMIN 역할. 같은 표준 1세트로 강제(공고마다 FACTOR 이름 달라도 같은 축으로 누적)
- **우선순위**: High | **MVP**: Y | **상태**: **신규** (CR-013)

#### BID-RFP-003 | 슬롯별 패턴 추출
- **모듈**: P. 성공 제안서 패턴 > P3. 패턴 추출
- **설명**: 같은 슬롯에 모인 여러 건(RfpSample들의 동일 슬롯 데이터)을 비교해 그 축의 공통 "이기는 패턴"을 AI(Aimbase 워크플로우)로 추출 → 슬롯별 가이드(PatternGuide) 생성. 관리자가 수동 트리거 → AI 초안 → 관리자 검수/수정 → 저장. 부분 재추출 가능(슬롯 단위, "인력배치만 다시")
- **입력**: 슬롯 코드, (선택)사업유형
- **출력**: 슬롯별 패턴 가이드(8블록 골격/체크리스트/금기), 추출 상태(PENDING/EXTRACTING/COMPLETED/FAILED)
- **제약조건**: ADMIN 역할. 동일 슬롯 2건 이상 모였을 때만 추출(BIZ-016). Aimbase 연동(로컬→14.63.25.49:8280 접근 불가 시 배포환경에서 E2E)
- **우선순위**: High | **MVP**: Y | **상태**: **신규** (CR-013)

#### BID-RFP-004 | 패턴 가이드 조회/편집
- **모듈**: P. 성공 제안서 패턴 > P4. 가이드 관리
- **설명**: 슬롯별 추출된 가이드를 조회하고, 작성 노하우 많은 전문가가 직접 편집. 출처(source) 구분 — AI_EXTRACTED는 재추출 시 자동갱신 가능, HUMAN_EDITED/HUMAN_ADDED는 보호되어 자동추출이 덮어쓰지 않음(BIZ-017). 살아있는 가이드(성공 제안서 쌓일 때마다 갱신)
- **입력**: 슬롯 코드, 편집 본문(markdown/json)
- **출력**: 가이드 본문 + 출처 표시 + 추출에 쓰인 건수
- **제약조건**: ADMIN 역할. 사람 편집분(HUMAN_*)은 자동추출 보호
- **우선순위**: High | **MVP**: Y | **상태**: **신규** (CR-013)
