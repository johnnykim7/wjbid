# SAM.gov Bidding Agency Platform 화면 상호작용 명세서

> 설계 버전: 1.14 | 최종 수정: 2026-10-15 | 관련 CR: CR-131, CR-132, CR-133, CR-135, CR-136, CR-137, CR-140, CR-141, CR-142, CR-146, CR-147, CR-152, CR-153, CR-155, CR-157, CR-159, CR-162

> 단계: 3. Detail Design | FE/풀스택 프로젝트에서 작성
>
> T3-3(화면 구조)이 "무엇이 있는지"를 정의한다면,
> 이 문서는 "어떻게 동작하는지"를 정의한다.
> 모든 페이지를 작성하지 않는다 — 복잡한 인터랙션이 있는 페이지만 작성한다.

## 작성 대상

| 페이지 | 사유 |
|--------|------|
| 공고 상세 — 입찰 신청 | 다단계 흐름 (서비스 레벨 선택 → 신청) + 자격 진단 연동 |
| 원본 공고 상세 (CR-152) | 공고문이 생기면 공고 상세로 전환, 공고문에 붙는 단추 숨기기 |
| 마감 전 공고를 모은 공고로 (CR-155) | 목록, 검색, 첫 화면이 같은 기준. 줄마다 공고문 상세와 원본 공고 상세로 갈림, 관심 공고 번호, 한글 본문과 원문 접기 |
| 입찰 상세 — 문서 업로드 | 파일 업로드 + 진행률 + 상태 자동 전이 |
| 문서 편집 (Admin) | TipTap 에디터 + 버전 관리 + 잠금/해제 + PDF 내보내기 |
| 입찰 상세 관리 (Admin) | FSM 상태 전이 UI + 조건부 액션 |
| 로그인·회원가입 (CR-131, CR-146) | 칸별 입력 오류, 이미 가입된 이메일, 가입 직후 안내, 이메일 인증번호, SNS 왕복과 SNS 가입 |
| 고객센터 1:1 문의 (CR-132) | 비로그인 접수, 로그인 채움, 주소로 유형·제목 채움, 접수 실패 |
| 1:1 문의 관리 (Admin, CR-132) | 거르기와 돌아오기, 답변 메일 성공·실패, 이미 답변된 문의 |

## 원본 공고 상세 (`/search/origin/{opportunityId}`) (CR-152)

### 진입 조건

- **인증**: 로그인 필요(공고 상세와 같다)
- **진입 경로**: 모은 공고 화면(사전 공고, 변경 공고, 최근 낙찰, 낙찰 업체, 월별 동향, 업종별 발주, 기지 지도)에서 공개 공고문이 없는 줄을 누름. CR-155 부터 마감 전 공고, 첫 화면 마감 전 공고 목록의 같은 줄과 관심 공고 목록의 모든 줄
- **진입 불가 시**: 없는 id, 지운 공고는 "공고를 찾을 수 없습니다" 와 마감 전 공고로 가는 단추

### 데이터 로딩

| 순서 | API 호출 | 타이밍 | 실패 시 |
|------|---------|--------|--------|
| 1 | GET /opportunities/origin/{opportunityId} | 페이지 진입 | 404 는 진입 불가 안내, 그 밖은 다시 시도 단추 |

### 화면 동작

| 단계 | 상황 | 시스템 반응 |
|------|------|-----------|
| 1 | 응답에 `publicNoticeId` 가 있음 | 공고문 상세(`/search/{publicNoticeId}`)로 바꿔 연다. 뒤로 가기는 모은 공고 화면으로 간다(방문 기록을 바꿔 쓴다) |
| 2 | `publicNoticeId` 가 없음 | 머리에 유형 꼬리표, 한글 제목, 원문 제목(작게), 공고번호, 발주처, 게시일, 마감. 머리 오른쪽에 "SAM.gov 원문 보기"(새 창). 본문 자리에 "아직 한글 공고문이 없는 공고라 원문을 보여 드립니다" 안내 |
| 3 | 원문 본문이 있음 | 원문 본문을 그대로(줄바꿈 유지). CR-155 부터는 3-1, 3-2 를 따른다 |
| 3-1 | 한글 본문(`descriptionKo`)이 있음 (CR-155) | 한글 본문을 줄바꿈 그대로 먼저 보이고, 그 아래 "원문 보기" 를 누르면 원문 본문이 펼쳐진다(다시 누르면 접힘). 2 의 안내 문구는 "아직 한글 공고문이 없는 공고라 SAM.gov 원문을 한글로 옮겨 보여 드립니다" 로 바꾼다 |
| 3-2 | 한글 본문은 없고 원문 본문이 있음 (CR-155) | 원문 본문을 그대로 펼쳐 보이고, 위에 "한글 번역을 준비하고 있습니다" 를 보인다 |
| 4 | 원문 본문이 없음 | "모아 둔 원문 본문이 없습니다" 와 SAM.gov 원문 보기 링크 |
| 5 | 첨부 주소 | 공고 상세의 원본 표시와 같이 SAM.gov 첨부 주소 목록, 없으면 "첨부 파일이 없습니다" |
| 6 | 공고문에 붙는 기능 | 관심 공고, 자격 판정 상자, 입찰 신청, AI 제안서 단추를 그리지 않는다 |

## 입찰 상세 — 문서 업로드 (`/proposals/{id}`)

- **인증**: 🔒 필요
- **권한**: CUSTOMER (본인 입찰만)
- **선행 조건**: 입찰 신청 완료 (BidRequest 존재)
- **진입 불가 시**: 403 (타인 입찰) 또는 404

### 데이터 로딩

| 순서 | API 호출 | 타이밍 | 실패 시 |
|------|---------|--------|--------|
| 1 | GET /bid-requests/{id} | 페이지 진입 | 에러 메시지, 목록으로 이동 |
| 2 | GET /bid-requests/{id}/history | 페이지 진입 | 이력 영역 빈 상태 |

| 4 | GET /bid-requests/{id}/documents | 페이지 진입 | 생성 문서 영역 빈 상태 |

- **변경 (CR-162)**: 화면과 단추 이름은 "참가 자격 확인", 답 상태 "답 안 함" 은 "답하기 전" 이다. 동작은 그대로다

### 진입 조건

- **인증**: 적격성 진단 첫 화면은 불필요(목록은 로그인해야 보인다). 공고별 진단은 회원 로그인(비로그인이면 로그인 화면을 거쳐 같은 주소로 돌아온다)
- **권한**: 자기 답만 보고 저장한다
- **선행 조건**: 공고문이 공개이고 분석이 끝나 참가 자격이 1개 이상(BIZ-033)

### 데이터 로딩

| 순서 | API 호출 | 타이밍 | 실패 시 |
|------|---------|--------|--------|
| 1 | GET /eligibility/notices | 첫 화면 진입(로그인했을 때만) | 목록 자리 "불러오지 못했습니다" 와 다시 시도 |
| 2 | GET /eligibility/notices/{noticeId} | 공고별 진단 진입 | 404 는 "진단할 수 없는 공고입니다", 그 밖은 다시 시도 |
| 3 | PUT /eligibility/notices/{noticeId}/answers/{itemNo} | 답 단추를 누름 | 그 자격 줄 아래 "저장하지 못했습니다" 한 줄, 단추는 누르기 전 답으로 돌아간다 |

## 공고별 판정 (CR-140)

대상: `/fit/verdicts`, 공고 검색의 우리 회사 칸, 공고 상세의 판정 상자, 공고별 진단의 판정 꼬리표와 증빙 서류. 영역은 T3-3 「공고별 판정」, 「공고 검색」, 「공고 상세」, 「공고별 진단」.

### 진입 조건

- **인증**: 공고별 판정 첫 화면은 불필요(판정은 로그인해야 보인다). 공고 검색, 공고 상세, 공고별 진단은 지금처럼 로그인
- **권한**: 자기 답과 자기 서류만
- **선행 조건**: 판정할 수 있는 공고(BIZ-041)

### 데이터 로딩

| 순서 | API 호출 | 타이밍 | 실패 시 |
|------|---------|--------|--------|
| 1 | GET /eligibility/notices | 공고별 판정 진입(로그인했을 때만), 공고 검색 진입 | 공고별 판정은 목록 자리 "불러오지 못했습니다" 와 다시 시도. 공고 검색은 우리 회사 칸만 비우고 공고 목록은 보인다 |
| 2 | GET /eligibility/notices/{noticeId} | 공고 상세 진입(공고 분석에 참가 자격이 있을 때) | 404 면 상자를 두지 않는다. 그 밖은 상자 자리에 "판정을 불러오지 못했습니다" |
| 3 | GET /member-documents | 공고별 진단에서 서류 고르기 창을 열 때 | 창 안에 "서류함을 불러오지 못했습니다" |
| 4 | PUT /eligibility/notices/{noticeId}/answers/{itemNo}/document | 서류 붙이기, 떼기 | 그 자격 줄 아래 "저장하지 못했습니다", 붙인 서류는 누르기 전으로 |

## 제출 전 검사 (CR-141)

대상: `/documents/pre-check`, `/documents/pre-check/:bidRequestId`, `/proposals/{id}` 제출 서류 탭. 영역은 T3-3 「제출 전 검사」, 「입찰 건별 제출 전 검사」.

### 진입 조건

- **인증**: 필요. 비로그인은 로그인 화면으로 가고, 마치면 이 화면으로 돌아온다
- **권한**: 자기 입찰 건만(BIZ-049). 남의 입찰 건이면 "입찰 건을 찾을 수 없습니다"
- **선행 조건**: 없음. 공고 분석 전인 건은 요구 서류 대신 안내

### 데이터 로딩

| 순서 | API 호출 | 타이밍 | 실패 시 |
|------|---------|--------|--------|
| 1 | GET /bid-requests/my/pre-check | 제출 전 검사 진입 | 목록 자리 "불러오지 못했습니다" 와 다시 시도 |
| 2 | GET /bid-requests/{id}/pre-check | 입찰 건별 검사 진입, 입찰 건 상세 제출 서류 탭 | 404 면 "입찰 건을 찾을 수 없습니다" 와 목록으로. 그 밖은 "불러오지 못했습니다" 와 다시 시도 |
| 3 | GET /member-documents | 서류함에서 고르기 창을 열 때 | 창 안에 "서류함을 불러오지 못했습니다" |
| 4 | POST .../required-document-slots/{itemId}/upload, POST .../from-vault, DELETE .../required-document-slots/{itemId} | 올리기, 고르기, 바꾸기, 빼기 | 그 줄 아래 "저장하지 못했습니다" 와 서버 메시지. 줄은 누르기 전으로 |
| 5 | PATCH /bid-requests/{id}/state (DOCS_RECEIVED) | 서류 제출 완료 | 409 면 응답의 빠진 서류 이름을 단추 위에 보이고 2번을 다시 부른다 |
