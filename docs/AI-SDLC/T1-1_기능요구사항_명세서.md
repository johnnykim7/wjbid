## 기능 상세

### A. 인증

#### BID-AUTH-001 | 회원가입
- **모듈**: A. 인증 > A1. 회원가입
- **설명**: 이메일/비밀번호로 회원가입. 고객은 회사 정보 포함. 이메일은 인증번호로 확인한 주소만 받는다(BID-AUTH-005, CR-146)
- **입력**: 이메일, 비밀번호, 회사명, 사업자등록번호, 담당자명, 전화번호, 약관 동의(필수 이용약관·개인정보처리방침, 선택 소식 받기). 주소는 가입 뒤 회사 정보에서 넣는다 (CR-131)
- **출력**: JWT 토큰, 회원 정보
- **제약조건**: 이메일 중복 불가(이미 가입된 이메일은 고객 화면이 알아볼 수 있는 오류로 알리고 화면은 "이미 가입된 이메일" 로 안내한다, CR-131), 비밀번호 8자 이상, 필수 약관 동의, 이메일 인증번호 확인을 마친 주소만(BIZ-062, CR-146). 가입하면 이메일 확인 시각을 남긴다
- **우선순위**: High | **MVP**: Y | **상태**: 설계중(CR-146 변경)

#### BID-AUTH-002 | 로그인
- **모듈**: A. 인증 > A2. 로그인
- **설명**: 이메일/비밀번호로 로그인하여 JWT 토큰 발급
- **입력**: 이메일, 비밀번호
- **출력**: Access Token (15min) + Refresh Token (7day)
- **제약조건**: 비밀번호를 잊은 고객은 고객센터 이메일로 안내한다. 메일 재설정 기능은 백로그 BL-001 (CR-131)
- **우선순위**: High | **MVP**: Y | **상태**: 구현완료(기존)

#### BID-AUTH-003 | 토큰 갱신
- **모듈**: A. 인증 > A3. 토큰
- **설명**: Refresh Token으로 Access Token 재발급
- **입력**: Refresh Token
- **출력**: 새 Access Token
- **제약조건**: 만료된 Refresh Token은 거부
- **우선순위**: High | **MVP**: Y | **상태**: 구현완료(기존)

#### BID-AUTH-004 | 로그아웃

- **설명**: 현재 세션 무효화
- **입력**: Access Token
- **출력**: 성공 응답
- **제약조건**: —
- **우선순위**: Medium | **MVP**: N | **상태**:

#### BID-AUTH-005 | 회원가입 이메일 인증번호 (CR-146)
- **모듈**: A. 인증 > A1. 회원가입
- **설명**: 가입하려는 이메일로 6자리 인증번호를 보내고, 고객이 넣은 번호를 확인한다. 확인을 마친 주소로만 가입(이메일 가입, SNS 가입)을 받는다
- **입력**: 이메일. 확인 때 이메일과 인증번호
- **출력**: 보낸 결과(유효 시간, 다시 받을 수 있는 시간), 확인 결과(맞음, 틀림과 남은 횟수, 시간 지남, 횟수 넘음)
- **제약조건**: 이미 가입된 메일에는 보내지 않는다(BIZ-008). 번호는 해시로만 저장한다. 유효 시간, 다시 받기 간격, 틀릴 수 있는 횟수, 메일 하나에 하루 보낼 수 있는 횟수, 확인 뒤 가입까지 남는 시간은 POL-037. 번호는 가입 한 번에 쓰고 끝난다. 메일은 알림 서버 틀 BID_EMAIL_CODE 로 보낸다
- **우선순위**: High | **MVP**: Y | **상태**: 설계중

#### BID-AUTH-006 | SNS 가입 (CR-146)
- **모듈**: A. 인증 > A1. 회원가입
- **설명**: 네이버, 카카오 계정으로 가입한다(구글은 보류, CR-146 10.5). SNS 에서 돌아오면 SNS 가 준 이메일을 채운 SNS 가입 화면에서 회사 정보와 약관 동의를 받는다. 가입하면 바로 로그인된다
- **입력**: SNS 가입 표(서버가 만든 한 번짜리 값), 이메일, 회사명, 사업자등록번호, 담당자명, 전화번호, 약관 동의(필수 이용약관·개인정보처리방침, 선택 소식 받기)
- **출력**: JWT 토큰, 회원 정보
- **제약조건**: SNS 가 확인을 마친 이메일(구글, 카카오의 확인 표시)을 그대로 쓰면 인증번호를 받지 않고, 그 밖에는 BID-AUTH-005 확인이 있어야 한다(BIZ-062). SNS 계정 하나는 회원 하나에만 잇는다(BIZ-063). SNS 이메일로 이미 이메일 가입한 회원이 있으면 잇지 않고 이메일 로그인을 안내한다(BIZ-063). 비밀번호는 받지 않는다(BIZ-064). 키가 설정된 SNS 만 보인다. SNS 가입 표 유효 시간은 POL-038
- **우선순위**: High | **MVP**: Y | **상태**: 설계중

- **회원 전용 (CR-157)**: 공고문 상세(공고 요약, 요구 서류, 판정 상자, 제안서 작성)는 회원과 관리자만 본다(BIZ-071). 원본 공고 상세는 무료회원과 회원 모두 본다. 같은 공고의 공개 공고문이 있으면 회원은 공고문 상세로 바로 가고, 무료회원은 원본 공고 상세에 머물며 "AI 공고문은 회원 전용" 안내와 요금 안내 연결을 본다. 무료회원이 공고문 상세 주소를 직접 열면 회원 안내를 본다
- **관심 공고 단추 (CR-157)**: 원본 공고 상세에도 관심 공고 단추를 둔다. 모은 공고 번호로 저장하므로(CR-155) 무료회원도 쓴다. 위 CR-152 줄의 "관심 공고는 원본 공고 상세에 보이지 않는다" 를 바꾼다
- **우선순위**: High | **MVP**: Y | **상태**: 구현완료(기존), 개선 필요. CR-152 설계완료(구현대기). CR-155 설계완료(구현대기). CR-157 설계중
