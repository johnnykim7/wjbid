# 04. 목차 기획 및 스토리 기획

**역할**: RFP 요청 목차 기반으로 세부 목차를 확정하고, 목차별 전략·핵심 내용을 정리한다.
**입력**: 컴플라이언스 매트릭스, 평가표, 수주 전략서
**산출물**: `4-outline/outline-strategy.md` (목차 전략표)
**함께 읽기**: `00-writing-style.md`

## Part A. 목차 확정

계층별 규칙:

| 레벨 | 규칙 |
|---|---|
| lv1~2 | **RFP 지정 목차를 표현 단어까지 그대로 준수** (고객이 "사업관리"라 썼으면 "프로젝트 관리"로 바꾸지 않는다) |
| lv3 | 평가표 항목 → 목차 1:1 매핑. 평가자가 평가표 순서대로 답을 찾을 수 있게 |
| 최하위 | 요구사항(REQ) 그룹핑과 연계 + 전략적 소목차 추가 개발 |

- RFP가 목차를 안 준 경우: 충실도 체크리스트(요구사항)와 평가표를 기초로 개발
- 세부 목차에는 섹션전략을 반영해 **표제에서부터 전략 포인트가 드러나게** 한다
- 전략적 솔루션 강조가 필요하면 하위 목차를 추가 개발한다
  (예: RFP에 "1. 설계계획"만 있으면 → 1.1 시스템 통합설계 / 1.2 H/W 설계 / 1.3 S/W 설계)

## Part B. 페이지 배분

- 총 페이지 제한(제출 지시사항)을 입력받아 **배점 가중치에 비례해 배분**한다
- 고배점 섹션 = 많은 분량. Discriminator가 배치된 섹션은 하한을 보장한다
- ES, 표지, 목차, 부록의 고정 분량을 먼저 빼고 본문에 배분

## Part C. 목차 전략표 (핵심 산출물)

모든 lv3(또는 최하위) 목차에 대해 다음 표를 작성한다.
템플릿: `assets/templates/outline-strategy.md`

| 열 | 내용 |
|---|---|
| 목차 번호·제목 | 정보 표제 형식 후보 포함 |
| 대응 REQ ID | 이 섹션이 답해야 하는 요구사항 (커버리지의 근거) |
| 평가 항목·배점 | 걸려 있는 평가표 항목 |
| 적용 제안전략 | 4방향 전략 중 이 섹션에 할당된 축·기술문 |
| 적용 수행전략 | 수행전략 6요소 중 해당 요소 |
| 주제문 초안 | 특징→효용 연결 1문장 |
| 배분 페이지 | Part B 결과 |

**모든 목차 항목을 균등한 깊이로 채운다.** 뒤쪽 목차라고 "상동", "생략" 금지.

## Part D. 스토리 검증

- 전체 흐름 리허설: 목차 제목+주제문만 위에서 아래로 읽었을 때
  하나의 설득 스토리(고객 도전 → 이해 → 솔루션 → 근거 → 효과)가 성립하는가
- 커버리지: `scripts/check_coverage.py`로 REQ ID 전수 매핑 확인 — 매핑 안 된 REQ는 0이어야 한다
- Winning Theme·Discriminator가 고배점 섹션에 배치되었는가
- 평가표 전 항목이 목차에서 1:1로 찾아지는가

**HITL 게이트**: 목차 확정은 사용자 승인 필수 (이후 모든 작업의 뼈대).
