# 00. 공통 작성 스타일 가이드

4~7단계(목차, 섹션 기획, 본문, 리뷰)에서 항상 적용하는 작성 원칙이다.

## 1. 대원칙: 쉬운 제안서가 이긴다

고객이 인지하는 가치 = 솔루션(S) × 커뮤니케이션(C).
객관적으로 우수한 솔루션(9점)도 전달이 나쁘면(5점) 45점이고,
보통 솔루션(7점)이라도 전달이 좋으면(9점) 63점으로 이긴다.

쉬운 제안서의 두 조건:
- **찾기 쉽다**: 평가자가 평가표의 답을 빨리 찾을 수 있다 (목차·표제가 안내한다)
- **평가하기 쉽다**: 주장(Claim)이 분명하고 근거(Proof)가 분명하다 (헤드라인 구조)

한국 공공 평가는 짧은 시간에 이뤄진다. 평가자가 답을 쉽게 찾는 제안서가
동일 내용이라도 더 높은 점수를 받는다.

## 2. 4-Box 헤드라인 구조 (섹션 구성의 기본)

모든 섹션(및 ES)은 4-Box로 구성한다. 위로 갈수록 주장, 아래로 갈수록 근거.

| Box | 내용 | 규칙 |
|---|---|---|
| Box 1 | 주제문(헤드라인) | 솔루션 특징(차별화 요소)이 주는 **고객 효용**만 쓴다. 본문 요약 금지. 2줄 이내 단문 |
| Box 2 | 요약 | 이 섹션에서 말할 내용 요약. 고객 요구(Requirement)의 답(Response) 제시 |
| Box 3 | 본문(Body) | Box 2의 증거. Box 2에서 나열한 항목을 제목으로 순서대로 전개 |
| Box 4 | 재요약 & 하위 섹션 소개 | Box 3을 뒷받침할 하위 섹션 안내 |

## 3. 6대 문장 원칙

1. **주제문 원칙**: 모든 문단의 첫 문장 = 그 문단의 결론.
2. **F-B-P 체인**: Feature(특징) → Benefit(효용) → Proof(증거) 순서.
   특징만 나열하고 효용을 빼먹는 것이 가장 흔한 실패.
3. **고객 주어**: "귀 기관은 ~을 확보하게 됩니다" ✓ / "저희는 ~에 강점이 있습니다" ✗.
   자사 자랑이 아니라 고객이 얻는 것을 말한다.
4. **정량화·구체화**: "최적의", "효율적인", "선진화된" 같은 추상어 금지.
   "응답 시간 50% 단축", "개발기간 6개월 단축"처럼 수치로.
   수치가 없으면 사례·방법·근거를 구체적으로.
5. **정보 표제(Informative Heading)**: 제목만 읽어도 핵심이 전달되게.
   "시스템 구성" ✗ → "AI 기반 3계층 아키텍처로 처리 속도 3배 향상" ✓.
   평가자는 주제문은 건너뛰어도 제목은 반드시 읽는다.
   단, RFP가 지정한 표제는 단어 하나도 바꾸지 말고 그대로 쓴다.
6. **Action Caption**: 그림 설명에 메시지를 담는다.
   "그림 1. 시스템 구성도" ✗ → "그림 1. AI 통합 관제로 장애 대응 시간 75% 단축" ✓.
   비주얼만 보고도 내용을 완전히 이해할 수 있어야 한다.

## 4. 어투 규칙 (한국 제안서)

| 위치 | 어투 | 예시 |
|---|---|---|
| 주제문, 헤드라인, Action Caption, ES | 완결문 합쇼체 "~하겠습니다 / ~합니다 / ~됩니다" | "선행연구 재사용으로 개발기간을 6개월 단축하겠습니다." |
| 근거·상세 나열 (불릿) | 개조식 명사형 종결 | "- EVMS 적용을 통한 비용·일정 통제" |
| 표 안 텍스트 | 개조식, 최대한 압축 | "체계통합 경험 3건 보유" |

- 한 문장 60자 이내. 두 가지 이상 말하려면 문장을 나눈다.
- 불릿 항목은 병렬 구조 유지 (전부 명사형이면 전부 명사형으로).

## 5. 카피라이팅 체크리스트 (본문 작성 후 자체 점검)

- [ ] 번역투 제거: "~에 있어서", "~을 통하여" 남발, "~적인" 연쇄, 피동 남용("~되어지는")
- [ ] 이중 부정 제거
- [ ] 주어-술어 호응 (긴 문장에서 특히)
- [ ] 조사 중복·누락 없는지
- [ ] 같은 단어의 근거리 반복 없는지 (동의어 교체 또는 문장 재구성)
- [ ] 추상어 → 수치/구체어로 교체했는지
- [ ] 고객 명칭을 RFP에 쓰인 그대로 사용했는지 (임의 축약 금지)

## 6. 시각화 원칙

**시각화 6유형** (선택 기준은 06-writing.md 참조):
As-is→To-be(변화) / VS 비교 / 프로세스·단계 / 시계열·로드맵 / 구조도 / 병렬형

**시각적 소음(Visual Noise) 경고**:
한국 제안서 특유의 "One Sentence, One Diagram" 남발은 최악의 관행이다.
불필요한 다이어그램은 텍스트보다 내용을 왜곡하고, 다이어그램이 너무 많으면
정작 핵심 그래픽의 강조 효과가 상호간섭으로 죽는다.
→ **도식은 차별화 포인트와 복잡한 근거 표현에만 집중 투입한다.**
섹션당 핵심 도식 1개 원칙, 차별화 요소(Discriminator)가 있는 섹션에 우선 배치.

**비주얼 배치 규칙**:
- 비주얼이 나오기 전에 본문에서 먼저 언급한다
- 비주얼은 해당 내용과 같은 페이지(또는 맞은편)에 배치
- 큰 비주얼은 페이지 중간이 아닌 상단/하단에
- 반드시 Action Caption을 하단에 붙인다

## 7. 디자인·강조 원칙 (DOCX — AX 표준 서식 v2, 상세는 06번 §DOCX 조립)

- 폰트: 전체 Pretendard 통일 (도식·간지와 동일). 대외 제출은 PDF 병행 필수
- 본문 12pt(공공)/11pt(기업), 줄간격 130%. 폰트를 더 작게 하지 않는다
  (평가위원은 중년 이상 — 작은 글씨는 감점 요인)
- 본문은 □→○→− 개조식 3계층이 기본. 레벨별 크기·굵기 차등으로 위계를 시각화
- 주제문은 무테 음영 박스(본문 폭 정렬), 절 제목은 음영 밴드 — 서구식 좌측 바 금지
- 표는 상하 굵은 외곽선만(좌우 무선), 헤더 회색 음영. 무채색 유지
- 강조는 굵게(+밑줄 허용)로 통일, 색 강조 금지, 페이지당 3회 이내
  — 전부 강조하면 아무것도 강조되지 않는다
- 색 원칙: 공공 완전 무채 / 기업 Navy 1색 포인트. Orange(#E8590C)는 도식 내부 전용
- 일관성: 제목·주제문·캡션 형식은 docx-style.js에 고정 — 프로젝트별 임의 변경 금지

## 8. 균등 깊이 원칙 (필수 준수)

여러 섹션/항목을 작성할 때 앞 항목은 상세하고 뒤 항목은 부실해지는 패턴을 금지한다.
- 본문은 소목차 3~4개 청크 단위로 나눠 작성하고, **매 청크 시작 시
  이 파일과 해당 섹션 기획서, Winning Theme을 다시 읽는다**
- 청크 완료 시 이전 청크와 분량·깊이를 비교해 편차가 크면 즉시 보강한다
