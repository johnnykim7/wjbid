## 2. 실측 (상용 AWS, 2026-10-12)

- 메인 공고명 검색이 0건이던 까닭: 마감 전 공고와 검색은 공개(VISIBLE) 공고문만 보이는데, 공개 공고문 21건이 모두 마감이 지났다. 검색 결함이 아니다
- 12:32 기준 모은 공고 394건(지운 것 제외) 가운데 마감 전 21건, 같은 공고번호를 하나로 치면 13건. 공개 공고문 중 마감 전은 0건, 숨긴 공고문 중 마감 전 2건(10/12 관리자 대신 만든 것)
- 한글 제목 394건, 원문 본문 52건, 한글 본문 12건. 수집은 제목만 옮기고 본문은 관리자 한글 번역 단추를 눌러야 받는다(`OpportunityTranslationService.translateAsync`)
- 새로 모이는 공고는 하루 1~6건(9/22~10/9). SAM.gov 하루 호출은 지금까지 검색 최대 10, 본문 조회 최대 12, 첨부 최대 14(`sam_api_call_log`). 새 공고마다 본문 조회 한 번을 더해도 지금까지 본 하루 범위 안이다
- 관심 공고: 저장은 모은 공고 번호를 받는데(`BookmarkService.add`) 마감 전 공고 목록과 공고 상세가 공고문 번호를 전달해 저장이 실패한다. 관심 공고 목록은 모은 공고 번호를 주는데 줄을 누르면 공고문 상세에서 찾아 열리지 않는다

## 3. 결정

1. 고객 마감 전 공고 목록, 검색, 첫 화면 목록과 건수는 모은 공고 중 마감 전인 것 전부를 보인다. 낙찰 공지와 지운 공고는 빼고, 같은 공고번호는 마지막 판 하나만(BIZ-069)
2. 새 조회를 만들지 않고 CR-135 의 `GET /opportunities/collected` 에 `q`, `sort`, `dueWithinDays` 를 더한다. `openOnly` 는 낙찰 공지를 늘 뺀다. 줄에 발주처, 업종 코드, 이행 장소를 더한다
3. 줄을 누르면 CR-152 규칙 그대로(공개 공고문이 있으면 공고문 상세, 없으면 원본 공고 상세). 판정 꼬리표는 공개 공고문이 있는 줄만
4. 원본 공고 상세는 한글 본문을 먼저, 원문 본문은 접어 둔다. 한글 본문이 없으면 원문과 준비 중 안내
5. 새로 모은 공고는 수집 때 SAM.gov 본문을 받아 저장하고 한글로 옮긴다. 실패해도 수집은 그대로, 있는 값은 덮지 않는다(BIZ-070). 이미 원문 본문과 한글 본문이 있으면 다시 받지 않는다
6. 관심 공고 번호를 모은 공고 번호로 맞춘다. 공고 상세 응답에 `opportunityId` 를 더하고, 관심 공고 목록의 줄은 원본 공고 상세 주소로 보낸다(공고문이 있으면 넘어간다)
7. 쓰지 않게 되는 `GET /opportunities/search`, `GET /opportunities/near-deadline` 은 없앤다. `GET /opportunities` 는 관리자 콘솔이 공개 공고문 수를 셀 때 써서 남긴다
8. 공고문 공개는 지금처럼 관리자가 정한다. 공고문 열람을 회원으로 묶는 것, 숨겨 둔 공고문 2건의 공개는 CR-156 에서 한다

## 5. 구현 범위

- BE: `MarketDataService.collected` 에 검색어, 마감순, 기한 안 거르기. `MarketRowAssembler.isOpen` 이 낙찰 공지를 뺀다. `MarketSource` 와 `MarketRowDto` 에 발주처, 업종 코드, 이행 장소. `OpportunityDto` 에 `descriptionKo`(원본 상세), `opportunityId`(공고문 상세). `OpportunityTranslationService.translateAsync` 가 본문도 받는다. `OpportunityController` 의 search, near-deadline 과 그것만 쓰던 공고문 조회를 지운다
- FE 고객 포털: 마감 전 공고 화면과 첫 화면이 collected 를 부른다. 줄 누름은 CR-152 의 `targetOf` 규칙. 판정 꼬리표는 공개 공고문 id 로 찾는다. 관심 공고는 모은 공고 번호. 원본 공고 상세의 한글 본문과 원문 접기. 관심 공고 목록 줄 누름
- 배포 뒤 운영 자료: 마감 전 13건 중 한글 본문이 없는 것을 관리자 한글 번역으로 채운다(운영 쓰기, 배포 승인 때 같이 묻는다)
- 시험: 단위시험 TC-BROWSE-010~017, TC-OPP-015~019. 로컬에서 마감 전 공고 목록, 검색, 첫 화면 두 탭, 줄 누름 두 경우, 관심 공고 저장과 목록, 원본 공고 상세 한글 본문을 본다

## 6. 구현 기록 (2026-10-12)

- 관심 공고: 공고 상세는 응답의 `opportunityId` 로 확인, 저장, 해제한다. 관심 공고 목록 줄은 원본 공고 상세 주소로 가고, 공개 공고문이 있으면 CR-152 대로 공고 상세가 열린다
- 첫 화면 마감 임박 탭은 지금처럼 7일 안 마감만 보인다. 부르는 것은 두 번(게시일순 7줄과 전체 건수, 마감순 7일 안 7줄과 그 건수)
- 지운 것: 고객 포털의 search, near-deadline, 목록 조회 호출과 서버의 같은 주소, 그것만 쓰던 공고문 조회 두 개
- 본문 번역은 수집 번역과 같은 흐름에서 제목 뒤에 한다. 본문이 링크이면 SAM.gov 에서 받고, 받기나 번역이 실패하면 기록만 남기고 다음 수집이나 관리자 한글 번역에 맡긴다. 그 사이 채워진 값은 덮지 않는다
- 원본 공고 상세의 "원문 보기" 는 같은 화면에서 영문 본문을 펼친다. 머리와 아래의 "SAM.gov 원문 보기" 는 SAM.gov 공고를 새 창으로 연다
