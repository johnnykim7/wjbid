## 1. 실측 (2026-11-08 develop 소스, 상용 자료, SAM 응답)

- 수집은 SAM 공고의 수행 장소(placeOfPerformance)에 도시도 주도 없으면 계약 사무소 주소(officeAddress)의 도시와 주로 짧은 수행 장소를 채운다(`OpportunitySelectionEnricher.extractPlaceShort`)
- 원본 JSON 의 `placeOfPerformance` 칸에는 SAM 수행 장소가 아니라 늘 계약 사무소 주소의 "도시, 주" 글을 넣는다(`OpportunityCollectorService` 원본 JSON 만들기). SAM 수행 장소 원본은 어디에도 남지 않는다. `opportunity_source_raw` 는 0줄이다
- 목록 줄의 장소는 짧은 수행 장소, 없으면 원본 JSON 의 `placeOfPerformance` 글이다(`MarketSource.placeOf`, CR-155). 관리자 원본 공고 상세의 "수행 장소" 도 짧은 수행 장소, 없으면 원본 JSON 값이다. 입찰 분석 입력의 장소는 짧은 수행 장소다(`BidAnalysisInputService`)
- 11/8 상용, 지우지 않은 공고 487건: 짧은 수행 장소 "APO, AP" 412건, 빈 칸 47건, 나머지 28건은 "Camp Humphreys, Gyeonggi", "Pyeongtaek" 같은 실제 장소. 원본 JSON 의 `placeOfPerformance` 가 글인 줄 479건
- 장표 그림의 공고(W91QVN27RA993, 대구, 김해, 광주, 수원, 청주 차량 정비)를 SAM 에서 다시 받아 보니 수행 장소는 `{streetAddress: "Vehicle Maintenance for Daegu, Gimhae, Gwangju, Suwon, and Cheongju.", zip: ""}` 로 도시와 주가 없고, 계약 사무소는 `{city: APO, state: AP, zipcode: 96271-5289}` 다
- APO, AP 는 미군 군사우편 주소다. APO(Army Post Office, Air Post Office) 는 미군 우체국, AP(Armed Forces Pacific) 는 태평양 지역이다. FPO(해군), DPO(외교), AA(미주), AE(유럽)도 같은 방식이다. 우편번호가 있어야 어느 기지인지 알고, 96271 은 캠프 험프리스다. 화면의 "APO, AP" 는 장소를 알려 주지 못한다
- "APO, AP" 412건 중 249건은 영문 제목에 기지 목록(상용 12곳)의 찾을 낱말이 있다(기지별 지도와 같은 계산, BIZ-031). 163건은 없다

## 2. 고칠 곳

| 순번 | 자리 | 지금 | 바꾼 뒤 |
|------|------|------|--------|
| 1 | 수집, 짧은 수행 장소 | SAM 수행 장소의 도시와 주, 없으면 계약 사무소 주소 | SAM 수행 장소의 도시와 주만 쓴다. 계약 사무소 주소로 채우지 않는다. 군사우편 주소(BIZ-103)면 비운다 |
| 2 | 수집, 원본 JSON | `placeOfPerformance` 에 계약 사무소 주소 "도시, 주" 글 | `placeOfPerformance` 에 SAM 수행 장소, `officeAddress` 에 SAM 계약 사무소 주소를 받은 그대로 둔다(BIZ-004) |
| 3 | 이미 모은 공고(V62) | 짧은 수행 장소 "APO, AP" 412건, 원본 JSON 의 `placeOfPerformance` 는 계약 사무소 주소 | 짧은 수행 장소가 군사우편 주소인 줄을 비운다. 원본 JSON 의 `placeOfPerformance` 가 글인 줄은 그 글을 `officeAddress` 로 옮긴다. 수정 시각(`last_modified_at`, `updated_at`)은 그대로 둔다 |
| 4 | 보이는 장소(서버) | 짧은 수행 장소, 없으면 원본 JSON 의 계약 사무소 주소 | 짧은 수행 장소, 없으면 영문 제목에서 찾은 기지의 한글 이름(BIZ-031 과 같은 낱말 찾기, 여러 곳이면 기지 목록 순서로 ", " 로 잇는다), 그것도 없으면 비운다(BIZ-103). 목록 줄(`placeOfPerformance`)과 관리자 원본 공고 상세(`placeOfPerformance`)가 같은 계산을 쓴다 |
| 5 | 고객 공고 상세 응답 | 원본 JSON 의 `placeOfPerformance` | 짧은 수행 장소. 고객 화면은 이 칸을 쓰지 않는다 |
| 6 | 입찰 분석 입력 | 짧은 수행 장소 | 그대로. 1번과 3번으로 계약 사무소 주소가 빠진다. 제목은 이미 입력에 있어 기지 이름은 더하지 않는다 |

고객 첫 화면 목록의 기지 칸과 관리자 원본 공고 상세의 "수행 장소" 묶음은 화면 코드를 바꾸지 않는다. 서버가 준 값을 보이고, 값이 없으면 지금처럼 기지 칸이 비고 "수행 장소" 묶음이 숨는다.

## 3. 정한 것

- 계약 사무소 주소는 장소로 보이지 않는다(사용자 11/8 08:49). 계약 사무소는 공고를 낸 곳이지 일을 하는 곳이 아니다
- SAM 수행 장소에 실제 도시나 주가 있으면 제목에 기지가 있어도 SAM 값을 보인다
- SAM 수행 장소의 주소 글(streetAddress)은 쓰지 않는다. 장표 그림의 공고처럼 제목을 다시 적은 글이 들어온다
- 제목 기지 찾기는 기지 목록에 있는 기지만 찾는다. 장표 그림의 공고는 "캠프 워커·헨리"(대구)만 보이고, 기지 목록에 없는 김해, 광주, 수원, 청주는 보이지 않는다. 제목에는 다섯 곳이 다 있다
- 군사우편 주소 판정은 도시가 APO, FPO, DPO 이거나 주가 AA, AE, AP 인 것이다. 미 우정청이 정한 표기라 관리자 설정으로 두지 않는다
- 계약 사무소 우편번호로 기지를 찾지 않는다. 계약 사무소가 있는 기지(대개 캠프 험프리스)이지 일하는 기지가 아니다
- 이미 모은 공고의 SAM 수행 장소 원본은 다시 받지 않는다. 412건을 다시 받으면 SAM 하루 호출 한도를 넘는다. 신규 공고와 다시 모으는 공고부터 원본이 남는다
- 옛 줄의 `officeAddress` 는 "도시, 주" 글이고 신규 줄은 SAM 이 준 그대로다. 이 칸을 읽는 곳은 없다
