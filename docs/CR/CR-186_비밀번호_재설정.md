# CR-186 비밀번호 재설정

> 설계 버전: 0.1 | 최종 수정: 2026-11-03 | 관련 CR: CR-131, CR-146

- CR-ID: CR-186
- 작성일: 2026-11-03
- 규모: 중 (고객 화면 1개 신설, API 1개 신설과 1개 확장, 인증번호 표에 칸 1개, 알림 서버 메일 틀 1개)
- 상태: 구현과 로컬 확인 (11/3 07:36). 상용 반영은 알림 서버 틀이 들어간 뒤
- 원문: `docs/origins/원본_CR-186_비밀번호_재설정_20261103.md`, 백로그 BL-001

## 1. 실측 (2026-11-03 develop 소스)

- 로그인 화면의 "비밀번호를 잊으셨나요?" 는 고객센터 메일 주소로 가입 이메일을 보내 달라는 안내뿐이다(`frontend/customer-portal/src/pages/LoginPage.tsx` forgot 상자). 고객이 스스로 비밀번호를 다시 정하는 화면과 API 가 없다
- 인증번호 보내기는 이미 가입된 메일이면 409 로 막는다(`EmailCodeService.java` send). 가입 전용이라 재설정에 그대로 쓸 수 없다
- 인증번호 표(`email_verification_codes`)에는 쓰임 칸이 없어 가입 번호와 재설정 번호를 가를 수 없다
- 알림 서버 틀 BID_EMAIL_CODE 본문은 "WJbid 회원가입 화면에 아래 인증번호 6자리를 넣어 주세요." 라서 재설정 메일로 쓰면 고객이 헷갈린다(`docs/templates/mail/BID_EMAIL_CODE.json`)
- 서버는 발급한 토큰을 기억하지 않는다(`JwtTokenProvider.java`, `AuthController.java` refresh). 비밀번호를 바꿔도 다른 기기의 로그인은 토큰이 끝날 때까지 남는다

## 2. 고칠 곳

| 순번 | 자리 | 지금 | 바꾼 뒤 |
|------|------|------|--------|
| 1 | 인증번호 표 | 쓰임 칸 없음 | `purpose` 칸(SIGNUP, PASSWORD_RESET). 옛 줄은 SIGNUP |
| 2 | 인증번호 보내기, 확인 | 가입 번호만 | `purpose` 를 받는다. 재설정 번호는 가입된 메일에만 보내고(아니면 404 `EMAIL_NOT_REGISTERED`), 알림 서버 틀 BID_PASSWORD_RESET_CODE 로 보낸다. 확인은 그 쓰임의 마지막 번호를 본다 |
| 3 | 가입 | 확인된 번호면 쓴다 | 확인된 가입 번호만 쓴다 |
| 4 | 서버 | 재설정 API 없음 | `POST /auth/password-reset` `{email, newPassword}`. 확인된 재설정 번호를 쓰고 비밀번호를 바꾼다 |
| 5 | 고객 화면 | 없음 | `/password-reset` 비밀번호 재설정. 이메일 인증번호 확인 뒤 새 비밀번호 두 칸, "비밀번호 바꾸기" |
| 6 | 로그인 화면 | 고객센터 메일 안내 | "비밀번호 재설정" 링크. 재설정 직후 들어오면 초록 줄 "비밀번호를 바꿨습니다. 새 비밀번호로 로그인해 주세요." |

## 3. 정한 것

- 메일 링크가 아니라 가입과 같은 6자리 인증번호로 한다. 가입 화면과 같은 칸, 같은 정책값(POL-037), 같은 오류 안내를 쓰고 한 화면 안에서 끝난다. 링크 방식은 새 표, 화면 주소 설정, 링크를 여는 새 화면이 따로 든다
- 가입되지 않은 이메일은 "가입되지 않은 이메일입니다." 로 알린다. 가입 화면이 이미 가입 여부를 알려 주므로 숨겨도 막아지는 것이 없다
- 재요청 간격과 하루 횟수는 쓰임을 가리지 않고 메일 하나로 센다. 한 메일함에 보내는 양을 막는 값이기 때문이다
- SNS 로만 가입한 회원도 재설정으로 비밀번호를 만들 수 있다. 그 이메일을 가진 사람임을 확인했고, 막으면 가입 방법을 드러내게 된다(BIZ-064 의 뜻과 어긋남)
- 바꾼 뒤 다른 기기의 로그인을 끊는 일은 이 CR 에 넣지 않는다. 서버가 토큰을 기억하지 않아 로그아웃도 같은 문제를 안고 있어 따로 다룬다(백로그 BL-008)

## 4. 알림 서버 요청 (bp-notification)

- 틀 BID_PASSWORD_RESET_CODE 를 BID_EMAIL_CODE 와 같은 방법(알림 CR-017, V115)으로 입찰대행 솔루션에 넣어 달라고 그 레포 창에 요청한다
- 내용 원본은 `docs/templates/mail/BID_PASSWORD_RESET_CODE.json`. 치환 변수는 `code`, `validMinutes` 로 BID_EMAIL_CODE 와 같다
- 상용 순서: 이 틀이 상용 알림 서버에 들어간 뒤에 이 CR 의 BE 를 배포한다. 틀이 없으면 재설정 번호 보내기만 502 `EMAIL_SEND_FAILED` 로 실패하고 가입 번호는 영향이 없다
