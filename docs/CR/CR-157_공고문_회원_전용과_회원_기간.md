## 2. 고칠 곳

1. 회원 기간 표 `member_memberships`(회원 id, 시작일, 끝일, 메모, 넣은 관리자, 넣은 시각). 결제 연동 전에는 관리자가 넣는다. 오늘(서울 날짜)이 어느 한 기간 안이면 회원이다. 관리자는 늘 회원과 같이 본다. 기간을 고치지 않고 잘못 넣은 것은 지우고 새로 넣는다
2. 서버 회원 판정 한 곳(`MembershipService.requireMember`). 공고문을 내주는 조회는 모두 이것을 거친다. 로그인한 무료회원은 403 과 이유 코드 `MEMBERSHIP_REQUIRED`. 로그인하지 않았거나 토큰이 끝났으면 401 `LOGIN_REQUIRED`(고객 화면은 401 에만 토큰을 새로 받으므로, 끝난 토큰을 403 으로 막으면 회원도 회원 안내를 보게 된다)
   - 공고문 상세, 공개 공고문 목록, 최근 공고문, 요구 서류: 회원만. 보안 설정의 `GET /opportunities/**` 공개에서 이 넷을 뺀다. 모은 공고 목록, 원본 공고 상세, 첨부 목록, 통계는 지금처럼 모두에게
   - 적격성 진단 목록, 상세, 답 저장과 판정: 회원만
   - 입찰 신청(`POST /bid-requests`): 회원만. 이미 낸 입찰 건은 회원 기간이 끝나도 낸 회원이 본다
   - 원본 공고 상세는 공개 공고문 id 를 지금처럼 싣는다(공고문 내용이 아니라 있다는 표시)
3. 내 정보(`/members/me`)에 회원 여부와 기간 끝일을 싣는다
4. 고객 화면
   - 원본 공고 상세: 회원이면 지금처럼 공고 상세를 연다. 무료면 그대로 머물고 "AI 공고문은 회원 전용입니다" 안내와 요금 화면 연결. 머리에 관심 공고 단추를 둔다(무료도 쓴다)
   - 모은 공고 줄을 누르면 원본 공고 상세부터 연다. 회원은 거기서 공고 상세로 간다
   - 마감 전 공고 목록, 첫 화면: 판정 칸은 회원만 부른다. 무료는 공고문 있는 줄에 "회원" 꼬리표
   - 적격성 진단, 공고별 판정: 무료는 회원 안내 화면(요금 화면 연결)
   - 공고 상세 주소를 무료가 직접 열면 회원 안내를 본다
   - 내 프로필에 "회원, 끝일까지" 또는 "무료회원", 요금 안내에 "지금 단계"
   - 입찰 캘린더의 공고 이름은 원본 공고 상세로 간다. CR-155 부터 관심 공고를 모은 공고 번호로 저장해 공고 상세 주소로는 열리지 않던 것을 함께 고친다
5. 관리자 콘솔 회원 화면: 줄마다 회원 여부와 끝일, 기간 넣기(시작일, 끝일, 메모)와 지우기, 그 회원의 기간 이력
6. 숨겨 둔 공고문 2건 공개는 결정 3 에 따른다
7. 시험: 회원 판정(기간 안, 시작 전, 끝난 뒤, 관리자, 서버 시간대가 UTC 여도 서울 날짜), 403 이유 코드, 조회 넷과 적격성 셋의 막음, 원본 공고 상세는 무료도 열림, 기간 넣기와 지우기
