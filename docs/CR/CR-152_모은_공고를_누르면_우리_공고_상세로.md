## 2. 실측 (상용 AWS, 2026-10-12 07:50)

- 모은 공고 398건 가운데 공개 한글 공고문(notices.visibility=VISIBLE)이 있는 것 21건. 나머지 377건은 줄을 누르면 SAM.gov 원문이 새 창으로 열렸다
- 한글 제목(title_ko) 395건, 모아 둔 원문 본문(description_body) 51건, 내려받아 둔 첨부(opportunity_attachments) 72건
- 화면 규칙 정본: `marketUtils.ts` 의 `targetOf`("공개 공고문이 있으면 WJbid 공고 상세, 없으면 SAM.gov 원문"). 이를 쓰는 화면은 사전 공고, 변경 공고, 최근 낙찰, 낙찰 업체, 월별 동향, 업종별 발주, 기지 지도
- 지금 공고 상세(`/search/{id}`)는 공고문 id 로만 열리고(`GET /opportunities/{id}` 가 VISIBLE 공고문만 찾음) 로그인해야 연다. 분석이 없으면 원본 표시(본문, SAM.gov 첨부 주소)로 그리는 분기가 이미 있다

## 3. 결정

1. 모은 공고 화면의 줄은 모두 우리 화면으로 간다. 공개 공고문이 있으면 공고문 상세, 없으면 원본 공고 상세
2. 원본 공고 상세는 새 주소 `/search/origin/{opportunityId}`, 새 조회 `GET /opportunities/origin/{opportunityId}`. 응답에 공개 공고문 id 가 있으면 화면이 공고문 상세로 전환한다(공고문이 생기면 그 내용으로 채운다)
3. 원본 공고 상세는 공고 상세 화면의 원본 표시 분기를 쓴다. 관심 공고, 자격 판정, 입찰 신청, AI 제안서는 공고문에 붙는 기능이라 그리지 않는다
4. 공고문 상세와 원본 공고 상세 모두 머리에 "SAM.gov 원문 보기" 단추(새 창)
5. 공고 상세는 지금처럼 로그인해야 연다. 목록과 집계 화면은 그대로 로그인 없이 연다

## 6. 구현 기록 (2026-10-12)

- 구현하며 더한 것: 공고 상세 응답에 `samUrl`(SAM.gov 원문 공개 주소). 응답의 `uiLink` 는 `sam.gov/workspace/contract/opp/...` 로 SAM 로그인이 필요해, 머리 단추와 본문의 SAM.gov 링크를 모두 `samUrl` 로 바꿨다. 공개 주소는 목록 화면과 같은 설정 `app.sam-gov.public-opportunity-url` 로 만든다(`MarketRowAssembler.samUrl` 을 공개로)
- 공고 상세의 뒤로 단추는 온 화면으로 돌아간다(모은 공고 화면에서도 들어오므로). 주소로 바로 열었으면 마감 전 공고로 간다
