## 4. 설계

### 4.1 사진 자리 (코드 표 `site_photo_slots`)

자리 이름과 목록은 표에 둔다. 코드는 「이 화면 칸은 이 자리 키」만 안다. 3.2 의 10행을 마이그레이션이 넣는다.

| 칸 | 내용 |
|---|---|
| slot_key | 자리 키(PK, 영문 대문자) |
| name | 관리자 화면 이름 |
| location | 보이는 곳 설명 |
| sort_order | 관리자 목록 순서 |

### 4.2 사진 (`site_photos`)

| 칸 | 내용 |
|---|---|
| id | UUID |
| slot_key | 자리(FK) |
| bundled_path | 고객 화면과 함께 배포된 사진 경로(`/img/...`). 처음 8장 |
| storage_url | 관리자가 올린 사진의 저장 경로(StorageService) |
| file_name | 원래 파일 이름 |
| width, height | 저장한 사진 크기 |
| original_width, original_height | 올린 원본 크기(함께 배포된 사진은 비움) |
| size_bytes | 저장한 무게 |
| visible | 고객 화면에 보이나 |
| created_at, updated_at | |

bundled_path 와 storage_url 은 둘 중 하나만 있다(CHECK). 처음 8장은 bundled_path 로 넣어 지금 public/img 파일을 그대로 쓴다. 그래서 첫 배포 뒤 고객 화면이 지금과 같다. 서비스 안내와 로그인, 회원가입이 같은 사진을 나눠 쓰던 것은 자리마다 따로 행을 둔다(행 10개).

### 4.3 설정값 (system_settings, POL-039)

| 키 | 처음 값 | 뜻 |
|---|---|---|
| SITE_PHOTO_ALLOWED_TYPES | image/jpeg,image/png | 받는 형식(쉼표로 나눔) |
| SITE_PHOTO_MAX_UPLOAD_MB | 20 | 한 장 올리는 무게 상한 |
| SITE_PHOTO_MAX_MEGAPIXELS | 50 | 원본 화소 수 상한(백만 화소). 작은 파일에 큰 화면을 숨긴 사진이 서버 메모리를 다 쓰지 않게 |
| SITE_PHOTO_MIN_WIDTH | 1000 | 이보다 좁으면 흐릿해 받지 않는다 |
| SITE_PHOTO_SAVE_WIDTH | 1600 | 이보다 넓으면 이 가로로 줄여 저장 |
| SITE_PHOTO_SAVE_MAX_KB | 400 | 저장 무게 목표 |

비었거나 읽을 수 없으면 처음 값을 쓴다(지금 설정값들과 같은 방식). 올리는 무게 상한은 앱의 올리기 상한(spring multipart 50MB)과 nginx(100M) 안에서만 뜻이 있다.

### 4.4 올릴 때 처리 (BIZ-067)

1. 자리가 없으면 404.
2. 무게가 상한을 넘으면 400 "한 장 20MB 까지 올릴 수 있습니다".
3. 원본 크기를 그림을 다 풀기 전에 읽는다. 형식이 받는 형식이 아니거나 그림으로 읽을 수 없으면 400 "JPEG, PNG 사진만 올릴 수 있습니다". 화소 수가 상한을 넘으면 400.
4. 가로가 최소보다 좁으면 400 "가로 820 사진이라 흐릿하게 보입니다. 가로 1000 이상 사진을 올려 주세요".
5. JPEG 의 촬영 방향 정보(EXIF Orientation)대로 바로 세운다. 휴대폰 사진이 옆으로 눕지 않게 하려는 것이다.
6. 가로가 저장 가로보다 넓으면 비율을 지켜 줄인다(여러 번 반씩 줄인 뒤 마지막에 맞춰 줄여 계단 현상을 막는다).
7. 투명한 부분은 흰 바탕으로 채워 JPEG 로 다시 저장한다. 화질 0.85 부터 0.05 씩 낮춰 저장 무게 목표 안에 들면 멈추고, 0.6 에서도 넘으면 0.6 으로 저장한다.
8. 원본 파일은 남기지 않는다. 다시 저장하므로 사진 속 촬영 위치 같은 정보도 빠진다.
9. 저장 이름은 원래 이름에 확장자 .jpg. 저장하고 행을 넣는다. 행을 넣다 실패하면 저장한 파일을 지운다.

### 4.5 고객 화면이 고르는 방식과 첫 화면 속도

- 사진 목록 API 하나(GET /site-photos)가 자리별로 보이는 사진 주소 목록을 준다. 숨긴 사진은 빠진다.
- 앱이 시작될 때(main.tsx) 목록을 받기 시작하고 화면은 기다리지 않고 바로 그린다. 사진 자리는 목록이 오면 그때 사진을 그린다.
- 받은 목록은 브라우저에 남겨 두고(localStorage), 다음 방문에는 남겨 둔 목록으로 바로 사진을 고른다. 새 목록은 뒤에서 받아 남겨 두기만 하고 지금 보이는 사진은 바꾸지 않는다(보다가 사진이 바뀌지 않게). 그래서 관리자가 바꾼 사진은 손님의 다음 방문부터 보인다.
- 자리마다 고른 사진은 방문 동안 기억해 화면을 옮겨도 같다.
- 남겨 둔 목록의 사진이 그새 지워졌으면 그 사진을 못 받으므로 그리지 않는다(3.2 의 빈 칸과 같음).
- 올린 사진 파일(GET /site-photos/{id}/image)은 한 번 저장되면 바뀌지 않으므로 브라우저가 1년 동안 다시 받지 않게 한다(Cache-Control public, max-age 31536000, immutable). 목록은 받을 때마다 새로 만든다(no-cache).

### 4.6 지우기와 숨기기

- 숨기기는 visible 만 바꾼다. 고객 목록에서 빠지고 관리자 화면에는 남는다.
- 지우기는 행을 지우고, 올린 사진이면 저장 파일도 지운다. 함께 배포된 사진은 행만 지운다(public/img 파일은 고객 화면 배포물이라 남는다). 파일 지우기가 실패해도 행은 지우고 기록만 남긴다.

### 4.7 API

| 순번 | 메서드 | 경로 | 권한 | 내용 |
|---|---|---|---|---|
| 1 | GET | /site-photos | 누구나 | 자리별 보이는 사진 주소 목록. `{ slots: { HOME_INTRO: ["/img/...", "/api/site-photos/{id}/image"], ... } }` |
| 2 | GET | /site-photos/{id}/image | 누구나 | 올린 사진 파일(image/jpeg). 함께 배포된 사진이면 404 |
| 3 | GET | /admin/site-photos | 관리자 | 자리 목록과 자리마다 모든 사진(숨긴 것 포함), 올리기 규칙(4.3 값) |
| 4 | POST | /admin/site-photos | 관리자 | multipart `slotKey`, `file`. 4.4 처리 뒤 만든 사진 정보(201) |
| 5 | PATCH | /admin/site-photos/{id} | 관리자 | `{ visible }` |
| 6 | DELETE | /admin/site-photos/{id} | 관리자 | 지우기(204) |

사진 주소는 서버가 만든다. 함께 배포된 사진은 bundled_path 그대로, 올린 사진은 BE 경로(`<context-path>/site-photos/{id}/image`). 관리자 화면은 운영에서 같은 주소에 열리므로 `/img/...` 를 그대로 쓰고, 로컬에서는 관리자 화면 개발 서버가 `/img` 를 고객 포털 개발 서버로 넘긴다.
