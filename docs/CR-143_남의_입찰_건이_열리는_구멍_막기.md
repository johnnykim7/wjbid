## 6. 설계

### 6.1 규칙

- BIZ-060 입찰 건은 낸 회원과 관리자만(T1-3). API 는 T3-2 F, G, M 절, 시험은 T3-5 TC-OWN-001~013.

### 6.2 본인 확인 자리

- 볼 수 있는 회원인지(낸 회원이거나 관리자)는 입찰 건 하나가 판정한다(`BidRequest.isAccessibleBy`). 여러 서비스가 같은 판정을 쓴다.
- `BidRequestService.findAccessible(id, 회원)`: 없거나 볼 수 없으면 `BidRequestNotFoundException`(404, "입찰 건을 찾을 수 없습니다").
- 입찰 건 상세, 다음 상태, 이력, 문서 목록은 이것으로 찾는다.
- `BidFSMService.customerTransition` 은 호출한 회원을 받는다. 고객 허용 상태 확인(403)을 먼저 하고, 그다음 주인을 본다.
- `ClientDocumentService` 를 둔다. 컨트롤러에 있던 올리기, 목록, 지우기를 옮기고 셋 다 `findAccessible` 로 시작한다. 지우기는 그 서류가 경로의 입찰 건 것일 때만 한다(아니면 404 "서류를 찾을 수 없습니다"). 크기 한도는 박혀 있던 50MB 대신 `spring.servlet.multipart.max-file-size`(지금 50MB)를 읽고, 넘으면 400.
- `ValidationController` 는 `app.validation-api.enabled=true` 일 때만 뜬다. application.yml 기본값 false, application-local.yml true.

### 6.3 고객 화면

- 바꾸지 않는다. 입찰 건 상세가 404 면 "제안서를 찾을 수 없습니다." 가 뜬다(ProposalDetailPage.tsx:353). 나머지 조회는 따로 실패해도 화면이 선다.
