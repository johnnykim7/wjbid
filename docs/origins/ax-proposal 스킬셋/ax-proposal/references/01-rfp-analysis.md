# 01. 공고문/제안요청서(RFP) 분석

**역할**: RFP를 입력받아 ① 컴플라이언스 매트릭스 ② 종합 분석 리포트를 생산한다.
**산출물**: `1-analysis/compliance-matrix.md`, `1-analysis/rfp-analysis-report.md`
**핵심 개념**: 수면 위 이슈(공식 요구사항) + 수면 아래 이슈(행간의 숨은 니즈)

## STEP 0. 파일 변환 (HWP/HWPX인 경우)

1. `.hwpx` 또는 `.hwp` 파일이면 `scripts/convert_hwp.py`를 실행한다:
   ```bash
   python scripts/convert_hwp.py <입력파일> bid-project/source/rfp.md
   ```
2. 변환 후 **표 무결성을 반드시 확인**한다: 배점표·요구사항표·자격요건표가
   깨졌는지 원문 대조. 깨졌으면 사용자에게 해당 페이지 스크린샷 또는 PDF 재업로드를 요청한다.
3. 변환 실패(암호화, 구버전 포맷) 시 사용자에게 PDF 변환 후 재업로드를 안내한다.
4. PDF 입력이면 pdf-reading 스킬 방식으로 읽는다. 원본과 변환본 모두 `source/`에 보관.

## STEP 1. 컴플라이언스 매트릭스 생성 (★척추)

템플릿: `assets/templates/compliance-matrix.md`

추출 규칙:
- RFP 본문·과업지시서·평가표·별첨에 **흩어진 요구사항을 전수 추출**한다
- 한 문장에 요구가 2개면 **2개 항목으로 분리**한다
- **고객의 단어를 그대로 기록**한다. 패러프레이즈 금지 (평가자는 자기 단어를 찾는다)
- 각 항목에 RFP 원문 위치(페이지/조항)를 기록한다
- 요구 동사(제시하라, 기술하라, 증명하라 등)를 보존한다 — 이 동사가 작성 방식을 지시한다
- 구분: **Shall**(필수/의무) / **Should**(권장) / **May**(선택·가점)
- ID 체계: REQ-001부터 순번. 이후 모든 단계에서 이 ID로 참조한다

## STEP 2. 과업 개요 정리

- 사업명, 발주처, 예산(부가세 포함 여부), 기간, 계약 방식(협상/적격/2단계 등)
- 사업 배경·목적: "발주처는 왜 지금 이 사업을 하는가?"를 1문단으로
- 과업 범위: WBS 수준 분해 (Task / Subtask / Deliverable)
- 제출 지시사항: 분량 제한, 서식(폰트/규격), 제출 형식·부수, 마감일시, 발표(PT) 유무
- 일정: 사전규격공개 → 공고 → 질의 마감 → 제안서 마감 → 평가 → 협상

## STEP 3. 발주처 분석

web_search를 활용한다:
- 기관 개요, 비전·경영방침, 최근 조직 개편
- 해당 사업 관련 동향: "{발주처명} {사업 키워드}" 뉴스, 보도자료, 상위 계획(정보화계획 등)
- 이 건에 대한 발주처의 진짜 동기 추정 → 수면 아래 이슈의 재료
- 의사결정 관련 정보: 담당 부서, 평가 방식(내부/외부 위원)
- 발주·낙찰 이력은 STEP 3-A에서 별도 심층 추적한다

## STEP 3-A. 발주 히스토리 추적 (반복 발주·기존 수행사 확인)

**이 사업이 처음 발주된 건인지, 매년/주기적으로 반복되는 사업인지, 직전 수행사는
누구인지**를 반드시 확인한다. 이는 내정 징후 판단(STEP 7), 경쟁 구도(STEP 6),
수면 아래 이슈(행간)의 핵심 재료다.

### 무엇을 찾는가

1. **동일/유사 제목 반복 발주 여부**: 같은 사업명(또는 연도·차수만 바뀐 제목)이
   과거에 반복 공고됐는가. 연례 사업, 다년 분할 발주(1차·2차·연차), 고도화/유지관리
   후속 사업인지 판별한다.
2. **기존 수행업체(Incumbent)**: 직전 및 과거 회차의 낙찰사, 낙찰금액, 낙찰률,
   수행기간, 컨소시엄 구성.
3. **예산·과업 추이**: 회차별 예산 증감, 과업 범위 변화(확대/축소), 계약 방식 변화.
4. **Incumbent 이점 평가**: 기존 수행사가 이번 사업에서 갖는 이점(도메인 지식,
   기 구축 산출물·소스 재사용, 발주처 관계, 전환비용 장벽)의 크기를 가늠한다.

### 검색 소스와 방법 (web_search / web_fetch 활용)

- **나라장터(국가종합전자조달)**: 사업명 키워드로 과거 입찰공고·개찰결과·계약현황 조회.
- **조달청 / 발주처 홈페이지**: 사업공고 게시판, 계약·낙찰 현황, 사전규격 이력.
- **공공기관 경영정보(알리오 ALIO) / 지방공공기관(클린아이)**: 용역·계약 내역 공시.
- **뉴스·보도자료**: "{사업명 핵심어} 낙찰 / 선정 / 우선협상" 검색으로 과거 수행사 확인.
- 검색 쿼리 예시:
  - `"{사업명 핵심어}" 나라장터 낙찰`
  - `{발주처명} {과업 키워드} 사업 수행사 {과거연도}`
  - `{발주처명} {과업 키워드} 우선협상대상자`
- 도구가 없거나 결과가 불충분하면 사용자에게 과거 회차·수행사 정보를 확인 요청한다.
  (검색 결과는 사실 확인이 어려울 수 있으므로 단정하지 말고 출처·확신도를 함께 기록한다.)

### 산출: 발주 히스토리 표

| 연도/차수 | 사업명 | 예산 | 낙찰사(수행사) | 낙찰금액 | 낙찰률 | 계약방식 | 비고 |
|---|---|---|---|---|---|---|---|
| | | | | | | | 반복 여부·과업 변화 |

- 표 아래에 판정을 명시한다: **신규 / 반복(연례) / 후속(고도화·유지관리) / 불명**.
- 반복·후속이면 Incumbent를 STEP 6 경쟁사 프로파일에 '기존 수행사'로 반영하고,
  STEP 7 징후 #4·#6 판단의 직접 근거로 연결한다.
- 반복 발주인데 예산·과업이 기존사에 맞춰 설계된 정황이 보이면 수면 아래 이슈로 기록한다.

## STEP 4. 제안 요청 내용 체크

- 요구사항을 테마별로 그룹핑 (기술/수행·관리/인력/보안/기타)
- 평가표 파싱: 항목별 배점, 정량/정성 구분, 기술:가격 비율
- 평가 항목 ↔ REQ ID 매핑 (어느 요구가 어느 배점에 걸리는지)
- 요구사항 중 모호하거나 해석이 갈리는 항목은 "질의 후보"로 별도 리스트업

## STEP 5. 입찰 가능 조건 검토

자격 요건 전수 추출 → 체크리스트:
- 면허/등록(직접생산증명, SW사업자 등), 인증(ISO, CMMI 등)
- 실적 요건 (유사 실적 건수·금액), 재무 요건 (신용등급 등)
- 참가 제한 (중소기업 간 경쟁, 지역 제한, 컨소시엄 허용 여부)
- 각 항목: 충족 ✅ / 미충족 ❌ / 조건부 ⚠️ (해결 방안 병기)

## STEP 6. 예상 경쟁사 분석

- STEP 3-A 발주 히스토리 표(기존 수행사 포함) + web_search로 경쟁사 3~5개 식별
- 경쟁사별: 솔루션, 레퍼런스, 발주처와의 관계(기존 수행사 여부), 예상 전략
- BCC(Bidder Comparison Chart) 초안: 주요 요구 테마별 자사 vs 경쟁사 1~5점
- 각사 참여 확률 추정 (관심도, 자격 충족 여부, 팀빌딩 가능성)

## STEP 7. 입찰 환경 지표 — 내정 징후 10개 체크

각 항목 O/X/불명 + 근거를 명시하고, 종합 "진입 공정성" 판단(양호/주의/위험)을 내린다.

| # | 징후 | 확인 방법 |
|---|---|---|
| 1 | 공고 기간이 법정 최소치에 가까움 | 공고일~마감일 계산 |
| 2 | 사전규격공개 의견이 묵살됨 | 나라장터 사전규격 의견·회신 조회 |
| 3 | 특정사 제품/기술 스펙 명시 | 요구사항에서 고유 스펙·상표 탐지 |
| 4 | 기존 유사 사업 수행사 존재 (연속 사업) | STEP 3-A 발주 히스토리 (반복·후속 판정) |
| 5 | 과업 범위가 특정사 레퍼런스와 정확히 일치 | 경쟁사 실적 대조 |
| 6 | 예산 대비 과업량 비정상 (기존사만 소화 가능) | STEP 3-A 회차별 예산·단가 추이 비교 |
| 7 | 자격 요건이 과도하게 좁음 | 요건 충족 가능사 수 추정 |
| 8 | 평가 배점이 특정 구도에 유리 (정성 편중 등) | 배점표 분석 |
| 9 | 작성 기간이 신규 진입자에게 불리하게 짧음 | 요구 산출물 대비 기간 |
| 10 | 발주처-자사 사전 접점 전무 (경쟁사는 有 추정) | 사용자에게 확인 |

## 산출물: 종합 분석 리포트 구조

```markdown
# RFP 종합 분석 리포트 — {사업명}
## 1. 과업 개요 (사업 정보, 일정, 제출 지시)
## 2. 발주처 프로파일 (동향, 이 사업의 진짜 동기)
## 2-A. 발주 히스토리 (반복 발주 여부, 기존 수행사, 회차별 예산·낙찰률 추이)
## 3. 요구사항 분석 (테마 그룹, 평가표 매핑, 질의 후보) ※상세는 compliance-matrix.md
## 4. 자격 요건 체크리스트
## 5. 경쟁 구도 (경쟁사 프로파일, BCC 초안, 참여 확률)
## 6. 입찰 환경 지표 (내정 징후 10개 + 공정성 판단)
## 7. 수면 아래 이슈 (행간 분석 — 발주처가 명시하지 않았지만 원하는 것)
## 8. 종합 시사점 (핵심 인사이트 3~5개, 2단계로의 인계 사항)
```

완료 후 `_status.md` 갱신, 사용자에게 핵심 요약(공정성 판단, 자격 이슈, 경쟁 구도)을 보고하고
2단계(Bid/No-Bid) 진행 여부를 확인한다.
