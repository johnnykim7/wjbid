# 05. 상세 섹션 기획 (섹션 기획서 + 목업)

**역할**: 소목차 1개당 섹션 기획서 1부를 작성한다 — 본문 작성의 설계도.
**입력**: 목차 전략표, 수주 전략서, 컴플라이언스 매트릭스
**산출물**: `5-section-plans/S-{목차번호}.md` (예: S-1.1.md)
**템플릿**: `assets/templates/section-plan.md`
**함께 읽기**: `00-writing-style.md`

## 섹션 기획서 7요소 (자이제 섹션기획서 구조)

### 1. 충실도 체크리스트
- 이 섹션이 답할 REQ ID와 원문(고객 단어 그대로)
- 요구 동사(제시/기술/증명…)별로 어떤 형태의 답을 내야 하는지

### 2. 섹션전략
- 목차 전략표에서 할당된 전략 기술문을 인계받아 하위 섹션 수준으로 구체화
- 형식: "무엇을 제안할 것인가 | 제안서에 어떻게 표현할 것인가"
- 인식의 싸움: 이 섹션에서 평가자에게 심을 한 가지 인상은 무엇인가

### 3. 솔루션 정의 + 고객 효용 + 차별성
- 솔루션 특징(Feature)은 **고객의 이슈에서 출발**해 정의한다 (판매자 관점 금지)
- 효용(Benefit)은 가급적 정량화 ("모듈화 기술" → "다양한 기종 장착 가능, 개조 비용 40% 절감")
- 차별성 체크: 경쟁사 대비 차별화 항목에 V 표시 → **V 항목은 반드시 핵심 그래픽 기획**

### 4. 수행 내용 구체화 (수행전략 반영)
- 이 섹션에서 제시할 수행 방법·절차·산출물
- **구체적 사례·실적 연결**: 어떤 레퍼런스/Past Performance를 어떤 형태로 (표, 사진, 수치)
- "무엇을 쓸 것인지"를 실행 가능한 수준으로: 항목 나열이 아니라
  "○○사업 EVMS 적용 실적표 + 절감률 수치 제시"처럼 재료까지 지정

### 5. 섹션 주제문
- 특징→효용 연결, 간결·구체 (예: "○○ 외 2건의 체계통합 경험으로 안정적 통합이 가능하고, 핵심 기술 56종 활용으로 개발기간을 6개월 단축하겠습니다")
- 하위 목차별 주제문도 함께 (목차 트리 순서대로)

### 6. 그래픽 기획
- 핵심 그래픽(차별화 V 항목)의 유형 선택: As-is→To-be / VS / 프로세스 / 시계열 / 구조도 / 병렬
- 담을 핵심 키워드·데이터, 강조 포인트
- Action Caption 초안 (메시지 포함형)
- **시각적 소음 금지**: 섹션당 핵심 도식 1개 원칙. 도식이 필요 없는 섹션은 "없음"이라 쓴다

### 7. 목업 (Mock-Up)
페이지별 배치를 결정한다 — 짜깁기 방지의 핵심 장치.
- 배분 페이지 수 안에서: 제목·주제문 10% / 본문 80% / 마무리 10% 가정
- 페이지마다: [표제 | 주제문 | 그래픽 위치 | 본문 포인트(상세 아닌 포인트만)]
- 상세 문장은 쓰지 않는다. 6단계에서 이 목업대로 채운다

## 실행 규칙

- **한 번에 섹션 기획서 2~3개씩** 작성하고 사용자와 중간 점검 (균등 깊이 유지)
- 모든 소목차에 대해 빠짐없이 작성 — "이하 동일" 금지
- 작성 완료 후 3중 검증 (Pink Team):
  - [ ] 전략 포괄: 전략서의 모든 기술문이 어느 섹션엔가 할당되었는가
  - [ ] 요구 충실: check_coverage.py로 REQ 100% 커버 확인
  - [ ] 평가 포괄: 평가표 전 항목이 대응 섹션을 가지는가
