# 07. 리뷰 — 개선점 추출

**역할**: 완성 본문(또는 중간 산출물)을 평가 기준으로 검토하고 개선 우선순위를 낸다.
**입력**: 본문(md/docx), 컴플라이언스 매트릭스, 평가표, 수주 전략서
**산출물**: `7-review/review-report.md`
**함께 읽기**: `00-writing-style.md`

## 리뷰 시점 (게이트 배치)

| 시점 | 리뷰 | 대상 |
|---|---|---|
| 4단계 후 | Pink | 목차·스토리 (전략/요구/평가 3중 검증 — 04번 파일에 내장) |
| 6단계 후 | Red | 본문 전체 — **이 파일의 메인** |
| 제출 직전 | Gold | 제출 요건·최종 품질 |

## Red Team 리뷰 — 3부 구성

### 제1부. 자동 검증
```bash
python scripts/check_coverage.py   # REQ ID ↔ 본문 매핑, 누락 리스트
```
- 누락 REQ = 즉시 Critical 등급
- 제출 지시사항 대조: 분량 초과/미달, 필수 서식, 필수 첨부

### 제2부. 7가지 기준 정성 평가 (자이제 제안서 평가 기준)

각 기준을 5점 척도 + 근거 + 대표 사례(좋은 곳/나쁜 곳 인용)로 평가한다.

| # | 기준 | 핵심 질문 |
|---|---|---|
| 1 | 충실도 (Compliance) | 요구사항에 빠짐없이, 요구 동사대로 답했는가 |
| 2 | 반응도 (Responsiveness) | 명시 요구를 넘어 수면 아래 이슈까지 대응했는가 |
| 3 | 전략적 초점 | Winning Theme·전략 기술문이 본문에 실제로 구현됐는가 |
| 4 | 경쟁사 초점 | Discriminator가 부각되고 Ghost가 작동하는가 |
| 5 | 헤드라인 구조·가독성 | 4-Box, 주제문, 정보 표제가 지켜졌는가. 찾기 쉬운가 |
| 6 | 신뢰성 (Proof) | 주장마다 증거(실적·수치·사례)가 붙었는가 |
| 7 | 표현 품질 | 어투·카피라이팅 체크리스트 통과 여부, 시각적 소음 여부 |

### 제3부. 모의 채점 (평가자 시뮬레이션)

- 실제 평가표의 항목·배점으로 섹션별 예상 점수를 매긴다
- 채점 관점: "짧은 시간에 평가하는 외부 위원"으로 빙의 — 답을 3분 안에 못 찾으면 감점
- 감점 사유를 항목별로 구체적으로 기록
- 경쟁사가 잘 쓸 것으로 예상되는 항목과 비교해 상대 위치 추정

## 개선 우선순위 산출

개선 항목을 다음 공식으로 정렬해 Top 10을 낸다:

**우선순위 = 해당 평가항목 배점 × 개선 여지(현재 점수와 만점의 격차) × 수정 난이도 보정**

- Critical(요구 누락, 자격 관련) → 무조건 최상단
- 각 항목에 구체적 수정 방안 제시 (어느 섹션, 무엇을, 어떻게)

## 산출물 구조

```markdown
# Red Team 리뷰 리포트 — {사업명}
## 1. 자동 검증 결과 (REQ 커버리지, 제출 요건)
## 2. 7기준 평가 (점수 + 근거 + 사례)
## 3. 모의 채점표 (섹션 × 평가항목, 예상 점수, 감점 사유)
## 4. 개선 우선순위 Top 10 (배점×여지 정렬, 수정 방안)
## 5. 종합 판정 (제출 가능 / 보완 후 제출 / 재작성 권고)
```

리뷰 후 사용자가 수정을 요청하면 6단계 청크 방식으로 해당 섹션만 재작성한다.
