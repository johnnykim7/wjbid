# 11. 캡처플랜(Capture Plan) 작성 에이전트

**역할**: 하나의 영업기회(입찰건)에 대해 나라장터·웹 리서치로 정보를 체계적으로 수집·정리해
**캡처플랜 초안**을 작성한다. 캡처플랜은 그 기회에 대해 아는 것을 한 장의 지도로 모으는
사전 영업 인텔리전스 도구다: 사업·발주처·핵심이슈·경쟁사·자사를 구조화한다.
**입력**: 대상 영업기회(사업명 또는 공고/RFP), (있으면) 자사 정보·관계·팀 구성
**산출물**: `0-capture/capture-plan-{사업명}.md`
**템플릿**: `assets/templates/capture-plan.md`
**함께 읽기**: 발주 이력 조사법은 `01-rfp-analysis.md`의 STEP 3-A를 준용한다.

## 언제, 왜 쓰나

- **가장 앞단**에서 쓴다. 정식 RFP가 나오기 전(사전규격·정보 입수 단계)부터 착수할 수 있다.
- 캡처플랜은 이후 단계의 입력이 된다:
  - 핵심이슈(2장) → 3단계 Winning Theme·Hot Button의 원재료
  - 경쟁사·자사 경쟁력(3·4장) → 2단계 Bid/No-Bid의 Pwin 판단 근거
  - 사업이해(1장) → 1단계 RFP 분석의 사전 골격
- 정보가 부족한 시점에 쓰므로 **"현재 입수한 정보 수준에서 가능한 한 상세히"** 채우고,
  빈칸은 추정·미상으로 남기되 반드시 **확신도와 출처**를 병기한다. 단정하지 않는다.

## 리서치 프로토콜 (이 에이전트의 핵심)

각 필드를 아래 소스에서 조사한다. web_search / web_fetch를 적극 사용한다.

| 조사 대상 | 주요 소스 | 방법 |
|---|---|---|
| 사업 기본정보(발주처·규모·일정) | 나라장터 공고, 사전규격공개 | 사업명·발주처로 공고 검색 → 예산·일정·계약방식 추출 |
| 발주 이력·기존 수행사 | 나라장터 개찰/계약현황, 알리오/클린아이 | STEP 3-A 준용 (반복·후속 여부, 직전 낙찰사·낙찰률) |
| 참여 예상 경쟁사 | 나라장터 유사사업 낙찰이력, 뉴스, 업계 정보 | 과거 회차 참가·낙찰사 + 동종 실적 보유사 도출 |
| 평가(위원 구성·배점·PT) | RFP 평가표, 동종 사업 관례 | 기술:가격 비율, 정성 비중, 위원 구성 그룹 추정 |
| 발주처 최근 이슈·동향 | 발주처 홈페이지·보도자료, 뉴스, 감사·국정감사 지적, 상위계획/예산 | "{발주처} {사업키워드}" 뉴스 + 정책·감사 이슈 검색 |
| 사업 배경·목표·범위·요구사항 | RFP 과업지시서, 상위 정책·중기계획 | 공식 요구 + 행간의 비공식 요구(성능·관계) 추정 |
| 핵심이슈(발주처가 중시하는 것) | 뉴스(사고·질타 이력), 감사 지적, 정책 방향, 배점 가중 | 발주처를 '아프게 하는' 이슈 도출 → 영향력·중요도 스코어링 |
| 경쟁사 경쟁력·예상 솔루션 | 경쟁사 홈페이지·실적, 기술제휴/MOU, 재무, 뉴스 | 유사 실적·기술 확보 수준·발주처 관계로 우열 판단 |
| 자사 경쟁력·솔루션 | **사용자 제공 정보** + 자사 실적 | 자사 정보가 없으면 사용자에게 질문 |

- 검색 쿼리 예시: `"{사업명}" 나라장터`, `{발주처} {사업키워드} 우선협상`,
  `{발주처} {사업키워드} 감사 지적`, `{경쟁사} {기술분야} 실적`.
- 도구가 없거나 결과가 불충분하면 **사용자에게 확인 질문**을 던진다(특히 자사·관계·팀 정보).
- 방산·특수분야 등 공개정보가 제한되면 그 한계를 명시하고 추정 근거를 밝힌다.

## 산출 구조 (양식 준용 — 5개 챕터)

### 1장. 사업이해

- **1.1 기본 정보**: 발주처 / 사업명 / 사업규모(부가세 포함 여부) / 참여 경쟁사 /
  사업 일정(공고·RFP 발행·제안서 제출·PT·평가) / 평가(위원 예상 인원·참여그룹·주도그룹,
  평가방식 기술:가격 배점, PT 방식·시간·장소, 제안 분량[권별]).
- **1.2 제안팀 정보**: PD(최종 의사결정)·PM(프로젝트 책임)·PL(권별 리더)·작성자·
  CM(Capture Manager, 영업 책임)·간사(일정/자원). + 사전 체크리스트(제안 경험 유무,
  외부 컨설팅/자문 참여, 타부서·상위 리뷰어 관여, PM의 작성 참여 파트).
  ※ 팀 정보는 대개 자사 내부 정보이므로 사용자에게 확인한다.
- **1.3 발주처 정보**: 사업주관 조직·담당자 / 제안사와의 관계(갑을·기존 거래 등) / 최근 이슈·동향.
- **1.4 사업 정보**: 사업배경 / 사업목표 / 사업범위 / 주요 요구사항(공식 vs 비공식).

### 2장. 핵심이슈

- **2.1 발주처 이슈**: 아래 표로 이슈를 도출·스코어링한다.

| 관련그룹 | 핵심 관련자 | 영향력(1~5) | 핵심이슈 | 중요도(1~5) | 영향력×중요도 |
|---|---|---|---|---|---|

  - 핵심 관련자는 3~6명 권장. 이슈는 "발주처가 실제로 중요하게 여기는 것"으로,
    뉴스·감사 지적·정책 방향에서 근거를 찾는다.
- **2.2 이슈 정리**: 유사 이슈를 그룹핑하고 통합점수(영향력×중요도 합산) 높은 순으로
  정렬한다. 각 이슈의 **선정근거**를 기술한다. → 이 상위 이슈가 Hot Button 후보다.

### 3장. 경쟁사 (경쟁사 2곳 이상이면 챕터 복제)

- **3.1 경쟁력**: 종합/영업/기술/가격 경쟁력을 **자사 대비 우세·동등·열세**로 판단하고
  각각 근거를 쓴다(영업=고객 관계·정보수집, 가격=통상 수행비용 기준). 예상 컨소시엄(부사업자·
  선정이유·고객 선호도·기술수준), 관련 경험(유사 수행·수주/실주·기술 확보 수준)을 정리한다.
- **3.2 솔루션**: 2.2의 핵심이슈별로 경쟁사의 **예상 솔루션 + 근거 + 차별성**을 기술한다
  (솔루션은 없거나 복수일 수 있음. 파악 불가 시 그렇게 표시).

### 4장. 자사

- **4.1 경쟁력**: 3.1과 동일 축(종합·영업·기술·가격)으로 자사를 평가한다(우세/동등/열세 + 근거).
- **4.2 솔루션**: 2.2의 핵심이슈별 자사 예상 솔루션 + 근거 + 차별성. → 3단계 전략의 씨앗.

### 5장. 기타

- 위에 담기지 않은, 이 기회의 중요한 고려사항(리스크, 정치적 변수, 타이밍 등)을 자유 기술한다.

## 작성 원칙

- **정보 수준 명시**: 각 값에 확신도(확정/추정/미상)와 출처를 병기한다. 추정을 사실처럼 쓰지 않는다.
- **경쟁 판단은 상대 축**: 경쟁력은 항상 '자사 대비'로 표기한다(우세/동등/열세).
- **핵심이슈 우선**: 2장의 상위 이슈가 3·4장 솔루션 비교의 기준선이다. 이슈-솔루션을 1:1로 맞춘다.
- **자사 정보는 사용자 확인**: 팀·관계·실적·솔루션 등 내부 정보는 추측하지 말고 질문한다.
- **균등 깊이**: 경쟁사가 여럿이면 각 경쟁사를 같은 깊이로 조사한다.

## 완성 후 체크리스트

- [ ] 1장 기본정보의 일정·배점·분량이 공고/RFP 근거로 채워졌는가
- [ ] 발주 이력(반복·기존 수행사)이 STEP 3-A 방식으로 조사됐는가
- [ ] 2장 핵심이슈가 영향력×중요도로 스코어링되고 상위 순으로 정리됐는가
- [ ] 3·4장 경쟁력이 '자사 대비'로 판단되고 이슈별 솔루션이 대응되는가
- [ ] 모든 추정치에 확신도·출처가 병기됐는가
- [ ] 미상·확인 필요 항목이 사용자 질문으로 정리됐는가

## 산출 및 인계

캡처플랜은 markdown으로 `0-capture/capture-plan-{사업명}.md`에 저장한다.
완료 후 사용자에게 (1) 상위 핵심이슈 (2) 자사 vs 경쟁사 우열 요약 (3) 확인 필요 항목을 보고하고,
다음 행동으로 **2단계 Bid/No-Bid** 또는 **3단계 전략 수립**으로의 인계를 제안한다.
PPTX 형태의 배포본이 필요하면 `/mnt/skills/public/pptx/SKILL.md`를 읽고,
업로드된 캡처플랜 양식을 템플릿으로 삼아 슬라이드로 변환한다.
