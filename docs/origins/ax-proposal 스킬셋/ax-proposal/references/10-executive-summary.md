# 10. ES(Executive Summary) 작성 에이전트

**역할**: 제안서 맨 앞에 놓여 평가자·의사결정자를 1~2페이지 안에 설득하는
경영 요약(Executive Summary)을 작성한다. 4-Box + Hot Button 구조를 사용한다.
**입력**: Winning Theme, 고객 비전, Hot Button 목록(3단계 전략서), HB별 근거(Proof),
평가표, (있으면) 컴플라이언스 매트릭스
**산출물**: `6-proposal/sections/00-executive-summary.md` (제안서 본문에 편입)
**함께 읽기**: `00-writing-style.md`, `03-win-strategy.md`(Hot Button 정의)
**템플릿**: `assets/templates/es-4box.md` (4-Box 뼈대 + 청중 검증표를 채워 쓴다)

## 언제 쓰나

- RFP 제안 트랙: **6단계 본문 작성의 첫 청크**로 ES를 먼저 쓴다(06-writing.md와 연동).
- 단독 요청: "ES만", "경영 요약만" 요청 시 이 에이전트를 독립 실행한다.
- 세일즈용 '미팅 제안서'(09)와 구분한다: 09는 아웃바운드 세일즈 문서,
  본 ES는 공식 제안서 제출용 요약이다. 다만 정량화·스토리·정보 표제 원칙은 공유한다.

## Hot Button이란

Hot Button = 고객이 **계약자(제안사)를 선택할 때 실제로 중요하게 보는 이슈**.
평가표 배점, RFP가 반복 강조하는 요구, 발주처 최근 관심사에서 도출한다.
ES 전체가 이 Hot Button 목록을 축으로 전개된다(3단계 전략서에서 확정된 것을 가져온다).

## 4-Box 구조

### Box 1 — Summary: 전략적 오프닝 (Theme · Vision · Link)

- **Theme(Winning Theme)**: 제안 전체를 관통하는 한 문장을 **첫 문장**에 배치한다.
- **Vision(고객 비전)**: 고객이 이루려는 궁극 목표를 고객의 언어로 진술한다.
  가능하면 고객 측 공식 발언·연차보고서·뉴스 인용으로 앵커링한다(출처 명기).
- **Link(연결 문장)**: 우리 제안이 그 비전 달성에 어떻게 직결되는지 한 문장으로 잇는다.

### Box 2 — Introduction: Hot Button List (프리뷰)

- 고객과의 논의·RFP 분석을 통해 파악한 **핵심 이슈 목록**을 제시한다.
  예: "T2OO 계약자 선정에서 특히 중요한 이슈는 다음과 같이 이해하고 있습니다:"
- Hot Button을 **우선순위 순 불릿**으로 나열한다(공중·작업 안전 / 리스크 회피 방법론 /
  경험 있는 핵심 인력 / 자원·자재·인력 확보 등).
- "이어지는 내용에서 각 이슈에 대한 우리의 접근을 설명합니다"로 본문을 예고한다.

### Box 3 — Body: Hot Button별 상세 (Benefit · Solution · Proof · Visual)

각 Hot Button을 **정보 표제**(제목만 읽어도 메시지 전달)로 열고, 아래 순서로 전개한다:

| 요소 | 내용 |
|---|---|
| Benefit | 이 이슈를 우리가 다루면 **고객이 얻는 효용**(고객 주어로) |
| Solution | 그 효용을 만드는 우리의 구체적 접근·방법 |
| Proof | 정량 근거·실적·수상·통계(숫자·고유명사로 신뢰 확보) |
| Visual | 이슈당 핵심 비주얼 1개 + Action Caption |

- 순서 원칙: 위로 갈수록 주장(Benefit), 아래로 갈수록 근거(Proof).
- **여백 콜아웃(Action Caption)** 기법: 본문 옆 여백에 핵심 실적을 한 문장으로 배치해
  훑어만 봐도 강점이 각인되게 한다.
  예: "당사는 6개 도시에서 27개 지하철 프로젝트를 건축물·기반시설 피해 없이 완수했습니다."
- Hot Button 개수만큼 **같은 깊이**로 전개한다(균등 깊이 원칙 — 뒤 이슈가 부실해지면 안 된다).

### Box 4 — Review: 요약과 다음 단계 (Summary · Next Steps)

- **Summary**: "우리를 선택하면 고객은 다음을 확보합니다"로, Box 3의 핵심을 불릿으로 재요약한다.
  각 불릿은 Hot Button과 1:1로 대응시킨다.
- **수미상관**: Box 1의 Theme을 마지막 문장에서 다시 언급해 닫는다.
- **Next Steps**: 필요 시 다음 절차·기대를 간결히 덧붙인다.

## 작성 원칙 (00번 파일 필수 준수)

- **고객 주어**: "귀 기관은 ~을 확보하게 됩니다" (✗ "저희는 ~에 강점이 있습니다").
- **정량·구체화**: "최적의/선진화된" 같은 추상어 금지. "50% 단축", "27개 프로젝트 무사고"처럼.
- **정보 표제**: Hot Button 제목은 그 자체로 메시지가 되게 한다. 단, RFP 지정 표제는 원문 그대로.
- **F-B-P 체인**: Feature만 나열하고 Benefit을 빠뜨리지 않는다.
- **어투**: Theme·헤드라인·Action Caption·ES 본문은 완결문 합쇼체, 근거 나열 불릿은 개조식.
- **분량**: A4 1~2p. 다중 독자(의사결정자·기술평가자·실무자) 각각에게 설득력 있는지 자체 검증.

## 완성 후 체크리스트

- [ ] Box 1 첫 문장 = Theme, 고객 비전은 고객 언어(가능하면 인용)로 앵커링했는가
- [ ] Box 2가 우선순위 순 Hot Button List인가
- [ ] Box 3의 각 HB가 Benefit→Solution→Proof→Visual 순서이고 Proof에 숫자가 있는가
- [ ] 여백 Action Caption으로 핵심 실적이 스캔 가능한가
- [ ] Box 4가 HB와 1:1 대응하는 요약 + Theme 수미상관으로 닫혔는가
- [ ] 모든 Hot Button이 균등한 깊이로 다뤄졌는가

## 산출 및 편입

ES는 markdown으로 작성해 `sections/00-executive-summary.md`에 저장한다.
`assets/templates/es-4box.md`의 뼈대를 채우고, 하단 **청중 검증표(EB·TB·User)**로
세 독자 모두에게 설득력이 있는지 자체 점검한다.
6단계 DOCX 조립 시 목차 다음, 본문 앞에 배치한다. 여백 콜아웃은 DOCX에서
사이드바 텍스트 상자 또는 본문 강조 문장으로 구현하고, Visual에는 Action Caption을 붙인다.
