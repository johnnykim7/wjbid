# 원본 요구사항: 공고 사전 분석 파이프라인 (CR-003)

> 입력일: 2026-03-28
> 입력자: 사용자 (대화창 텍스트)

---

## 전체 시나리오

### [백그라운드 프로세스]
1) SAM.org에서 공고를 주기적으로 조회한다 (최소 1일 1회)
2) 새로운 공고가 발생하면, 관리자에게 Noti를 준다 (문자 나 이메일)
3) 새로운 공고안에 첨부파일이 있으면, 해당 첨부파일을 LLM에게 분석 요청하여, 요약본을하나 만들고, 문서양식을 만들고, 필요한 서류목록을만들어서 사용자 페이지에 게재한다. 이때, 추후 사용자가 신청할때 LLM에게 요청할 내용을 요약한것을 이때 어딘가에 저장해놓는다. (이때 노출은 하지않고 비노출로 설정)
4) 사용자페이지에서 사용자가 작성 요청을 하면, 사용자가 올린 문서와 위 백그라운드에서 생성한 문서양식 및 공고요약등 필요한 정보들을 모아서 LLM에게 작성 요청을 한다. (위 3번에서 정리한 문서들)
5) LLM으로 응답이 오면 (파이선코드가 될지 뭐가 될지 그건 설계에 따라) 그걸 기반으로 최종 문서를 만든다.

### [관리자 페이지]
1) 관리자는 페이지에서 신규 공고를 조회하여, 첨부파일 (PWS, RFP등등 요청서)이 있는지 여부를 체크하여, 첨부파일이 있으면 그냥두고, 첨부파일이 없으면 관리자가 수동으로 업로드한다
2) 수동으로 업로드된 파일을 기반으로, [백그라운드 프로세스] 3)번의 동작을 수행한다.
3) 관리자는 수동으로 업로드를 하든, 자동으로 문서가업로드되든, 사용자페이지에 공고문이 게재된후, 승인을 하여 최종 사용자 페이지에서 노출되도록한다.

### [사용자 페이지]
1) 사용자는 게재된 공고문의 내용을 보고 필요 서류들을 첨부한다. 이때 시스템에서는 앞서 절차들에 따라 필요한 문서를 알고 있기에 누락된 문서가 있는여부를 체크할수 있도록 한다.

---

## 추가 논의사항

### LLM 문서 작성 시 입력 파이프라인 3개
1. **공고 사전 분석** — 공고 수집 시 1회 실행, 결과 캐시
2. **사용자 제출 서류** — 사용자 신청 시마다
3. **과거 제출 이력** — 플랫폼을 통해 제출된 과거 문서들. 초기엔 데이터 0건이지만 파이프라인 구조는 동일하게 설계. 조회해서 넘기면 끝 (비어있으면 빈 배열).

### 설계 원칙
- 공고 분석은 공고당 1회 — 여러 사용자가 신청해도 재분석 불필요
- 과거 이력 조회에 조건 분기(if) 불필요 — 그냥 조회해서 넘기면 됨. 비어있으면 빈 배열일 뿐
- LLM 입력 = 공고 분석 결과(캐시) + 사용자 서류 + 과거 이력(있는 만큼)
