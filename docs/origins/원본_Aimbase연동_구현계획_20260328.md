# Aimbase 연동 구현 계획 — 원본 대화 기록

> 날짜: 2026-03-28
> 출처: 사용자-AI 대화 (입찰제안시스템 Aimbase 연동 검토)

---

## 실제로 필요한 흐름

RFP 문서 투입
  → LLM이 RFP를 읽고 요구 구조/평가항목 파악
  → 회사 역량·실적 데이터(RAG)에서 관련 내용 검색
  → RFP 요구 구조에 맞춰 내용 작성
  → Word 문서로 출력
이건 템플릿 문제가 아니라 RAG + LLM 생성 + 문서화 파이프라인 문제입니다.

## Aimbase로 구현 가능한 구조

| 단계 | 활용 기능 | 역할 |
|------|----------|------|
| 1 | RAG 인제스션 | RFP 문서(PDF) 파싱·청킹 |
| 2 | RAG 인제스션 | 회사 실적·역량 자료를 지식베이스로 구축 |
| 3 | LLM_CALL | RFP에서 목차·평가항목·제출 요건 추출 |
| 4 | LLM_CALL + RAG | 각 섹션별로 회사 데이터 기반 내용 생성 |
| 5 | TOOL_CALL | python-docx 코드로 Word 문서 생성 |

여기서 5단계가 관건인데, RFP마다 구조가 다르니까 LLM이 python-docx 코드 자체를 생성하고 generate_document API로 실행하는 방식이 됩니다.

## 솔직히 말하면

이건 Aimbase의 범용 기능을 조합해서 할 수는 있지만, 입찰제안 전용 시스템으로 만드려면 별도 설계가 필요합니다:

- RFP 분석 로직 (평가항목 추출, 배점 구조 파악)
- 회사 자산 DB 구조 (실적, 인력, 인증서 등)
- 섹션별 생성 품질 관리 (할루시네이션 방지)
- 문서 레이아웃 품질 (표, 이미지 배치 등)

Aimbase를 백엔드 엔진으로 쓰되, 입찰제안 도메인 로직은 별도 레이어로 설계하는 게 맞을 것 같습니다.

## 역할 분담 결론

별도 레이어로 할 것. Aimbase는 인프라 엔진 역할이고, 입찰제안시스템이 소비앱으로 Aimbase API를 호출하는 구조.

### Aimbase가 담당하는 영역

1. **RFP 문서 분석 (RAG)**
   - RFP PDF/DOCX 인제스션 → 파싱·청킹·임베딩
   - RFP 내용에 대한 질의 (평가항목, 제출 요건 등 추출은 소비앱이 프롬프트로 지시)

2. **회사 지식베이스 (RAG)**
   - 실적, 역량, 인력, 인증서 등 자료 인제스션·관리
   - 섹션 작성 시 관련 자료 검색·제공

3. **LLM 호출 (오케스트레이션)**
   - 프롬프트 기반 섹션별 내용 생성
   - 멀티 LLM 라우팅 (Anthropic/OpenAI 선택)
   - 정책 엔진 (토큰 제한, 비용 관리)
   - 세션 관리 (대화 컨텍스트 유지)

4. **문서 출력 (Document Generation)**
   - python-docx 코드 실행으로 Word 생성
   - generate_document API (코드 → 바이너리)

5. **인프라**
   - 멀티테넌시 (고객사별 격리)
   - API Key 인증
   - 감사 로깅

### 소비앱(이 플랫폼)이 담당해야 하는 영역

- RFP 올리는 화면
- 생성된 문서 보고 수정하는 화면
- 입찰 건별 관리 화면 (목록, 상태)
- 어떤 순서로 Aimbase API를 호출할지 (이것도 워크플로우로 넣으면 더 줄어듦)

### 한 줄 요약

- Aimbase = "문서 넣고, 검색하고, LLM 돌리고, Word 찍어내는" 엔진
- 소비앱 = "무엇을 넣고, 뭘 검색하고, 어떤 프롬프트로, 어떤 구조의 Word를" 결정하는 두뇌

## 회사 자산 DB 관련

회사 실적·인력 데이터가 기존 시스템에 있다면 → MCP 서버로 연결하면 됨.
소비앱이 직접 DB를 만들 필요 없이, 기존 시스템에 MCP 서버만 붙이면 Aimbase가 LLM 실행 중에 알아서 가져다 씀.

| 회사 데이터 위치 | 연동 방식 |
|----------------|----------|
| 기존 시스템(ERP, HR 등)에 있음 | MCP 서버로 노출 → Aimbase가 도구로 호출 |
| 문서 형태(PDF, Word)로 있음 | RAG 인제스션으로 지식베이스 구축 |
| 아직 없음 (새로 구축) | 그때만 소비앱에서 DB 설계 필요 |

## 문서 레이아웃 관련

LLM이 코드까지 생성하는 방식 — Aimbase 안에서 다 해결됨.

```
LLM_CALL: "다음 목차 구조로 python-docx 코드를 작성해줘"
  → TOOL_CALL: generate_document(생성된 코드 실행)
  → Word 파일 출력
```

## 추가 결정사항 (2026-03-28)

- 문서 출력은 이 플랫폼에서 안 함. Aimbase에서 처리.
- 최종 제안서가 Word일지 PDF일지는 RFP를 봐야 알 수 있음. RFP마다 다름.
- RAG: MVP에서는 미사용. 단, 과거 제안서에서 아이디어를 얻을 수 있으므로 향후 RAG 확장 가능성 열어둠.
