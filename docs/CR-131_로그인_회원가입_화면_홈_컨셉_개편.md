## 4. 정할 것

### 4.1 비밀번호 찾기 빈 링크 (결정: 1, 재설정 기능은 docs/CR/BACKLOG.md BL-001)

1. 고객센터 이메일로 문의하라는 안내 문구로 바꾸고, 메일 재설정 기능은 백로그에 둔다 (권장). 1:1 문의 화면은 아직 서버에 닿지 않아 안내처로 쓸 수 없다.
2. 링크를 감춘다 (잊은 사람이 길을 못 찾는다).
3. 메일 재설정 기능을 새로 만든다 (백엔드, 메일 양식, T1 부터 캐스케이드, 규모가 커진다).

### 4.2 이미 가입된 이메일 안내 (결정: 1)

1. 서버가 "이미 가입된 이메일" 을 정해진 오류 코드(409)로 알려 주고 화면이 그 코드를 보고 한글 안내를 낸다 (권장, 서버 수정 소).
2. 화면만 고치고 서버 문장은 그대로 둔다 (영문 문장이 빨간 줄에 그대로 보인다).

### 4.3 설계

- 설계서 반영: T1-1 BID-AUTH-001 (입력을 실제 가입 항목으로, 이미 가입된 이메일 안내), BID-AUTH-002 (비밀번호 찾기 안내), BID-BROWSE-006 (공통 틀 적용 범위에 로그인·회원가입 포함). T3-2 /auth/register 409. T3-3 「로그인」, 「회원가입」. T3-4 「로그인·회원가입」. T3-5 TC-AUTH-002.
- 서버: 회원 서비스가 이미 가입된 이메일이면 전용 예외를 던지고, 예외 처리기가 409 와 `{ error: "EMAIL_ALREADY_EXISTS", message }` 로 바꾼다. 기존 처리기(CustomerTransitionExceptionHandler)와 같은 모양이다. 다른 예외의 동작은 바꾸지 않는다.
- 화면: 두 화면을 공통 틀 라우트 묶음으로 옮긴다. 화면이 서버 문장을 그대로 보이지 않고, 오류 코드를 보고 칸 아래 한글 안내를 낸다. 문구 중 고객센터 이메일, 무료 회원 혜택은 화면 정의 파일(siteContent.ts) 값을 쓴다.

## 5. 완료 조건

1. 로컬에서 로그인, 로그인 실패, 가입 직후, 회원가입, 가입 오류(입력), 가입 오류(이미 가입) 여섯 상태를 1440x900 으로 찍어 목업과 홈 정본 캡처와 나란히 대조하고, 머리말 끝(192)이 홈과 같고 넘친 글자가 없다.
2. 강조색 묶음 7개를 차콜과 주황 값으로 바꿔 두 화면이 함께 바뀌는 것을 로컬에서 확인하고 되돌린다.
3. 이미 가입된 이메일로 가입하면 로컬 서버가 409 `EMAIL_ALREADY_EXISTS` 를 돌려주고 화면이 칸 아래 한글 안내를 낸다.
4. 운영 배포(./deploy.sh, 서버와 화면이 함께 바뀌어 all)와 운영 화면 확인.

### 함께 고친 것

- 로그인·가입 요청이 401 을 받으면 화면 공통 처리가 토큰 갱신을 시도하고, 남은 옛 토큰이 있으면 갱신이 실패해 화면을 새로 열어 실패 안내가 사라졌다(api/client.ts). 로그인·가입 요청의 401 은 갱신하지 않게 했다.
- 공통 틀 손댐 두 곳은 컨타에 먼저 알렸다(22:58): 아이콘 묶음에 알림·확인 원 아이콘 2개 추가, 공통 레이아웃 설명 주석의 적용 범위 문구.
