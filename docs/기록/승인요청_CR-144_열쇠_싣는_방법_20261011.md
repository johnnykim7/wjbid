# CR-144 열쇠 싣는 방법과 반영 순서 승인요청 (2026-10-11)

확인한 것의 근거는 [../CR-144_Aimbase_가_부르는_통로에_열쇠_확인_넣기.md](../CR-144_Aimbase_가_부르는_통로에_열쇠_확인_넣기.md) 3절에 있다.

- Aimbase 는 지금 우리 통로를 부를 때 머리글을 실을 수 없다. 등록은 주소 하나만 읽고 물음표 뒤 값도 버린다. 첨부 내려받기도 머리글 없이 주소 그대로 부른다. 쓰는 라이브러리에는 머리글 기능이 있어 Aimbase 가 몇 줄 고치면 된다.
- 운영 등록은 SSE, http://59.8.160.12:8183/api/mcp, 상태 disconnected, 도구 20개다. 바꾸기 전 값은 [Aimbase_MCP_등록_백업_CR-144_20261011.json](Aimbase_MCP_등록_백업_CR-144_20261011.json) 에 받아 두었다.
- 그런데 Aimbase 는 지금 우리 서버에 아예 닿지 못한다(Aimbase 서버 안에서 8183 이 시간초과, 10/10 15:00 부터 1분마다 실패). 공고 분석은 7/28 이 마지막 성공이고 8/18~9/1 은 "알 수 없는 도구" 로 실패, 9/1 뒤로 실행이 없다. 열쇠를 켜서 끊길 분석이 지금은 없다.
- 규모 소: 새 API, 화면, 표가 없다. 설계서(T1-3 BIZ-061, T3-2 MCP 절, T3-5 시험)를 먼저 고친다. 마이그레이션은 없다.

| 순번 | 정할 것 | 선택지 |
|------|--------|--------|
| 1 | 열쇠 싣는 방법 | ①Aimbase 에 "등록에 머리글 싣기" 를 그 레포 CR 로 요청하고, 우리는 X-API-Key 머리글을 본다(권장. 표준 방식. Aimbase 수정과 배포가 그쪽 창에서 필요) ②등록 주소 경로에 열쇠를 넣는다(Aimbase 를 안 고친다. 대신 Aimbase 가 1분마다 남기는 로그와 등록 조회에 열쇠가 그대로 찍힌다) |
| 2 | 첨부, 샘플 내려받기 주소 | ①우리가 Aimbase 에 건네는 내려받기 주소에 기한 있는 서명을 붙인다(권장. Aimbase 내려받기 도구를 안 고친다. 기한은 설정값) ②같은 열쇠를 주소에 붙인다(주소가 새면 열쇠도 샌다) |
| 3 | 끊긴 통로 | ①서버 망 복구를 새 CR 로 먼저 열고, CR-144 운영 확인(Aimbase 가 열쇠로 붙고 공고 분석 1건이 도는지)은 그 뒤에 한다(권장) ②CR-144 에서 같이 고친다(서버 sudo 권한 필요) |

반영 순서 (①①① 기준)

1. Aimbase 창: 등록에 머리글 싣기를 만들고 배포한다(SSE 연결, 메시지 보내기, Streamable 모두. 등록 조회와 로그에서 머리글 값은 가림).
2. 망 복구 CR: Aimbase 가 지금 등록 그대로 다시 붙는지(도구 20개) 확인한다.
3. 이 창: 설계서 커밋, 구현, 로컬 확인(열쇠 없음 401, 틀린 열쇠 401, 맞는 열쇠 통과, 서명 없는 내려받기 401, 기한 지난 서명 401). 바깥 Aimbase 는 부르지 않는다.
4. Aimbase 등록 변경(운영 쓰기): config 에 headers 로 X-API-Key 를 더하고 /reconnect. 우리 쪽 확인이 아직 없어 열쇠가 더 실려도 지금처럼 붙는다.
5. 이 플랫폼 배포: 서버 환경변수에 같은 열쇠를 두고, 커밋분을 깨끗한 작업 폴더에서 빌드해 BE 배포. 이때부터 열쇠 없는 호출은 막힌다.
6. 운영 확인: 바깥에서 열쇠 없이 부르면 401, Aimbase /reconnect 로 도구 20개, 공고 분석 1건 실행.

알림

- 같은 파일: 보안 설정은 /mcp 줄 주석만 고치고, 열쇠 확인은 따로 둔 거름망에 둔다. CR-143 창과 커밋 순서를 맞춘다.
- 내려받기 주소를 만드는 NoticeService 에 다른 창 수정이 있다. 한 줄만 바꾸고 줄 단위로 커밋한다.
- 열쇠 값은 4, 5 를 할 때 서버에서 만들고, 문서와 커밋에는 넣지 않는다.
