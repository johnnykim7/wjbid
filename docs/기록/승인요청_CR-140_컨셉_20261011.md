# CR-140 공고별 판정 화면 컨셉과 정할 것 승인요청 (2026-10-11)

컨셉: docs/CR-140_메뉴_속_화면_4묶음_공고별_판정.md 4절(판정 규칙), 5절(화면). 맞춤 판정 속페이지에 "공고별 판정" 화면을 새로 두고, 공고 검색 목록에 "우리 회사" 칸, 공고 상세에 판정 상자, 공고별 진단에 판정 꼬리표를 더한다. 판정마다 걸린 자격의 이름, 원문 위치, 내 답, 서류 상태를 함께 보인다.

실측: 판정할 수 있는 공고 19건(모두 마감 지남), 통과 조건 자격 63개 중 서류함 분류와 이름이 맞는 것은 13개다.

| 순번 | 정할 것 | 선택지 |
|------|--------|--------|
| 1 | 화면 컨셉 | ①컨셉+목업(권장) ②컨셉만 ③그냥 진행 |
| 2 | 판정 규칙 | ①CR 문서 4절대로: 없음 하나면 어려움, 답 안 함·확인 필요면 판정 전, 모두 있음인데 서류 없거나 만료면 서류 부족, 다 있으면 참여 가능(권장) ②계획 3.2 문장 그대로 |
| 3 | 서류 부족을 어떻게 아나 | ①"있음" 으로 답할 때 서류함 서류를 붙인다. 이름이 맞는 서류는 먼저 제안(권장, 답 표 칸 하나와 API 하나) ②이름이 맞는 자격만 기계가 본다(잃는 것: 통과 조건 63개 중 50개는 답만 믿고 "참여 가능" 이 나옴) |
| 4 | 자격 묶음 | ①이번에는 하지 않고 공고마다 답한 것으로 판정, 묶음은 따로 CR(권장) ②이번에 회사 자격 표와 묶음까지(대) |

알림

- 새 화면 하나와 화면 세 곳 고침, API 응답 확장이라 규모는 중이다. 승인 뒤 설계서(T1, T3)부터 고치고 설계분을 커밋한 뒤 구현한다.
- menu.ts 는 공고별 판정 줄의 목적지만, subpageContent.ts 는 opportunity-fit 안내만 뺀다. 고치기 전에 컨타에 알린다.
- 마감 전 공고는 분석된 것이 아직 없어 운영에서는 지난 공고로만 판정이 보인다(CR-137 결정 4와 같음).
- 컨타 11:29 [알림]대로 적격성 진단 서비스 시험 TC-QUAL-001~015 도 이 CR 에서 쓴다.
