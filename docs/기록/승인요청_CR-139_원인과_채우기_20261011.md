# CR-139 원인과 고칠 방향, 채우기 승인요청 (2026-10-11)

원인(운영 DB 와 Aimbase 기록 읽어 확인): 수집 때 제목 번역은 매번 돌고 Aimbase 는 한글 제목을 돌려주는데, 그 결과를 DB 에 저장하지 않고 버린다. 6/2 뒤로 저장되는 경로는 관리자 단추뿐이다. 상세는 docs/CR-139_수집_때_공고_한글_제목이_빠지는_결함.md 2절.

채울 것: 한글 제목 없는 공고 344건(낙찰 공지 94). 그중 291건은 Aimbase 에 이미 완료된 번역이 남아 있어 새로 돌리지 않아도 된다. 새 번역 53건, 한 건씩 약 15분. 번역기는 Claude CLI 구독 연결이라 건당 과금 없음.

| 순번 | 정할 것 | 선택지 |
|------|--------|--------|
| 1 | 고칠 방향 | ①번역은 저장 단위 밖에서 받고, 받은 뒤 공고를 다시 읽어 한글 제목이 비어 있을 때만 짧게 저장한다(권장, 번역 동안 DB 를 잡지 않고 같은 때 들어오는 낙찰 정보를 덮지 않음) ②번역 전체를 한 저장 단위로 묶는다(번역 10~20초 동안 DB 연결을 잡고, 끝날 때 공고 전체를 다시 써 그 사이 들어온 낙찰 정보를 지울 수 있음) |
| 2 | 채우기 방법 | ①Aimbase 기록의 번역 291건과 새 번역 53건을 목록 파일로 만들어 운영 DB 에 한 번에 넣는다. 한글 제목이 빈 행만(권장, 새 번역 53회 약 15분, 목록 docs/기록/CR-139_한글_제목_채우기_목록.tsv) ②344건 모두 관리자 제목 번역 기능으로 한 건씩 새로 번역한다(344회 약 1.5시간) |
| 3 | 번역기 꺼짐 때 재시도 | ①만들지 않는다. 번역기가 꺼져 실패한 건(7월 뒤 22회)은 화면에 원문 제목으로 보이고 관리자 목록의 미번역 일괄 번역으로 채운다(권장) ②다음 수집 때 한글 제목이 빈 공고를 다시 번역한다(수집 코드를 고쳐 CR-136 과 겹침) |

순서: 승인 뒤 고침과 로컬 확인, 운영 배포 승인요청, 채우기 실행 승인요청(새 번역 53회와 운영 DB 쓰기는 그때 실행). 마이그레이션 없음.
