# 결정 메모 - 제안서 작성 개편

> 참가: 클로드 2, GPT 2, 사람 0(모든 라운드 건너뜀) · 라운드 R1~R5 · 2026-11-08 · IR-002
> 작업장: docs/기록/토론_제안서작성개편/

## 정할 것
제안서 작성을 어떻게 다시 짤 것인가. 지금 흐름에서 버릴 것과 살릴 것은 무엇이고, sam-proposal 스킬 7단계를 어느 자리에 어떤 꼴로 넣으며, 어떤 순서로 들일 것인가(계획만 있는 CR-171 ~ 175 포함).

## 합의된 것
### 들이는 순서
1. 기준선을 다시 잰다. CR-189 뒤 같은 건을 한 번에 입력 하나만 바꾼 세 조건으로 돌린다. (1) 같은 다섯 파일과 지금 시험 계정, (2) (1) 에 회사 정보만 채움, (3) (2) 에 서류만 원재료로 바꿈. (근거: A-3, R5 C1 B-8, R5 C2 B-8, R5 G1 B-8, R5 G2 B-8, F-1)
2. 산출물을 바꾸지 않는 제출 검사를 들인다. 검증 실패를 합격으로 치는 동작을 없애고 "검증 못 함(미검증)" 상태를 둔다. 고객 업로드 60, 플랫폼 생성 10, 정부 양식 17 SHALL 줄을 모두 추적해 사실 검증 합격과 제출 가능을 가른다. 다만 모든 줄에 본문이나 첨부가 있어야 낸다고 판정하지 않고, 제안서에서 답하지 않는 줄(사유), 원문과 다른 증빙(동등 여부 확인), 적용이나 해석이 확인되지 않은 줄을 따로 둔다. (근거: A-4, A-5, R5 C1 "같은 것에 대해" A-4, R5 C2 A-4, R5 G1 A-4, R5 G2 A-4, F-2, F-6, F-10)
3. 제출 검사가 생기면 실제 낙찰 제출본에 돌려 줄마다 상태를 가르는 진단 시험을 한다. 낙찰본이 모두 통과하도록 검사를 맞추지 않고, 낙찰했다는 사실을 판정 근거로 쓰지 않는다. (근거: R5 C1 B-8, R5 C2 B-8, R5 G1 B-8, R5 G2 B-8, F-7, F-10)
4. 제출 검사 뒤, CR-171 앞에 다음 셋을 들인다. 결정 조건 전달과 최소 단어 끄기는 회차를 갈라 따로 재고, 각각 기준선과 같은 입력으로 재어 요구 누락이 늘지 않는지 본다. 셋 사이의 앞뒤는 넷이 같게 정하지 않았다(C1 의 R3 는 결정 조건, 최소 단어, 가격 순이고, G1, G2 의 R3 는 가격을 제출 검사 바로 다음에 두었다). (근거: R5 C1 B-1, R5 C2 B-1, R5 G1 B-1, R5 G2 B-1, R3 C1 순서 (3) ~ (5), R3 G1 표 순서 2, R3 G2 표 순서 2)
   - 가격: 공고 가격 항목으로 채운 표, 고객이 넣는 단가, 서버 계산, 파일 내보내기. AI 는 단가를 정하지 않는다. 표가 있는지가 아니라 공고 항목, 금액, 합계가 채워졌는지로 판정한다. (근거: A-6, A-7, F-4)
   - 결정 조건 전달: 입찰 분석의 결정 조건을 확인된 사실이 아니라 고칠 것 목록으로 지금의 절 작성에 넘긴다. 본문은 정정을 마친 사실로 쓰지 않고, 풀리지 않은 조건은 미해결로 남는다. (근거: A-8, R5 C1 B-1, R5 C2 B-1, R5 G1 B-1, R5 G2 B-1)
   - 최소 단어 끄기: 하한을 없애는 것이지 짧게 쓰라는 것이 아니다. 필요한 표, 설명, 약속 문단은 남긴다. 어느 자리에서 끄는지는 갈린 것. (근거: A-10, R5 C1 B-1, R5 C2 B-1, R5 G1 B-1, R5 G2 B-1, F-9, F-10)
5. CR-171 수주 전략을 들인다. Go 결정 화면이나 같은 관리자 작업 화면에서 승인하고, 승인은 조건부 Go 조건의 해소와 수행 약속까지 본다. 작성으로 넘어갈 때 승인된 전략과 Go 조건을 대조한다. 평가 방식은 저장된 공고 사실에서 먼저 찾고(평가 항목 트리가 없어도), 그래도 모르면 Go 화면에 미상을 드러내 관리자가 갈래를 고르거나, 평가 방식 보완을 돌리거나, 미상인 채 간다고 표시해야 전략 승인으로 넘어간다. (근거: A-13, A-14, A-16, F-3, F-8, R5 C1 B-5, R5 C2 B-5, R5 G1 B-5, R5 G2 B-5, R5 C1 B-7, R5 G1 B-7, R5 G2 B-7, R3 C2 (4))
6. CR-172 목차와 모든 절의 기획을 들인다. AI 가 기획을 2~3개씩 나눠 만든다. 증빙, 가격, 양식 자리는 요구 줄별 대응표 같은 짧은 꼴로 기획하고, 대응표에 그 줄을 제안서에서 답하지 않는지와 그 사유, 원문 근거를 둔다. 공고가 요구하는 조직도 같은 도식은 여기서 기획하고 해당 작성에 넣는다. 작성 전에 목차와 기획을 사람이 확인한다. 5 와 6 을 한 회차로 들이나, 확인을 언제 받나, 줄마다 꼴을 무엇으로 가르나는 갈린 것. (근거: A-11, R5 C1 A-11, R5 C2 A-11, R5 G2 B-3, R5 C1 B-2, R5 C2 B-2, R5 G1 B-2, R5 G2 B-2, R5 C1 B-7, R5 C2 B-7, R5 G1 B-7, R5 G2 B-7)
7. CR-173 을 기능마다 나눠 한 회차에 하나씩 들인다. 지정 양식 채우기, 증빙 원본 붙임, 영문 본문이다. 영문은 기획과 같은 회차에 넣지 않는다. 셋 사이의 차례는 C1 만 적었다(지정 양식, 영문 순). 증빙 원본 붙임의 자리는 넷이 같게 적지 않았다. G1, G2 는 CR-172 뒤에 두고, C2 는 R3 에서 가격과 함께 두었다가 R4 에서 "순서 4 에 두어도 다투지 않는다" 고 했으며, C1 은 R4 에서 "증빙 원본 붙임을 가격과 함께 두는 것도 받는다" 고 했고 R5 에 자리를 적지 않았다. (근거: A-12, A-17, R5 C1 B-7, R5 C2 B-7, R5 G1 B-7, R5 G2 B-7, R4 C2 B-1, R4 C2 B-7, R4 C1 B-1, R3 G2 표 순서 4)
8. CR-174 나머지를 들인다. 건의 제출물 전체를 보는 리뷰 한 번과 최종 파일 검사다. 문서 사이 일치를 보고, 자동 전체 재작성은 넣지 않는다. 영문 뒤, 서식과 장 표지 꾸밈 앞에 둔다. LPTA 건도 별도 호출이나 점수표 없이 이 리뷰 안에서 본다. (근거: A-19, A-20, R5 C1 B-7, R5 C2 B-7, R5 G1 B-7, R5 G2 B-7, R5 C1 B-6, R5 C2 B-6, R5 G1 B-6, R5 G2 B-6)
9. 워드 서식과 장 표지 꾸밈을 들인다. 꾸밈 뒤 새로 생기거나 바뀐 글은 사실 검증을 다시 거치고, 바뀐 곳만 문서 사이 일치를 다시 보며, 최종 파일 검사는 실제 마지막 파일에 다시 돌린다. 요약문을 어느 회차에 들이나는 갈린 것. (근거: A-18, A-20, R5 C1 B-7, R5 C2 B-7, R5 G1 B-7, R5 G2 B-7)
10. CR-175 회사소개서, 사전 의향조사 회신, 콜드메일은 맨 끝 별도 영업 흐름으로 두고 제안서 작성의 선행 조건으로 두지 않는다. (근거: A-21, R5 C1 B-7, R5 G1 B-7)

### 버릴 것
- 검증 실패를 합격으로 치는 동작. "검증 못 함(미검증)" 상태로 바꾼다. (근거: A-5, R3 C2 (1))
- 증빙 자리의 고정 최소 단어와 긴 서술 강제. 하한을 없애되 필요한 표, 설명, 약속 문단은 남긴다. (근거: A-10, R5 C1 B-1, R5 C2 B-1, R5 G1 B-1, R5 G2 B-1, F-9)
- 한국어 초안 고정. 영문 본문으로 간다. (근거: A-12)

### 살릴 것
- 공고 분석과 입찰 분석을 스킬 1, 2단계로 그대로 쓰고 다시 만들지 않는다. (근거: A-1)
- 지금의 절 작성과 절 검증. 결정 조건 전달과 최소 단어 끄기는 기획을 기다리지 않고 이 흐름에 넣는다. (근거: R5 C1 B-1, R5 C2 B-1, R5 G1 B-1, R5 G2 B-1)
- 절 사실 검증. 리뷰가 고친 문장, 꾸밈 뒤 새 글도 다시 거치고, 사람의 승인이나 "수행 계획" 이라는 분류로 면하지 않는다. (근거: A-15, R5 C1 B-6, R5 C2 B-6, R5 G1 B-6, R5 G2 B-6, R5 C1 B-7, R5 C2 B-7, R5 G1 B-7, R5 G2 B-7)
- 기존 Go 결정 관문. 전략 승인을 같은 화면이나 같은 관리자 작업 화면에서 다룬다. (근거: A-13, F-3)
- 공고 분석 매트릭스의 요구 줄과 줄마다의 채우는 쪽 값(고객 업로드, 플랫폼 생성, 정부 양식). 제출 검사와 줄 단위 꼴 판단에 쓴다. 꼴의 기본 신호로 쓰나 보조로 쓰나는 갈린 것. (근거: A-4, A-9, R5 C1 B-3, R5 C2 B-3, R5 G1 B-3, R5 G2 B-3)

### 그 밖에 넷이 같은 것
- F-1 ~ F-6 으로 앞 라운드의 사실 다툼을 닫았고(A-2), R5 에서는 넷 모두 F-7, F-8, F-10 을 확인된 근거로 들어 입장을 고쳤다. 실제 낙찰 제출본은 검사의 잣대를 찾는 사례로 쓰고, 줄마다의 정답표나 자동 면제 목록으로 쓰지 않는다. (근거: A-2, R5 C1 B-8, R5 C2 B-3, R5 G1 B-8, R5 G2 B-8, F-7, F-10)
- 작성 꼴은 요구 줄 단위로 정하고 한 절 안에 서술, 증빙, 가격, 양식이 섞일 수 있다. 모든 SHALL 줄을 추적하되 모든 줄에 본문을 만들지 않는다. 제안서에서 답하지 않는 줄은 공고 원문에 기댄 사유를 남기고, 낙찰본에 답이 없었다는 것만으로나 한꺼번에 면제하지 않으며, 적용이 불명확한 줄은 확인되지 않은 것으로 남긴다. (근거: A-9, R5 C1 B-8, R5 C2 B-3, R5 G1 B-3, R5 G2 B-3, F-10)
- 꼴은 채우는 쪽 값만으로도, 요구 동사만으로도 정하지 않는다. 공고 가격 항목과 공고가 지정한 양식이 꼴을 정하는 데 함께 들어간다. (근거: R5 C1 B-3, R5 C2 B-3, R5 G1 B-3, R5 G2 B-3, F-7, F-9, F-10)
- 작성 전 사람 확인 자리는 Go 와 전략, 목차와 절 기획이다. 목차는 반드시 확인받는다. 확인한 대상과 판을 남기고, 바뀌지 않은 것은 다시 확인받지 않으며, 목차를 고치면 그 목차에 기댄 기획만 다시 확인받는다. (근거: R5 C1 B-2, R5 C2 B-2, R5 G1 B-2, R5 G2 B-2, SKILL.md 87줄)
- 승인과 검증 결과는 본문 판만이 아니라 실행이 쓴 입력 묶음(공고 분석, 고객 서류, 회사 근거, Go 조건, 전략, 기획)의 식별자에 묶는다. 입력이 바뀐 결과는 영향을 확인하기 전에는 제출 판정에 쓰지 않는다. 과거 혼선 사고 기록이나 사실 키 안정을 기다리지 않고 들인다. (근거: R5 C1 B-4, R5 C2 B-4, R5 G1 B-4, R5 G2 B-4)
- 원문과 다른 증빙(REQ-089 자리의 건설업 등록증 같은 것)은 동등 여부를 확인할 것으로 두고, 근거를 적어야 풀린다. 낙찰했다는 사실이나 근거 없는 관리자 확인만으로는 충족이 되지 않고, 관리자의 확인은 회사 사실을 만들지 않는다. (근거: R5 C1 B-8, R5 C2 B-8, R5 G1 B-8, R5 G2 B-8, A-15, F-7)
- 평가 방식 보완은 관리자가 고를 때만 돌리고 미상 건마다 자동으로 다시 분석하지 않는다. 미상이나 섞인 문구를 절충형으로 자동 확정하지 않고, 모르는 평가 방식이나 점수, 배점을 만들어 넣지 않는다. (근거: R5 C1 B-5, R5 C2 B-5, R5 G1 B-5, R5 G2 B-5, F-8)
- LPTA 리뷰에서 스킬 리뷰 지침(07)의 7기준 가운데 1 충실도, 5 헤드라인 구조와 가독성(찾기 쉬운가), 6 신뢰성은 보고, 3 전략적 초점과 4 경쟁사 초점은 해당 없음으로 점수와 고칠 순위에서 뺀다. 리뷰 결과는 합격 관문이 아니고, 고친 문장은 사실 검증을 다시 거친다. (근거: R5 C1 B-6, R5 C2 B-6, R5 G1 B-6, R5 G2 B-6, A-15)
- LPTA 와 최고 가치 절충은 전략과 리뷰를 달리 한다. (근거: A-16)
- 요약문, 장 표지, 서식은 공고 작성 지시와 기획이 요구하는 만큼 들인다. (근거: A-18)
- F-5 의 다시 쓰고 다시 검증한 12분 27초는 관측된 재작업 몫이고, 개편으로 그만큼 준다고 약속하지 않는다. (근거: A-22, F-5)
- 장별 분량은 목표로 강제하지 않고 비교 신호로만 본다. (근거: A-23)

## 갈린 것

### 최소 단어 기준을 어느 자리에서 끄나 (B-1)
넷 모두 이 회차를 CR-171 앞에 두는 데는 같아졌다. 끄는 자리가 다르다.

#### 안 1 모든 절에서 하한만 끈다 - 지지: C1
- 핵심 근거: 채우는 쪽 값으로 꼴을 바꾸면 F-10 의 "고객 업로드인데 다른 꼴로 답한 10줄" 이 틀린 꼴로 간다. 그래서 꼴 바꿈(대응표와 붙임)은 이 회차에서 빼고 CR-172 의 줄 단위 기획으로 옮긴다. "하한을 끄는 것은 덜 쓰라는 지시가 아니라 자리를 채우라는 압력을 없애는 것이라 이 10줄을 해치지 않는다." 해치지 않는다는 것은 C1 의 [추정] 이다. (근거: R5 C1 B-1, F-10)
- 버릴 조건: 적지 않음.
- 받은 반박과 답: R3 에서는 이 회차에 "최소 단어를 끄고 대응표와 붙임으로 낸다" 를 두었다(R3 C1 (4)). G2 R4 B-1 이 C2 에 한 반박 "고객 업로드 줄이라는 이유만으로 서술을 축소하는 초기 규칙은 답의 필요한 구성까지 줄일 수 있다" 와 F-10 이 꼴 바꿈을 빼게 했다. G2 R4 의 받아들일 조건 가운데 요구별 적용 범위는 꼴 바꿈을 뺀 것으로 채운다고 적었다. C2 R4 B-1 의 조건 (가)(CR-172 가 절 작성 지시문을 새로 쓰는가)는 CR-172 설계서를 보지 않아 채우지 못한다고 적었다.

#### 안 2 고객, 가격, 양식 줄 자리에서 하한을 끄고 증빙 줄은 위치와 못 다 답한 몫을 쓴다 - 지지: C2
- 핵심 근거: "(2a) 는 하한을 없애는 규칙이지 짧게 쓰라는 상한이 아니다. 증빙 줄의 답은 위치와 함께, 고객 서류로 다 답하지 못한 몫(부족분, 임차 같은 약속, 인원 같은 수행 약속)을 문단으로 쓴다." "하한을 없애는 것은 기획이 없어도 들어간다." 누락이 늘었는지는 F-10 의 줄별 표를 대조표로 같은 입력으로 잰다. 끄는 범위는 R5 에 다시 적지 않았고, R3 의 (2a) 는 "고객이 낼 줄, 가격 줄, 정부 양식 줄이 걸린 자리에서는 최소 단어와 상세 문단 규칙을 끄고" 이다. (근거: R5 C2 B-1, R3 C2 (2a), F-9, F-10)
- 버릴 조건: 범위에 대해서는 적지 않음. 이 회차를 CR-172 뒤로 미루는 조건 둘은 R4 에 적었다(아래 확인하지 못한 사실 1, 2).
- 받은 반박과 답: G1 R4 B-1, G2 R4 B-1 의 반박 "F-9 의 REQ-097 에도 짧은 서술과 약속이 있으니, 고객 업로드라는 까닭만으로 서술을 줄이면 필요한 구성이 빠진다" 를 받아 (2a) 를 하한을 없애는 규칙으로 고치고 증빙 줄에도 약속 문단을 남겼다. 입장은 "그대로" 이고 순서는 늦추지 않았다.

#### 안 3 답의 꼴이 확인된 자리부터 끈다 - 지지: G1, G2
- 핵심 근거: G1 "최소 단어와 상세 문단 강제는 해당 답의 형태를 확인한 범위에서 끄되, 필요한 표·설명·수행 약속·증빙 위치는 보존한다." "고객 업로드라는 값만으로 일괄 축소하지 않는다." G2 "고객 업로드 줄 전체에서 서술을 끄지 않는다. 제출 시 필요한 답의 형태가 확인된 증빙·양식·가격 자리부터 적용하고, 판단이 불명확한 줄은 기존 담당 값만으로 축소하지 않는다." 고객 업로드 줄에도 설명, 약속, 서술, 양식이 있다. (근거: R5 G1 B-1, R5 G2 B-1, F-9, F-10)
- 버릴 조건: 적지 않음.
- 받은 반박과 답: 둘 다 R4 까지는 이 회차를 CR-171, 172 앞에 두지 않았다. C1, C2 R4 B-1 의 논거를 받아 앞으로 옮겼다. G1 은 그 논거를 "경고 전달과 해소 확인은 별개이며, 기획 도입과 효과를 분리할 수 있다" 로 옮겼고, 조건 전달의 효과는 "시험 가설로 둔다" 고 적었다. G2 는 "이를 함께 뒤로 미룬 내 순서는 불필요하게 결합돼 있었다" 고 적었다.

### 절 기획 확인을 언제 받나 (B-2)
#### 안 1 기획이 다 나온 뒤 목차와 함께 한 번 - 지지: C1, C2
- 핵심 근거: 기획은 2~3개씩 나눠 만들되 확인은 다 나온 뒤 목차와 함께 한 화면에서 한 번 받는다. 스킬 지침이 2~3개씩 중간 점검하라고 한 목적은 "균등 깊이 유지" 이고, "깊이가 고른지는 다 된 기획을 한 화면에 놓을 때 더 잘 보인다"(C2, C1 도 같은 줄을 같은 까닭으로 읽음). C2 는 "셋은 자리 수이지 대기 수가 아니다" 라 했다. (근거: R5 C1 B-2, R5 C2 B-2, 05-section-plan.md 49줄)
- 버릴 조건: C1 R4 "또는 관리자가 기획을 실제로 고치는 비율을 재서 높게 나오면 묶음 확인을 받는다." C2 R4 "앞 묶음에서 관리자가 고친 것이 뒤 묶음 기획의 입력으로 들어가게 만든다면 받아들인다." "절이 많아 한 화면 확인이 너무 긴 건이 실제로 있어도 받아들인다." R5 에서 C1 은 "묶음 크기의 우열은 대기와 고친 비율을 재서 정한다는 G1, G2 의 말에는 동의한다", C2 는 "방문 횟수의 우열은 실제 대기를 재서 정한다는 데도 동의한다" 고 적었다.
- 받은 반박과 답: C1 은 R3 의 작성 전 확인 한 자리(Go 와 전략)에서 두 자리로 바꿨다. G2 R3 의 스킬 지침 지적(목차도 반드시 확인받는다)과 C2 R4 B-2 의 반박 "서버 대조는 지정한 사실이 있는지를 볼 뿐, 목차가 요구를 잘못 나눴는지는 보지 않는다" 가 바꿨다. 묶음 확인에는 지켰다. C2 는 G2 R4 B-2 의 반박 셋(스킬의 중간 점검, 모든 건의 자리를 셋으로 정할 근거 부족, 목차를 고친 뒤의 확인)에 답하고 그대로 두었다. G1, G2 는 R5 에서 C2 의 R4 받아들일 조건(앞 묶음에서 고친 것을 뒤 묶음 입력으로)을 채운다고 적었다. C2 의 R5 에는 이에 대한 답이 없다(R5 가 마지막 라운드).

#### 안 2 2~3개 묶음마다 중간 확인 - 지지: G1, G2
- 핵심 근거: 스킬 지침(05)이 기획서를 한 번에 2~3개씩 쓰고 사용자와 중간 점검하라고 한다. 앞 묶음에서 고친 요구 배정, 재료, 표현 방침을 뒤 묶음 기획의 입력으로 넘긴다(G1). 그만큼 잘못된 배정을 모든 절에 되풀이하는 것이 준다는 것은 G1 의 [추정] 이고 재지 않았다. G1 "서버가 재료 칸의 존재를 검사하는 것과 사람이 요구 해석·수행 약속을 확인하는 것은 구분한다." G2 "칸이 채워졌는지 검사하는 것만으로 기획의 내용과 깊이를 확인했다고 볼 수는 없다." 한 작업 화면에서 여러 묶음을 이어 확인하고 "중간 확인을 별도 화면·알림·방문으로 강제하지 않는다"(G2). (근거: R5 G1 B-2, R5 G2 B-2, 05-section-plan.md 49줄, SKILL.md 87줄)
- 버릴 조건: G1 R4 "방문 횟수의 우열은 실제 대기와 작업시간을 측정해 정한다." G2 R4 "묶음 크기와 대기 개선은 실제 작업시간과 재작업을 비교해야 한다." G2 R5 "수정 비율만으로 중간 확인을 없애지도 않는다."
- 받은 반박과 답: C2 R4 B-2 의 반박 "묶음마다 확인하면 이 건의 7절에서 확인 대기가 서너 번 생긴다"(C2 의 [추정])에 G2 는 "묶음마다 확인하면 대기가 늘 수 있다는 지적은 인정한다" 고 하고, 화면과 알림을 합치고 바뀌지 않은 것은 다시 확인받지 않는 것으로 답했다. G1 은 R4 까지 절 기획 확인을 몇 번에 묶을지 정하지 않았다가 R5 에서 묶음 중간 점검으로 정했고, G2 R4 B-2 와 C2 의 받아들일 조건이 그렇게 정하게 했다고 적었다. C1 이 R4 에 G2 쪽으로 건 조건 "(묶음마다 작성이 멈추지 않으면)" 을 G1, G2 가 채우는지는 R5 문장에 없다.

### 요구 줄마다 꼴을 무엇으로 먼저 가르나 (B-3)
#### 안 1 채우는 쪽 값을 기본으로 가격, 양식으로 덮어쓰고 답하지 않음 갈래를 둔다 - 지지: C1, C2
- 핵심 근거: F-10 에서 답이 있는 43줄 가운데 채우는 쪽 값대로 답한 줄이 25줄, 플랫폼 생성인데 가격 엑셀로 답한 가격 줄이 8줄, 고객 업로드인데 지정 양식 칸으로 답한 줄이 8줄이다. "세 신호로 41줄이 맞고, 남는 2줄(REQ-095, REQ-100)은 요구 동사로도 설명되지 않는다."(C1) 같은 동사 submit 이 증빙 줄(REQ-089)과 서술 줄(REQ-096)에 함께 쓰여 요구 동사는 기준에서 뺀다. 꼴은 서술, 증빙, 양식, 가격, 답하지 않음 다섯이고(C2), 이것으로도 갈리지 않는 줄은 절 기획의 줄별 대응표에서 덮어쓰고 관리자가 목차와 기획 확인에서 본다. (근거: R5 C1 B-3, R5 C2 B-3, F-7, F-9, F-10)
- 버릴 조건: 적지 않음. 둘 다 세 신호가 다른 공고에서도 맞는지를 모르는 것으로 적었다.
- 받은 반박과 답: C1 은 R3 의 "요구 동사로 줄마다" 를 거뒀다(R4 에서 F-9 로 거두는 쪽으로 갔고 R5 에서 F-10 으로 거둠). C2 는 R4 의 채우는 쪽 값 하나로 정하는 안을 F-10 으로 거두고, G1 이 함께 보자고 한 신호 가운데 서식과 가격 항목만 받았다. C2 R4 B-3 의 "관리자가 기획 화면에서 줄의 채우는 쪽을 바꿀 수 있게 하는 쪽이 정석" 에 G1, G2 는 R5 에서 담당 자체가 틀린 경우에만 고친다고 답했다. C1 은 대응표에서 관리자가 꼴을 고치는 칸을 이 C2 R4 문장과 같다고 적었다.

#### 안 2 적용 여부와 시점을 먼저 정하고 요구 내용, 지정 서식, 가격 항목으로 꼴을 정한다 - 지지: G1, G2
- 핵심 근거: G2 "먼저 요구의 적용 조건·시점·행위 주체를 판정하고, 그다음 요구 내용·지정 서식·가격 항목으로 답의 형태를 정한다. 담당 값과 동사는 보조 정보로 사용한다." G1 은 동사를 "요구 문장 전체를 해석하는 보조 신호로 한정" 하고, "담당과 출력 형태를 별도로 기록하고, 원문 근거와 수정 이유를 남기는" 안이다. 고객이 재료를 내고 플랫폼이 인원표를 쓰거나 지정 양식에 옮기는 줄(REQ-095 등)이 있어, 누가 재료를 내나와 답의 꼴은 다른 정보라고 본다(G1 의 [추정]). G1 "제출본에 답이 없다는 사실과 분류가 틀렸다는 사실은 다르다." (근거: R5 G1 B-3, R5 G2 B-3, F-10, 자료/F-10_요구줄별_실제답.md REQ-095 줄)
- 버릴 조건: 적지 않음.
- 받은 반박과 답: 둘 다 F-10 으로 바꿨다. G1 은 "채우는 쪽 값만으로 충분하다는 사실 가정은 이 공고에서 유지할 수 없다" 고 하고 C1, C2 R4 의 동사 단독 분류 반박을 받았다. G2 는 C1 R4 의 지적을 받아 "동사만으로 형태를 결정하지 않는다" 고 하되 동사를 버리지 않았다. G2 는 "담당 주체 자체가 잘못 추출됐다면 공고 근거로 바로잡는다" 고 하고, 형태를 맞추려고 담당 값을 바꾸지는 않는다고 했다.

### 입력이 바뀌었을 때 옛 결과를 다시 쓰나 (B-4)
넷 모두 입력 묶음에 묶는 데는 같아졌다. 입력이 바뀐 뒤의 처리가 다르다.

#### 안 1 사실 키 안정이 확인되기 전에는 입력이 바뀐 건을 통째로 다시 검증한다 - 지지: C1, C2
- 핵심 근거: C1 "다시 분석한 사실로 검증한 적이 없는 본문은 지금 사실로는 검증되지 않은 본문이다. 드는 것은 다시 쓰기가 아니라 다시 검증이다." C2 는 조건부 Go 건에서 "작성 뒤에 서류가 바뀌는 것이 예외가 아니라 정해진 길이다" 라 했다(이 건의 결정 조건이 임대차 보완과 Kun San 표기 정정을 요구함). 사실 키가 안정한 것이 확인되면 바뀐 사실에 닿은 절만 다시 보는 쪽으로 좁힌다. C1 은 작성에 들어간 뒤의 공고 다시 분석과 서류 바꿈을 관리자가 고를 때만 하고, 고르기 전에 다시 검증이 돈다는 것을 화면에 알리자고 더했다. C2 는 글 해시 대신 실행 식별자와 서류 묶음 판을 쓰자고 했다. (근거: R5 C1 B-4, R5 C2 B-4, 자료/원자료/bid-analysis.json decision.conditions, 자료/원자료/절/ 의 검증 기록 칸)
- 버릴 조건: 적지 않음.
- 받은 반박과 답: C2 는 R4 의 본문 판에만 묶고 혼선이 보이면 더한다는 안에서 바꿨다. 지금 검증 기록에 무엇을 보고 검증했는지 남는 칸이 없다는 C1 R4 B-4 의 자료와 이 건의 결정 조건이 바꿨다고 적었다. 다시 분석하면 해시가 바뀌어 거의 모든 건이 영향 미확인으로 보류된다는 C2 R4 의 반박에 C1 은 "그대로 일어난다고 보고, 그것이 맞는 동작이라고 본다" 고 답했다. C2 는 C1 R4 의 조건(작성에 들어간 뒤 입력 바꿈을 시스템이 막음)은 결정 조건이 작성 뒤의 서류 정정을 요구해 쓰지 않는다고 했다.

#### 안 2 바뀐 내용을 대조해 영향이 없으면 옛 결과를 그대로 쓴다 - 지지: G1, G2
- 핵심 근거: G1 "다시 분석한 결과가 달라지면 관련성을 비교하고, 영향 없음이 확인되면 기존 결과를 재사용한다. 영향을 가릴 수 없을 때만 그 범위의 제출 가능 판정을 보류한다." G2 "해시 차이는 내용 오류 판정이 아니라 기존 결과의 유효성을 확인해야 한다는 신호로 사용한다." G2 는 안정된 키가 부분 재검증을 줄이는 데는 쓸모가 있지만 입력 보존의 필수 조건은 아니고, 키가 불안정하면 재확인 범위가 커질 수 있으나 "이것은 비용 문제이며 어떤 입력을 검증했는지 모르게 둘 이유는 아니다" 라 했다. (근거: R5 G1 B-4, R5 G2 B-4, SKILL.md 81줄)
- 버릴 조건: 적지 않음. G1 은 "비교 비용과 불필요한 보류 빈도는 아직 모른다" 고 적었다.
- 받은 반박과 답: 위 핵심 근거가 C2 R4 B-4 의 해시 변경, 사실 키 불안정 우려에 대한 답이다. G1 은 재실행 혼선이 실제로 난 적이 확인되지 않았다는 C2 R4 의 지적을 받아 사고가 관측됐다는 주장은 하지 않는다고 했다. 둘 다 입장은 "그대로" 다.

### 섞인 평가 방식 문구를 무엇으로 가르나 (B-5)
#### 안 1 요소별 사실로 정한다 - 지지: C1, C2
- 핵심 근거: 비가격 요소가 합격/불합격이면 합격 점검 갈래, 비교 분석이면 절충형이다. 이 낙찰 공고의 평가방식 사실은 섞인 문구지만 요소별 사실은 "각 소계수 Acceptable/Unacceptable, 하나라도 미달하면 전체 부적격" 이고, F-8 의 섞인 2건(4번, 7번)도 비가격 요소가 합격/불합격이다. 미상인 채 갈 때 C1 은 전략에 어느 평가 방식에도 필요한 것(관문 증빙, 수행 계획, 가격)만 쓰고 차별화와 모의 채점은 쓰지 않는다. C2 는 지금 문서 구성으로 쓰고 점수를 만들지 않으며, 제출 검사 화면에 "평가 방식 미상, 평가 항목 대응은 확인 못 함" 을 남기되 막지 않는다. (근거: R5 C1 B-5, R5 C2 B-5, 자료/원자료/notice-facts.json "평가기준-Factor A Technical", F-8)
- 버릴 조건: 적지 않음.
- 받은 반박과 답: C1 은 R3 의 "평가 방식을 모르거나 공고 문구가 섞이면 절충형 판을 기본으로" 를 거뒀다. C2 R4 B-5 의 요소별 사실로 정하는 조건, G1 R4 B-5 의 "‘더 깊은 전략 검토’와 ‘이 공고의 평가 방식 확정’은 다르다", G2 R4 B-5 의 "분석 불확실성이 사라진 것처럼 보일 수 있다" 가 바꿨다. C2 는 36건 대부분이 갈래 없이 쓰인다는 C1 R4 B-5 의 반박에, 갈래 없이 쓰이는 건은 관리자가 미상인 줄 알고 고른 건뿐이라고 답했다.

#### 안 2 단계, 요소, CLIN, 제출 지시를 함께 대조하고 남은 충돌을 드러낸다 - 지지: G1, G2
- 핵심 근거: G1 "혼합 문구는 ‘최선가치’라는 낱말 하나로 정하지 않고 단계·요소·CLIN별 분석 근거로 처리한다. 해소되지 않은 충돌은 관리자가 고른 갈래와 별개로 남긴다." G2 "요소가 합격/불합격이라는 사실만으로 공고 전체의 모든 평가 관계가 확정됐다고 단정하지 않는다." F-8 에 2단계 평가(1번), CLIN 별 평가(8번)가 있다. 미상인 채 갈 때 확인된 요구에 대한 전략과 초안은 진행하고, "더 넓은 전략 검토를 하더라도 ‘미상 상태의 내부 가설’로 표시하고, 절충형이라는 공고 분류나 모의 점수로 바꾸지 않는다"(G1). (근거: R5 G1 B-5, R5 G2 B-5, F-8)
- 버릴 조건: 적지 않음.
- 받은 반박과 답: G1 은 미상 36건을 모두 자동으로 다시 분석한다는 C2 R4 B-5 의 반박은 자기 방식이 아니라고 답했고, 전략까지 유보하면 안 된다는 C1 R4 B-5 의 지적을 받았다. G2 는 C1 R4 B-5 의 설명과 C2 R4 B-5 의 조건을 받았다. 둘 다 입장은 "그대로" 다.

### LPTA 리뷰에 스킬 리뷰 지침의 2 반응도와 7 표현 품질을 넣나 (B-6)
#### 안 1 2 반응도를 뺀다 - 지지: C1, G1, G2
- 핵심 근거: REQ-097 의 최소 장비는 명시 요구라 1 충실도와 소계수 합격 점검이 보는 것이고, 2 는 "명시 요구를 넘어" 를 보는 기준이다(C1). 07 이 개선 우선순위를 내는 단계라 2, 3, 4 가 돌면 서류 밖 주장이 우선순위에 오른다(C1 이 C2 R4 의 근거를 받음). G2 "‘내부 진단’이라고 이름 붙여도 차별화·경쟁사 공격·숨은 이슈가 개선 우선순위를 차지하면 불필요한 주장을 늘릴 수 있다." 7 표현 품질은 셋이 다르게 적었다. C1 은 "읽기를 막는 것(시각적 소음, 어투)만 본다", G1 은 "7 표현 품질의 별도 카피라이팅 확장도 두지 않는다", G2 는 "7 표현 품질은 별도 점수표를 만들지 않는다". (근거: R5 C1 B-6, R5 G1 B-6, R5 G2 B-6, 07-review.md 3줄, 32줄)
- 버릴 조건: 적지 않음. G2 가 R4 에 적은 조건(별도 7기준 리뷰가 중복 비용만 늘린다는 비교 결과)은 재지 않은 채 R5 에서 바꿨다고 G2 스스로 적었다("그 효과나 비용 우위가 실측된 것은 아니지만").
- 받은 반박과 답: C1 은 R4 에서 2 를 넣었다가 C2 R4 B-6 으로 뺐다("내가 R4 에서 2 를 넣은 근거는 틀렸다"). G1 은 C2 R4 B-6 의 개선 우선순위 문제와 C1 의 역할 중복 지적을 받아, R4 의 7기준 내부 진단 유지에서 바꿨다. G2 도 C1, C2 R4 B-6 의 반박을 받아 바꿨다.

#### 안 2 2 반응도와 7 표현 품질을 넣는다 - 지지: C2
- 핵심 근거: F-9 의 REQ-097 답(보유가 요구보다 적음을 밝히고 임차로 채우겠다는 약속)이 2 반응도가 보는 꼴이다. 점수에 들지 않는 우선순위가 서술을 늘린다는 걱정은 점수를 내지 않고, 해당 없음을 표시하고, 고친 문장을 다시 검증하는 셋으로 막는다. 7 은 문장을 더하는 쪽이 아니라 다듬는 쪽이라 남긴다(C2 의 [추정]). 3, 4 는 해당 없음이다. (근거: R5 C2 B-6, F-9, 07-review.md 32줄, 37줄)
- 버릴 조건: 적지 않음. C2 가 R4 에 적은 받아들일 조건 "LPTA 에 07 을 돌리되 1(충실도), 5(헤드라인 구조·가독성), 6(신뢰성)만 쓰고, 2, 3, 4 는 점수와 개선 우선순위에서 빼면 받아들인다." 는 G1, G2 의 R5 안과 같다.
- 받은 반박과 답: C2 는 R4 에서 2 를 뺐다가 C1 R4 B-6 이 든 F-9 의 REQ-097 답으로 넣었다("내 R4 조건(1, 5, 6)에서 2 를 뺀 것은 이 답을 놓친 것이다"). C1 과 C2 는 2 에 대해 서로의 R4 근거로 자리를 맞바꿨다.

### CR-171 전략과 CR-172 기획을 한 회차로 들이나 (B-7)
#### 안 1 따로 들인다 - 지지: C1, G1, G2
- 핵심 근거: C2 R4 의 "갈라서 얻는 것은 운영 쪽이다". 전략 회차에서는 전략 승인, Go 조건 일치, 작성으로 넘어가기를 확인하고, 기획 회차에서 승인된 전략을 고정해 기획과 본문 연결을 확인한다(G1). 본문 효과는 기획 뒤에 한 번 잰다(C1). G1 "두 기능을 나눈다고 전략만의 본문 개선 효과까지 측정됐다고 주장하지는 않는다." (근거: R5 C1 B-7, R5 G1 B-7, R5 G2 B-7, R4 C2 B-7)
- 버릴 조건: 적지 않음.
- 받은 반박과 답: G1, G2 는 R3 에서 전략과 기획을 한 묶음(순서 3)에 두었다가 C2 R4 B-7 의 운영상 분리 이유를 받아 바꿨다. C1 은 R3 부터 따로 두었고, R5 에서 영문을 기획에서 뗐다(C2, G1, G2 R4 B-7). C2 의 조건 "전략은 기획을 거쳐서만 본문에 닿는다" 를 C1 은 받는다고 했고, G1 은 "작성은 승인된 기획과 전략을 함께 참조한다" 며 받지 않았다. G2 는 이 점을 R5 에 적지 않았다.

#### 안 2 한 묶음으로 들인다 - 지지: C2
- 핵심 근거: "전략은 절 작성에 바로 넣지 않고, 기획을 거쳐서만 본문에 닿는다." R3 (4) 설계의 전략은 Go 화면 승인과 작성으로 넘어갈 때의 대조이고 절 작성의 입력이 아니다. C1 R4 B-7 의 "전략만 들인 회차는 본문에서 잴 것이 없어 한 회차로 재도 잃는 것이 없다" 도 같은 계산이다. 기획 지침의 입력에 수주 전략서가 있다. (근거: R5 C2 B-7, R4 C1 B-7, 05-section-plan.md 4줄)
- 버릴 조건: R4 에 한 묶음을 받는 조건으로 "한 번에 바꾸는 흐름 정의가 CR-189 만큼(넷, 다시 연결 한 번) 안이다" 를 적었다. R5 에서 "흐름 정의 수에 건 조건은 지킬 수 있다고 본다" 고 했고, 그 까닭(CR-189 가 흐름 넷을 한 번에 바꿈)은 C2 의 [추정] 이다.
- 받은 반박과 답: C2 는 R3 에서 (4) 전략, (5) 기획으로 따로 두었다가 R5 에서 한 묶음으로 바꿨다. 자기 R4 조건이 R3 (4) 설계에서 이미 성립한다는 것과 C1 R4 B-7 의 계산이 바꿨다고 적었다. G2 는 "CR-189에서 흐름 넷을 바꿨다는 사례를 모든 변경의 안전한 상한으로 일반화하지 않는다" 고 했다. G1 은 C1, C2 의 묶음 도입 조건을 채택하지 않는다고 했다. C1, G1, G2 는 C2 R4 의 근거로 따로 들이는 쪽에 섰고, C2 는 C1 R4 의 근거로 한 묶음 쪽에 섰다.

### 요약문과 장 표지 문구를 어느 회차에 들이나 (B-7)
넷 모두 서식과 장 표지 꾸밈은 리뷰 뒤에 두고, 뒤에 생긴 글은 다시 검사한다. 요약문의 자리가 다르다.

#### 안 1 주장을 담는 글로 리뷰 앞에 따로 들인다 - 지지: C1
- 핵심 근거: "주장을 담는 글은 리뷰 앞에, 보이는 꼴만 바꾸는 것은 리뷰 뒤에 둔다." 차례는 영문 다음에 "요약문과 장 표지 문구처럼 주장을 담는 글", 그다음 리뷰와 최종 파일 검사, 그다음 워드 서식과 장 표지 꾸밈이다. 꾸밈을 둘로 가른 까닭은 R4 에서 서로 반박한 자리가 요약문 하나였기 때문이다. (근거: R5 C1 B-7)
- 버릴 조건: 적지 않음.
- 받은 반박과 답: R3 에서는 요약문, 장 표지, 워드 서식을 리뷰 앞 한 회차에 두었다(R3 C1 (8)). G1, G2 의 조건 "선택적 표현 고도화보다 전체 리뷰·최종 파일 검사를 먼저 사용할 수 있다" 를 받아 보이는 꼴만 바꾸는 것을 리뷰 뒤로 옮겼다.

#### 안 2 공고가 요구한 요약문은 기획과 작성 안에, 나머지는 리뷰 뒤 선택 꾸밈으로 - 지지: C2, G1
- 핵심 근거: C2 "공고가 요구하는 도식(조직도)과 공고가 요구하는 요약문은 기획과 작성 안에 둔다." 선택 꾸밈(서식, 장 표지, 공고가 요구하지 않은 요약문)은 리뷰 뒤에 둔다. G1 "요약문이 필요한 건에서는 작성 과정에 포함하고 최종 리뷰 대상에 넣는다." (근거: R5 C2 B-7, R5 G1 B-7, 06-writing.md)
- 버릴 조건: 적지 않음.
- 받은 반박과 답: C2 는 R4 에서 요약문이 리뷰 뒤에 들어온다고 반박했으나 G2 R4 B-7 의 "요구에 직접 답하는 도식과 선택적인 꾸밈을 분리하면, 필수 작성 완료와 전체 리뷰를 표현 고도화보다 앞에 둘 수 있다" 를 받아 리뷰를 선택 꾸밈 앞에 두었다. G1 은 요약문이 리뷰 뒤에 들어간다는 C1, C2 의 반박을 받아 기능을 들이는 차례와 한 건이 도는 차례를 가르겠다고 했다.

#### 안 3 요약은 리뷰 뒤 선택적 표현으로 두고 새 문장을 다시 검사한다 - 지지: G2
- 핵심 근거: "전체 리뷰 기능은 선택적 표현 기능보다 먼저 갖추되, 요약문·표지 문구·서식이 추가된 최종 결과를 반드시 다시 검사한다." "내 순서는 기능을 언제 갖추는가에 관한 것이며, 먼저 얻은 리뷰 결과를 뒤의 모든 수정에도 계속 유효하게 쓰는 순서가 아니다." 공고가 요구한 요약문을 작성 안에 두는지는 R5 에 적지 않았다. (근거: R5 G2 B-7, R3 G2 표 순서 6)
- 버릴 조건: 적지 않음.
- 받은 반박과 답: 리뷰 뒤에 생긴 요약문이 빠진다는 C1, C2 의 반박을 재검사 규칙으로 푼다고 답했다.
