# R3 - C2

## 안
바꿈. 전에는 안 D "기준선 먼저, 뼈대는 살리고 저장되는 산출물로 하나씩 끼운다", 지금은 같은 뼈대에 들이는 순서와 사람 확인 자리를 고친 안 D2 "기준선, 서버 제출 검사, 하나씩 바꿔 재기".

뼈대(문서 구성, 목차 설계, 절 작성, 절 검증, 서버 묶기)와 공고 분석, 입찰 분석은 그대로 둔다. 들이는 순서는 이렇다. 한 단계에 AI 산출물을 바꾸는 것은 하나만 넣고, 넣을 때마다 같은 건으로 다시 잰다.
- (0) 기준선 두 번. 같은 다섯 파일로 CR-189 효과를 한 번, 원재료 서류로 한 번 잰다. 절마다 시작과 끝 시각, 시도 횟수를 남긴다.
- (1) 서버 제출 검사(AI 호출 없음). 공고 분석의 SHALL 87줄과 필수 서류 17개를 채우는 쪽(고객, 플랫폼, 정부 양식)별로 상태를 보인다. 검증이 미충족으로 남긴 줄, 빈 가격 표, 검증 못 함(PASS 폴백을 버린 자리)이 하나라도 있으면 "제출 불가" 로 표시하고 제출 쪽 전이를 막는다. 관리자 검토로 가는 것은 막지 않는다. 산출물을 바꾸지 않는 검사라 맨 앞에 두어도 측정을 흐리지 않는다.
- (2) 작성 규칙과 입력을 하나씩 바꾼다. (2a) 고객이 낼 줄, 가격 줄, 정부 양식 줄이 걸린 자리에서는 최소 단어와 상세 문단 규칙을 끄고, 증빙은 위치(파일, 쪽)와 짧은 설명으로 쓴다. 꼴은 절 하나에 하나가 아니라 요구 줄의 채우는 쪽 값으로 정해 한 절 안에 섞인다. (2b) 입찰 분석의 결정 조건을 "고칠 것 목록" 으로 절 작성 입력에 넘긴다.
- (3) 가격 엑셀 내보내기(CR-189 가격 항목 66줄, 합계와 인상률 칸은 서버 계산)와 증빙 원본 붙임. AI 를 부르지 않아 (2)와 나란히 들여도 된다.
- (4) 수주 전략(CR-171). 입찰 분석 흐름 끝 단계로 만들어 Go 화면에서 같이 승인한다. 전략은 바탕으로 삼은 조건을 함께 저장하고, 관리자가 확정한 Go 조건과 다르면 작성으로 넘어가는 전이에서 막고 전략을 다시 낸다.
- (5) 목차와 절 기획서(CR-172). 승인된 전략을 입력으로 받고, 기획 항목마다 근거 사실을 지정한다. 서버는 지정한 사실이 있는지만 대조하고, 그 사실이 문장을 뒷받침하는지는 지금처럼 절 검증이 본다. 목차와 기획은 한 화면에서 한 번 관리자 확인을 받은 뒤 작성한다. 기획은 목차 저장 뒤 절 몇 개씩 따로 부른다.
- (6) 따로따로 셋. (6a) 제출 언어를 정하고 영문 본문으로 바꾼다 (6b) 서식, 도식, 장 표지, 요약문은 공고 작성 지시와 기획이 요구할 때 (6c) 건의 제출물 전체를 보는 AI 리뷰 한 번(CR-174 나머지). 문서 사이 숫자 대조는 서버가 먼저 한다. 자동 재작성은 넣지 않는다. 관리자가 절을 고치면 (1) 검사가 다시 돌고 AI 리뷰 결과는 "낡음" 으로 표시된다.
- (7) CR-175 는 공고 전 영업용 별도 입구로 맨 뒤에 둔다.

버릴 것은 그대로다. 고정 최소 단어 수, 검증 실패를 합격으로 치는 동작, 한국어 초안 고정. 사람이 서는 자리는 지금 둘(Go, 마지막 검토)에서 셋(Go와 전략, 목차와 기획, 마지막 검토)이 된다.

## 받은 반박에 대한 답

C1 C2-10: 받아들인다. 관문 점검 몫을 CR-174 에서 떼어 (1)로 올렸다. 서버 검사라 AI 리뷰를 기다릴 이유가 없다(바꾼 것 1, 7).

## 여전히 모르는 것
- CR-189 뒤 같은 건에서 가격 항목 66줄, 정부 양식, 불합격 절이 실제로 어떻게 나오는지.
- 원재료 서류를 따로 구할 수 있는지, 아니면 장 파일에서 증빙 쪽만 떼어 만들어야 하는지.
- 실제 낙찰 때 업종 등록(REQ-089)을 무엇으로 충족했는지(F-6 이 보지 못한 것). 낙찰본에 (1) 서버 검사를 돌렸을 때 이 줄이 미충족으로 나오면 검사나 검증이 틀린 것이다. 서버 검사의 잣대를 맞출 첫 시험이 여기에 달렸다.
- (1)의 "제출 불가" 를 상태 전이의 어느 자리에 걸지. 검토 대기 뒤의 전이를 보지 않았다.
- 절 작성이 앞 절의 결과를 읽는지, Aimbase 가 절 작성을 동시에 몇 개까지 돌릴 수 있는지. F-5 로 지금은 한 줄로 돈다. 동시에 돌릴 수 있으면 불합격을 줄이는 것보다 큰 시간 감소가 이쪽에 있을 수 있다.
- 절 하나 안에서 작성과 검증이 각각 몇 초인지(F-5 가 보지 못한 것).
- 공고 사실과 고객 서류 사실의 키가 다시 분석해도 같은 값으로 남는지. 기획의 근거 지정 대조가 여기에 달렸다.
- 기획을 절 몇 개씩 낼 때 호출당 시간과, 목차와 기획 확인 화면에서 관리자가 기다리는 시간.
- 관리자가 AI 와 다른 조건으로 Go 하는 비율. 전략을 다시 내는 일이 얼마나 생기는지가 여기에 달렸다.
- 관리자가 영어 본문을 검토할 수 있는지.
- 지금 PDF 내보내기가 고객 서류 원본을 붙일 수 있는지.
- 입찰 분석 건 가운데 No-Go 비율.
