# R1 - C2 (구현과 운영)

## 안
새 안 D "기준선 먼저, 뼈대는 살리고 저장되는 산출물로 하나씩 끼운다".
지금 뼈대(문서 구성, 목차 설계, 절 작성, 절 검증, 서버 묶기)와 이미 운영 중인 공고 분석, 입찰 분석(스킬 1, 2, 11)은 그대로 둔다. 스킬 3 ~ 7단계는 단계마다 DB 에 저장되는 산출물과 서버 대조를 붙여 사이사이에 끼운다.
들이는 순서: (0) CR-189 같은 건 재시험으로 기준선 (1) 절 기획서(05, 항목마다 근거 사실 지정)와 절의 작성 꼴(서술, 증빙, 가격, 양식). 꼴은 흐름을 따로 만들지 않고 절 속성과 지시문 갈래로 두고, 증빙 붙임과 가격 엑셀 내보내기를 함께 만든다(CR-172 확장) (2) 수주 전략(03)을 입찰 분석 흐름 끝 단계로 붙여 관리자가 Go 결정과 같은 화면에서 승인(CR-171) (3) 묶은 뒤 문서 전체 리뷰 1회, 자동 재작성 없음(CR-174) (4) 제출 언어를 정한 뒤 서식, 도식, 장 표지, 요약문(CR-173).
CR-175 는 공고 전 영업 트랙이라 이 개편에서 뗀다. 버릴 것은 고정 최소 단어 수, 검증 실패를 합격으로 치는 동작, 한국어 초안 고정이다.

## 이 안을 버릴 조건
- CR-189 재시험에서 같은 건의 불합격 절과 근거 없는 문장이 모두 0 이면 기획서를 맨 앞에 둘 이유(C2-3, C2-4)가 약해진다. 그때는 작성 꼴과 내보내기(C2-6, C2-7)를 첫 자리로 올린다.
- 공고 사실과 고객 서류 사실에 기획서가 가리킬 안정된 키가 없어 서버가 근거 지정을 대조할 수 없으면 C2-3 의 핵심이 무너진다. 그때는 근거 대조를 검증 단계에만 두는 쪽으로 물러난다.
- 스킬 4 ~ 6단계를 한 에이전트 호출 안에서 파일로 이어 가는 꼴(안 B 쪽)이 같은 건에서 시간과 불합격 수 둘 다 낫다는 결과가 나오면 이 안을 버린다.
- 관리자가 AI 판정과 다른 조건으로 Go 하는 일이 잦거나 No-Go 가 대부분이면 전략을 입찰 분석 끝에 두는 C2-8 을 버리고 Go 뒤 별도 관문으로 옮긴다.
- 최고 가치 절충 낙찰 건을 구해 돌렸을 때 전략 유무가 결과를 크게 가르면 전략(CR-171)을 순서 맨 앞으로 당긴다.
