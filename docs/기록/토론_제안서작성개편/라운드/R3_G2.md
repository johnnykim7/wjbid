# R3 - G2

## 안

**바꿈. 전에는 ‘공통 7단계와 산출물 종류별 실행’, 지금은 그 구조를 유지하면서 가격 기능을 먼저 분리 도입하고, 승인·재실행 범위를 명시한 수정안이다.**

기존 공고 분석·입찰 분석·장절블록·절별 검증은 재사용한다. 전략 → 목차 → 절 기획 → 종류별 작성 → 전체 리뷰의 연결도 유지한다. 한 절에 서술·증빙·가격·양식을 함께 담을 수 있게 한다.

달라지는 것은 도입 묶음과 운영 범위다. 가격 항목·입력·계산·내보내기를 전략·영문·다른 파일 출력과 분리해 앞당긴다. 평가 트리 부재만으로 공고 분석 전체를 다시 돌리지 않는다. 커버리지는 서버를 판정의 기준으로 삼고, 원본 스크립트 실행용 어댑터를 기본 구현에서 뺀다.

   다만 28분 16초 전체를 재작업이나 절약 가능 시간으로 읽지 않는다. 최초 작성·검증에도 15분 49초가 들었다. 12분 27초 역시 관측된 재작업 비용이며, 새 기획·검사로 전부 없어질 것이라는 보장은 없다.

   근거: [확인] F-5.  
   근거: [추정] 추가 기획·검사 비용과 실제로 줄어든 재시도 비용을 함께 재야 순효과를 판단할 수 있다.

## 받은 반박에 대한 답

**C1의 G2-3 반박 및 ‘가장 약한 곳’ 지적:** 목차를 보이기만 하고 확인을 생략하자는 제안은 받아들이지 않는다. 승인이 회사 사실의 증거가 아니라는 것과, 승인된 결정·목차를 후속 작업의 전제로 삼는 것은 별개다. 사람은 증거를 만들어 주는 대신 적용 범위·제출 구성·수행 약속을 검토한다. 서버의 참조 존재 검사만으로 이 결정을 대신할 수는 없다.

근거: [자료] `docs/skills/sam-proposal/SKILL.md`, 87줄: “특히 Go/No-Go(2), Winning Theme(3), 목차(4)는 이후 모든 작업의 전제이므로 반드시 확인받는다.”  
근거: [추정] C1이 인용한 문장에도 목차가 포함돼 있으므로 Go와 전략만으로 충분하다는 결론은 그 인용에서 나오지 않는다. 확인 횟수가 정확성을 보장한다는 주장도 하지 않는다.

**C2의 G2-3 반박 및 ‘가장 약한 곳’ 지적:** 사람 대기가 늘 수 있다는 지적은 인정한다. 같은 화면을 쓴다고 확인 대기가 없어지는 것도 아니다. 다만 아직 고치는 비율을 모른다는 이유로 목차·기획 확인을 마지막 검토로 미루지는 않는다. 다음 방식으로 확인 부담을 제한한다.

- 기존 분석 결과와 Go 결정은 유효한 입력이 유지되면 재사용한다.
- Go·전략·목차·기획은 같은 관리자 작업 화면에서 이어 보되, 서로 다른 확인 대상을 명시한다.
- 절 기획은 스킬이 정한 묶음 단위로 확인한다. 절마다 새 화면을 열도록 만들지 않는다.
- 바뀌지 않은 산출물은 다시 승인받지 않고, 변경된 내용과 영향을 받는 범위만 재확인한다.

최소 구현은 **실행이 실제로 사용한 입력 묶음의 식별자와 내용 해시 또는 보존 사본**, 산출물 버전, 승인 대상, 검증 대상을 연결하는 것이다. 전략·기획은 해당 기능을 만들 때부터 이 연결을 붙인다. 중복·지연 결과는 이력으로 남길 수 있지만 현재 산출물과 입력이 맞지 않으면 최신 승인·검증으로 사용하지 않는다.

|---|---|
