# R5 - G1

## 마지막 입장

### B-1

입장: **바꿈.** 기준선과 제출 검사 다음에 결정 조건 전달과 증빙형 서술 축소를 별도 회차로 들이고, CR-171·172보다 먼저 시험한다. 증빙 원본 붙임은 작성 규칙 변경과 분리한다.

바꾼 까닭 또는 받은 반박에 대한 답: **C1·C2의 R4 B-1**에서 지적한 ‘경고 전달과 해소 확인은 별개이며, 기획 도입과 효과를 분리할 수 있다’는 논거를 받는다. 기존 경고를 전달하는 것까지 정식 전략·기획 연결을 기다릴 필요는 없다. 다만 전달했다면 기존 실패가 반드시 없어졌을 것이라는 인과관계는 확인되지 않았으므로 시험 가설로 둔다.  
근거: [자료] `docs/기록/토론_제안서작성개편/라운드/R4_공개.md`, C2 B-1이 인용한 `bid-analysis.json`의 `decision.conditions` “공룡중기 장비 임대차를 계약 시작일과 인수 기간까지 포함하도록 보완하고 Kun San 표기·임차인 상호 오기를 정정할 것”.  
근거: [추정] 이미 있는 결함 정보를 작성 입력에 추가하는 변경과 전략·기획 추가를 따로 비교하면 각 변경의 영향을 구분하기 쉽다.

앞당기는 안에는 **내 R4와 G2 R4 B-1의 수용 조건**을 붙인다. 결정 조건은 요구·근거와 연결된 ‘고칠 것’으로 전달하고, 정정 완료는 새 증거가 있을 때만 기록한다. 최소 단어와 상세 문단 강제는 해당 답의 형태를 확인한 범위에서 끄되, 필요한 표·설명·수행 약속·증빙 위치는 보존한다. 이 연결은 이후 절 기획에서도 재사용한다. 고객 업로드라는 값만으로 일괄 축소하지 않는다.  
근거: [확인] F-9, F-10. 고객 업로드 줄에도 설명·약속·서술·양식이 있다.  
근거: [추정] 동일 입력 비교에서 요구 누락이 늘지 않는 것을 정식 적용의 조건으로 삼는다. 이 조건이 이미 충족됐다는 주장은 하지 않는다.

### B-2

입장: **바꿈—미정이던 절 기획 확인 방식을 확정한다.** Go·전략·목차의 확인 대상을 구분하고, 확정된 목차에 따라 절 기획을 2~3개씩 작성·중간 점검한다. 같은 관리자 화면을 쓰고 유효한 확인은 재사용하되, 방문·대기 횟수를 고정하지 않는다.

바꾼 까닭 또는 받은 반박에 대한 답: **G2의 R4 B-2와 C2의 수용 조건**을 받아, 앞 묶음에서 고친 요구 배정·재료·표현 방침을 뒤 묶음 기획의 입력으로 전달한다. 이미 만든 부분이 영향을 받으면 그 부분만 다시 확인한다. 중간 점검이 단순한 승인 클릭에 그치지 않게 하는 보완이다.  
근거: [자료] `docs/skills/sam-proposal/references/05-section-plan.md`, 실행 규칙 “**한 번에 섹션 기획서 2~3개씩** 작성하고 사용자와 중간 점검 (균등 깊이 유지)”.  
근거: [추정] 수정 사항을 후속 기획에 반영하면 잘못된 요구 배정이나 재료 선택을 모든 절에 반복하는 것을 줄일 수 있다. 실제 감소량은 미측정이다.

**C1·C2의 ‘생성은 묶음별, 확인은 모두 나온 뒤 한 번’**은 기본 방식으로 채택하지 않는다. 서버가 재료 칸의 존재를 검사하는 것과 사람이 요구 해석·수행 약속을 확인하는 것은 구분한다. 대신 화면과 알림은 합치고, 바뀌지 않은 내용을 다시 승인받지 않는 조건을 채운다. C1이 바로잡은 목차 필수 확인도 반영한다.  
근거: [자료] `docs/skills/sam-proposal/SKILL.md`, 실행 원칙 “특히 Go/No-Go(2), Winning Theme(3), 목차(4)는 이후 모든 작업의 전제이므로 반드시 확인받는다.”  
근거: [추정] 확인 대상과 의존 순서를 보존하면서 화면을 합치는 것은 가능하지만, 그것이 실제 대기를 한 번으로 만든다는 보장은 아니다.

### B-3

입장: **바꿈.** 채우는 쪽 값은 담당 구분으로 재사용하되, 먼저 요구의 주체·조건·적용 시점과 제안서 답변 필요성을 확인한다. 답변이 필요한 줄은 요구 내용·목적어·지정 서식·가격 항목·증빙에 따라 형태를 정하고, 동사만으로 분류하지 않는다.

바꾼 까닭 또는 받은 반박에 대한 답: **F-10이 판단을 바꿨다.** 고객 업로드인데 양식으로 답한 8줄과 서술로 답한 2줄이 확인됐다. 따라서 채우는 쪽 값만으로 충분하다는 사실 가정은 이 공고에서 유지할 수 없다. 동시에 REQ-095·100은 동사만으로도 설명되지 않으므로, **C1·C2 R4 B-3의 동사 단독 분류 반박**을 받는다. 내 이전 ‘요구 동사도 본다’는 말은 요구 문장 전체를 해석하는 보조 신호로 한정한다.  
근거: [확인] F-10.

**C2의 ‘잘못된 값이면 고친다’는 조건**은 담당 자체가 틀린 경우에 받는다. 그러나 고객이 재료를 제공하면서 플랫폼이 인원표를 작성하거나 지정 양식에 옮기는 경우까지 담당 값을 바꿔 답의 형태를 표현할 필요는 없다. 담당과 출력 형태를 별도로 기록하고, 원문 근거와 수정 이유를 남기는 안으로 보완한다.  
근거: [추정] F-10의 고객 업로드→서술·양식 사례에서, 재료 제공 책임과 제출물 작성 형태가 서로 다른 정보라고 판단했다.

답 없음 51줄은 일괄 면제하지 않는다. 원문을 확인해 제출 전 답변, 제출 행위, 계약 후 이행, 정부 평가 절차, 조건부 적용을 구분한다. 적용 여부가 불명확하면 검토 대상으로 남긴다. 또한 25/94를 분류 정확도로 쓰지 않는다. 제출본에 답이 없다는 사실과 분류가 틀렸다는 사실은 다르다. 이는 **G2 R4 B-3의 원문 요구와 실제 제출 내용을 따로 기록하자는 조건**도 충족한다.  
근거: [확인] F-10은 51줄 각각의 답변 불필요 여부까지 확인하지 않았다.

### B-4

입장: **그대로.** 실행에 실제 사용한 공고 분석·회사 근거·Go 조건·전략·기획·본문을 승인·검증 대상과 연결한다. 최소 구현은 입력 묶음의 식별자와 보존 사본 또는 해시이며, 저장소 전체의 별도 버전 관리 체계를 선행시키지 않는다.

바꾼 까닭 또는 받은 반박에 대한 답: **C2 R4 B-4의 ‘혼선이 실제 발생한 적은 미확인’이라는 지적**을 받는다. 사고가 관측됐다는 주장은 하지 않는다. 다만 본문이 같아도 근거가 달라질 수 있으므로, 본문 버전만으로 검증의 유효성을 판단하는 축소에는 계속 반대한다. 이는 사고 이력에 관한 주장이 아니라 새 승인·검증 기능의 입력 식별 조건이다.  
근거: [자료] `docs/skills/sam-proposal/SKILL.md`, 실행 원칙 “**순차 의존성**: 앞 단계 산출물이 뒷 단계 입력이다.”  
근거: [추정] 검증이 본 회사 자료와 현재 적용하려는 회사 자료가 다르면, 본문이 동일해도 이전 결과를 그대로 쓸 수 있는지 확인해야 한다.

**C2의 해시 변경·사실 키 불안정 우려**에는 다음과 같이 답한다. 해시는 내용 변경을 감지할 뿐 의미 변경을 확정하지 않는다. 다시 분석한 결과가 달라지면 관련성을 비교하고, 영향 없음이 확인되면 기존 결과를 재사용한다. 영향을 가릴 수 없을 때만 그 범위의 제출 가능 판정을 보류한다. 안정된 사실 키는 세밀한 영향 분석에 유리하지만, 사용한 입력을 보존하는 것의 선행 조건은 아니다.  
근거: [추정] 입력 식별과 의미상 변경 판정은 서로 다른 작업이다. 비교 비용과 불필요한 보류 빈도는 아직 모른다.

**C1·G2의 최소 구현 조건**을 받는다. 본문 버전에서 실제 입력 묶음 전체를 불변 참조할 수 있다면 개별 칸을 여섯 개 만들 필요는 없다. 늦게 도착한 작성 결과는 실행 식별자로, 검증 결과는 실행·대상 버전으로 확인한다. 사실 키가 같다는 이유만으로 내용까지 같다고 간주하지는 않는다.  
근거: [추정] 같은 연결 책임을 충족하는 구현 중 범위가 작은 방법을 택한다.

### B-5

입장: **그대로.** 저장된 공고 분석의 평가 방식과 요소별 지시를 먼저 쓰고, 부족한 항목만 보완한다. 미상·상충은 그대로 표시하며, 확인된 요구에 대한 전략·초안은 진행하되 확인하지 않은 평가 방식이나 점수를 만들어 넣지 않는다.

바꾼 까닭 또는 받은 반박에 대한 답: **C2 R4 B-5의 ‘미상 36건 전체 자동 재분석’ 반박**은 내가 정한 방식이 아니다. 저장값 확인 후 필요한 보완 항목을 표시하고, 원문 보완 분석은 관리자가 선택해 실행할 수 있게 한다. 보완하지 않은 항목은 미상으로 남으며, 관리자 선택이 공고 사실을 대신하지 않는다.  
근거: [확인] F-8. 트리가 없는 44건 중 8건에는 저장된 평가 방식이 있고, 나머지 36건의 원문은 확인되지 않았다.  
근거: [추정] 전체 재분석을 강제하지 않으면서도 미해결 항목을 숨기지 않는 방식이다.

**C1 R4 B-5의 ‘전략까지 유보하면 안 된다’는 지적**을 받는다. 확인된 요구·자원·증거에 따른 전략은 계속 작성한다. 더 넓은 전략 검토를 하더라도 ‘미상 상태의 내부 가설’로 표시하고, 절충형이라는 공고 분류나 모의 점수로 바꾸지 않는다. Go 화면에는 미상 사항과 그 상태로 진행한다는 선택을 남긴다. 이는 C1의 수용 조건을 채운다.  
근거: [추정] 알려진 요구에 답하는 작업과 모르는 평가 방식을 확정하는 작업은 분리할 수 있다.

혼합 문구는 ‘최선가치’라는 낱말 하나로 정하지 않고 단계·요소·CLIN별 분석 근거로 처리한다. 해소되지 않은 충돌은 관리자가 고른 갈래와 별개로 남긴다.  
근거: [확인] F-8. 단계별 평가, 점수 없는 비교평가, CLIN별 평가가 확인됐다.

### B-6

입장: **바꿈.** LPTA에는 7기준 전체의 점수표를 돌리지 않는다. 소계수별 합격 요건 점검과 전체 정합성 검토를 기본으로 하고, 내부 개선 리뷰는 1 충실도·5 가독성·6 신뢰성을 중심으로 실행한다.

바꾼 까닭 또는 받은 반박에 대한 답: **C2 R4 B-6의 개선 우선순위 문제와 C1의 역할 중복 지적**을 받는다. 발주처 점수와 구분한다고 표시하는 것만으로, 근거 없는 차별화·숨은 이슈가 개선 목록에 올라오는 문제까지 막지는 못한다. 내 R4는 이 제한을 충분히 구체화하지 못했다.  
근거: [자료] `docs/skills/sam-proposal/references/07-review.md`, 역할 “**역할**: 완성 본문(또는 중간 산출물)을 평가 기준으로 검토하고 개선 우선순위를 낸다.” 같은 문서, 개선 우선순위 “**우선순위 = 해당 평가항목 배점 × 개선 여지(현재 점수와 만점의 격차) × 수정 난이도 보정**”.  
근거: [자료] `docs/기록/토론_제안서작성개편/라운드/R4_공개.md`, C1 B-6이 인용한 공고 사실 “비가격 요소는 합격/불합격만 판정하고 서열화하지 않으며, 하나라도 불합격이면 전체 제안 부적격. 가격은 점수화하지 않고 완전성·합리성만 분석”.

**C1·C2의 수용 조건을 다음처럼 채운다.** LPTA에서 2 반응도·3 전략적 초점·4 경쟁사 초점은 별도 점수와 개선 우선순위에서 제외한다. 7 표현 품질의 별도 카피라이팅 확장도 두지 않는다. 요구된 수행계획과 승인된 자원 약속의 일치는 충실도·문서 간 정합성에서, 가격은 가격 검사에서, 답을 찾기 쉬운지는 가독성에서 확인한다. 수정 제안은 요구·근거·승인된 계획과 연결하며, 고친 문장은 다시 사실 검증한다. 내부 개선 진단의 평점이 제출 관문을 대신하지 않는다.  
근거: [추정] 필요한 검토 내용을 기존 검사에 명시적으로 배정하면, LPTA에 없는 배점이나 경쟁 우위를 만들지 않고도 답의 충실성을 검토할 수 있다.

**G2 R4 B-6의 중복 비용 비교 결과는 아직 없다.** 이번 변경을 비용 절감이 입증된 결정으로 설명하지 않는다. 근거 없는 개선 과제를 만들 여지를 줄이는 설계 판단이다. 최고 가치 절충에는 공고 근거가 있는 범위에서 더 넓은 전략·7기준 진단을 유지하되, 공식 배점이 없으면 모의 점수를 만들지 않는다.  
근거: [추정] 평가 방식별로 리뷰의 적용 범위를 달리한다는 A-16에서 도출했다.

### B-7

입장: **바꿈.** CR-171 전략 승인과 CR-172 목차·절 기획을 별도 도입 회차로 확정한다. 전체 리뷰 기능은 선택적 표현 고도화보다 먼저 갖추되, 각 건의 최종 검사는 요약문·표지·서식까지 반영한 마지막 제출 파일에 수행한다.

바꾼 까닭 또는 받은 반박에 대한 답: **C2 R4 B-7의 운영 효과 분리 논거**를 받는다. CR-171에서는 전략 승인·Go 조건 일치·작성 전이를 확인하고, CR-172에서는 승인된 전략을 고정해 기획과 본문 연결을 확인한다. 이후 증빙 조립·지정 양식·영문 작성과 출력을 각각 도입한다. 기획과 영문을 함께 바꾸지 않는 입장은 유지한다. 두 기능을 나눈다고 전략만의 본문 개선 효과까지 측정됐다고 주장하지는 않는다.  
근거: [자료] `docs/skills/sam-proposal/references/05-section-plan.md`, 입력 “**입력**: 목차 전략표, 수주 전략서, 컴플라이언스 매트릭스”.  
근거: [추정] 승인 기능의 운영 검증과 기획·작성 연결 검증을 나누면 변경 범위와 실패 지점을 구분하기 쉽다. 이는 G2가 제시한 확정 전략 연결·별도 비교 조건도 채운다.

**C1·C2의 ‘요약문이 리뷰 뒤에 들어간다’는 반박**을 받는다. 내 도입 순서를 실행 순서로 읽으면 마지막 산출물이 검사에서 빠질 수 있었다. 앞으로는 기능 도입 순서와 개별 건의 실행 순서를 명시적으로 구분한다. 선택적 표현 기능을 나중에 도입하더라도, 그 기능으로 새로 생긴 요약문·표지 문구는 사실 검증을 거치고 관련 문서 간 일치를 다시 확인하며 최종 파일 검사는 마지막에 한다. 숫자 대조만으로 요약문의 새 주장까지 검증됐다고 치지 않는다.  
근거: [자료] `docs/skills/sam-proposal/references/07-review.md`, 리뷰 시점 “| 제출 직전 | Gold | 제출 요건·최종 품질 |”.  
근거: [추정] 검사 후 내용이 바뀌면 이전 검사는 변경된 내용을 보증하지 않는다. 이 보완으로 C1·C2의 요약문 포함 조건을 채운다.

필수 조직도는 해당 작성 기능에 포함한다. 요약문이 필요한 건에서는 작성 과정에 포함하고 최종 리뷰 대상에 넣는다. 전략과 기획을 분리 도입하므로 ‘전략은 기획을 거쳐서만 본문에 닿아야 한다’는 C1·C2의 묶음 도입 조건은 채택하지 않는다. 작성은 승인된 기획과 전략을 함께 참조한다.  
근거: [자료] `docs/skills/sam-proposal/references/06-writing.md`, 입력 “**입력**: 섹션 기획서 전체, Winning Theme, 컴플라이언스 매트릭스”. 같은 문서, 요약문 “ES는 본문보다 먼저, 4-Box + Hot Button 구조로 작성한다:”.

CR-175를 마지막 별도 영업 흐름으로 두는 합의는 유지한다.

### B-8

입장: **그대로.** 기존 계정·다섯 제출 장 고정, 같은 서류에서 회사 정보 보완, 회사 정보를 고정한 원재료 입력의 세 조건을 구분한다. 실제 낙찰본 검사는 별도 진단 시험으로 명시하되 전부 PASS로 만드는 것을 목표로 삼지 않는다.

바꾼 까닭 또는 받은 반박에 대한 답: **C2 R4 B-8의 ‘새 기능이 아니면 회사 정보 조건을 따로 둘 이유가 없다’는 반박**은 받지 않는다. 회사 정보는 기능 여부와 관계없이 분석·작성의 입력이다. 시험 계정의 영향까지 판단하려면 서류 변경과 독립적으로 비교해야 한다. 회사 정보 효과를 판단하지 않는 제한된 시험이라면 두 조건으로 가능하지만, 내 안은 그 효과도 확인한다.  
근거: [자료] `docs/기록/토론_제안서작성개편/쟁점지.md`, 시뮬레이션 결과 “회사 정보는 시험 고객 계정 것(UEI, CAGE 없음)으로 돌렸다”.  
근거: [추정] 같은 코드·같은 서류에서 회사 정보만 바꾼 비교와, 같은 회사 정보에서 서류만 바꾼 비교를 구분해야 원인을 가를 수 있다.

**C1·C2 R4 B-8의 해명**도 반영한다. 두 사람의 원재료 시험에 회사 정보 변경이 들어 있었다고 간주한 우려는 거둔다. 다만 회사 정보를 고정한 두 조건만으로 회사 정보 보완 효과까지 알 수 있는 것은 아니다. 세 조건은 정확히 세 번만 실행하라는 뜻도 아니며, 원재료 조건이 실제 고객 전체를 대표한다는 뜻도 아니다.  
근거: [자료] `docs/기록/토론_제안서작성개편/라운드/R4_공개.md`, C2 입장 밝히기 B-8 “내 \"원재료 서류\" 시험에 회사 정보 보완은 들어 있지 않다.”  
근거: [확인] F-1. 원재료 입력의 성능은 확인되지 않았다.

**C1의 대체 증빙 상태 조건과 C2·G2의 진단 시험 조건**을 받는다. 원문과 다른 증빙이 있으면 ‘대체 증빙—동등성 확인 필요’로 구분하고, 원문·첨부·추출 오류·적용 조건·대체 인정 근거를 조사한다. 자동으로 실제 부적격이라고 단정하지 않지만, 낙찰 사실이나 관리자 승인만으로 충족 PASS를 만들지도 않는다.  
근거: [확인] F-7. 실제 A-1의 증빙 차이는 확인됐지만 발주처의 대체 인정과 평가 경위는 미확인이다.

F-10의 답 없음도 같은 원칙으로 조사한다. 계약 후 이행이나 제출 행위를 본문 누락과 구분하며, 답변 위치가 발견됐다는 사실만으로 내용 충족까지 인정하지 않는다. 낙찰본은 검사 오류를 찾는 사례이지 모든 줄의 정답표가 아니다.  
근거: [확인] F-10. 확인 대상은 제출본에서의 답변 위치·형태이며, 51줄 각각의 답변 불필요 여부는 미확인이다.

## 같은 것에 대해

**A-4의 제출 검사 적용 방식을 F-10에 맞춰 보완한다.** 고객 업로드 60줄을 포함해 SHALL 전체를 추적한다는 합의는 유지한다. 그러나 이를 ‘모든 줄에 제안서 본문이나 첨부 답이 있어야 제출 가능’으로 구현하면 안 된다. 각 줄의 적용 주체·조건·시점·필요한 제출 행위를 확인하고, 제출 단계에 적용되는 요건을 검사해야 한다. 제외·후속 이행·해석 미확인도 근거와 함께 남긴다. 답 없음 51줄을 자동 면제하는 것도 금한다.  
근거: [확인] F-10.

그 밖에 새 사실로 뒤집힌 합의는 없다. A-9의 요구별 혼합 작성과 A-11의 모든 실제 절에 대한 기획은 유지한다. 모든 요구를 추적한다는 것과 모든 요구마다 본문 절을 만든다는 것은 구분한다.  
근거: [추정] F-10에서 제안서 답변 외의 절차·행위·후속 의무가 확인된 데서 도출했다.

## 여전히 모르는 것

- **답 없음 51줄의 개별 적용 여부.** 원문 조항별 재검토와 필요한 원본 확인 없이 모두 면제하거나 모두 누락으로 판정할 수 없다. 다른 공고에서도 같은 분류가 충분한지는 모른다. [확인] F-10.
- **REQ-089의 대체 인정 근거와 실제 평가 경위.** 낙찰 사실과 제출 증빙 차이만 확인됐으며, 이를 일반적인 동등성 규칙으로 만들 근거는 없다. [확인] F-7.
- **CR-189 재시험, 조건 전달, 서술 축소, 기획·영문 도입의 실제 효과.** 누락·근거 없는 문장·재작업·시간·비용의 변화는 같은 입력 비교로 확인해야 한다. [자료] `docs/기록/토론_제안서작성개편/쟁점지.md`, 배경 “같은 건 재시험은 하지 않았다.”
- **버전 연결의 구현 비용과 변경 영향 판정의 정확도.** 사실 키 안정성, 의미가 같은 재분석에서 발생할 불필요한 보류, 기존 저장 구조에서의 최소 구현 범위는 미확인이다. [추정] B-4의 입력 보존과 의미 비교를 구현해야 정해지는 사항이다.
- **관리자의 기획 수정 비율과 확인 대기 시간.** 묶음 중간 점검이 재작업을 얼마나 줄이는지, 실제 사람 손을 얼마나 늘리는지는 측정되지 않았다. [자료] `docs/기록/토론_제안서작성개편/라운드/R3_공개.md`, B-2 “관리자가 목차와 기획을 실제로 고치는 비율과 확인 대기 시간은 아무도 재지 않았다.”
- **평가 방식이 저장되지 않은 36건의 원문 내용과 원재료 입력의 대표성.** 미상이나 원재료 조건을 편의상 하나의 평가 갈래·고객 유형으로 일반화하지 않는다. [확인] F-8, F-1.
