# R3 공개 - IR-002

넷의 R3 원문을 묶었다. 앞머리에 감독이 새로 확인한 사실 F-7 ~ F-9 와, 감독 쪽 빈 맥락 정리관이 R3 넷에서 추린 "넷이 같은 것" 과 "아직 갈린 것" 을 붙였다. F-1 ~ F-6 은 R2_공개.md 머리에 있다. 사람은 이번 토론에서 의견을 내지 않는다.

같은 것과 갈린 것은 감독이나 정리관의 입장이 아니다. 참가자 R3 문장을 옮긴 것이고, 자기 입장이 잘못 옮겨졌으면 R4 에서 바로잡는다. "(R4 에서 본인이 밝힐 것)" 은 R3 에 그 참가자의 입장이 적혀 있지 않아 앞 라운드 문장으로 채운 자리다.

### B-2 작성 전 사람 확인을 Go 와 전략 한 자리로 두나, 목차와 절 기획까지 따로 받나, 받는다면 몇 번에 받나
- C1: R3 안에는 "3단계 전략은 건마다 한 번, Go 결정 화면에서 함께 승인한다" 는 한 자리만 있다 (안 2). 목차와 기획의 확인은 R3 에 없고, R2 G2-3 반박의 "사람 확인은 스킬이 반드시라 한 Go 와 전략 두 자리로 족하다. 목차는 보이기만 해도 된다" 를 거두지 않았다. 그 근거는 확인 횟수가 사실 충실을 올리지 않고 빈 재료는 서버 대조가 잡는다는 것이다 (R4 에서 본인이 밝힐 것).
- C2: 사람 자리를 "셋(Go와 전략, 목차와 기획, 마지막 검토)" 으로 둔다. AI 가 낸 조건 그대로 Go 하면 "한 번에 둘을 승인" 하고 조건을 바꾼 건만 전략을 따로 승인한다. "목차와 기획은 한 화면에서 한 번 관리자 확인을 받은 뒤 작성한다" (바꾼 것 5, G2 C2-8 에 대한 답, F-3, F-5, SKILL.md 87줄).
- G1: "Go 결정·전략 승인·목차 확인은 기존 화면에서 순차로 진행할 수 있지만, 각각 무엇을 확인했는지는 남겨야 한다". "같은 화면이면 사람 대기가 반드시 한 번이라는 결론은 유지하지 않는다" (C2 의 G1-3 에 대한 답, F-3, 03-win-strategy 입력).
- G2: "목차를 보이기만 하고 확인을 생략하자는 제안은 받아들이지 않는다". Go, 전략, 목차, 기획을 같은 작업 화면에서 이어 보되 확인 대상을 따로 적고, "절 기획은 스킬이 정한 묶음 단위로 확인한다", 바뀌지 않은 산출물은 다시 승인받지 않는다 (C1, C2 의 G2-3 에 대한 답, F-3, SKILL.md 87줄, 05-section-plan 49줄 "한 번에 섹션 기획서 2~3개씩").
- 갈림의 종류: 판단. C1, C2, G2 가 같은 SKILL.md 87줄을 들되 확인 자리를 다르게 읽는다. 관리자가 목차와 기획을 실제로 고치는 비율과 확인 대기 시간은 아무도 재지 않았다.

### B-3 요구 줄의 작성 꼴을 공고 분석 매트릭스의 채우는 쪽(fulfillmentParty) 값만으로 정하나, 요구 동사와 지정 서식, 가격 항목을 함께 보나
- C1: "장에는 기본 꼴을 두고, 절 기획에서 요구 동사로 줄마다 답의 꼴(서술, 증빙 위치, 가격 칸, 양식 칸)을 덮어쓴다". 다른 공고의 기준은 "요구 동사와 누가 채우나(fulfillmentParty)를 함께 보는 절 기획" 이다 (바꾼 것 1, C2 가장 약한 곳에 대한 답, notice-run2 의 A-4 CLIENT_UPLOAD 와 실제 장비 계획의 서술 뒤 임대차 계약, 05-section-plan 13줄).
- C2: "꼴은 절 하나에 하나가 아니라 요구 줄의 채우는 쪽 값으로 정해 한 절 안에 섞인다". 고객이 낼 줄, 가격 줄, 정부 양식 줄에서는 최소 단어와 상세 문단 규칙을 끈다 (순서 (2a), 바꾼 것 6, F-2). R2 G1-5 에서는 "AI 에게 꼴을 새로 가르게 할 필요가 없다" 고 했다.
- G1: "기존 fulfillmentParty를 기본 분류에 재사용하는 것은 찬성한다. 하지만 담당 주체만으로 답의 형태가 모두 정해진다는 데는 동의하지 않는다". "요구 동사·지정 서식·가격 항목을 함께 보고 한 절의 복수 작성 방식을 정한다" (C2 의 G1-5 에 대한 답, notice-reqdocs A-4 "보유 증빙과 사용 확약").
- G2: R3 에 판정 기준을 적지 않았다. R2 C2-5 반박은 "작성 종류를 절 속성과 지시문 분기만으로 한정해서는 안 된다" 와 계산, 원본 조립의 별도 도구였고, C2 는 R3 에서 뒤의 것을 서버 코드로 받았다 (R4 에서 본인이 밝힐 것).
- 갈림의 종류: 사실. 매트릭스 94줄의 채우는 쪽 값과 실제 제출본이 그 줄에 답한 꼴을 줄마다 견주면(A-4 의 장비 목록 서술 줄과 보유 증빙, 사용 확약 줄이 각각 어느 값인지), 이 공고에서 채우는 쪽 값만으로 꼴이 맞게 갈리는지 정해진다. 다른 공고에도 맞는지는 견본이 1건이라 판단으로 남는다.
- 감독 사실 확인: F-9 가 장비 계획 장의 두 줄을 봤다. 나머지 92줄은 보지 않았다.

### B-5 평가 방식을 모르거나 공고 문구가 섞인 공고를 어느 갈래로 다루나
- C1: "평가 방식을 모르거나 공고 문구가 섞이면 절충형 판을 기본으로 두고 관리자가 Go 화면에서 바꾼다". 갈래는 평가 항목 트리가 아니라 공고 사실 "평가방식" 과 Go 화면의 관리자 확정으로 정한다 (바꾼 것 9, notice-facts "평가방식" 의 최선가치 병기 문구).

- 갈림의 종류: 판단. 이 기본 갈래가 몇 건에 걸리는지는 사실이고, 평가 항목 트리가 없는 44건의 공고 사실에 "평가방식" 이 있는지 보면 정해진다(C1 여전히 모르는 것). C1 의 절충형 기본이 전략에만 미치는지 모의 채점까지 미치는지는 R3 문장으로 가려지지 않는다 (R4 에서 본인이 밝힐 것).

### B-8 기준선을 몇 가지 입력 조건으로 재나, 그때 제출 검사를 실제 낙찰 제출본에 돌려 맞추나

- 감독 사실 확인: F-7. 낙찰본 A-1 에는 국세청 조경용역 등록 증빙이 없고 보령시 건설업 등록증이 그 자리를 채웠다. 원문 글자대로 판정하는 검사는 낙찰본의 REQ-089 에서 걸린다.

# R3 - C2

## 안
바꿈. 전에는 안 D "기준선 먼저, 뼈대는 살리고 저장되는 산출물로 하나씩 끼운다", 지금은 같은 뼈대에 들이는 순서와 사람 확인 자리를 고친 안 D2 "기준선, 서버 제출 검사, 하나씩 바꿔 재기".

뼈대(문서 구성, 목차 설계, 절 작성, 절 검증, 서버 묶기)와 공고 분석, 입찰 분석은 그대로 둔다. 들이는 순서는 이렇다. 한 단계에 AI 산출물을 바꾸는 것은 하나만 넣고, 넣을 때마다 같은 건으로 다시 잰다.
- (0) 기준선 두 번. 같은 다섯 파일로 CR-189 효과를 한 번, 원재료 서류로 한 번 잰다. 절마다 시작과 끝 시각, 시도 횟수를 남긴다.
- (1) 서버 제출 검사(AI 호출 없음). 공고 분석의 SHALL 87줄과 필수 서류 17개를 채우는 쪽(고객, 플랫폼, 정부 양식)별로 상태를 보인다. 검증이 미충족으로 남긴 줄, 빈 가격 표, 검증 못 함(PASS 폴백을 버린 자리)이 하나라도 있으면 "제출 불가" 로 표시하고 제출 쪽 전이를 막는다. 관리자 검토로 가는 것은 막지 않는다. 산출물을 바꾸지 않는 검사라 맨 앞에 두어도 측정을 흐리지 않는다.
- (2) 작성 규칙과 입력을 하나씩 바꾼다. (2a) 고객이 낼 줄, 가격 줄, 정부 양식 줄이 걸린 자리에서는 최소 단어와 상세 문단 규칙을 끄고, 증빙은 위치(파일, 쪽)와 짧은 설명으로 쓴다. 꼴은 절 하나에 하나가 아니라 요구 줄의 채우는 쪽 값으로 정해 한 절 안에 섞인다. (2b) 입찰 분석의 결정 조건을 "고칠 것 목록" 으로 절 작성 입력에 넘긴다.
- (3) 가격 엑셀 내보내기(CR-189 가격 항목 66줄, 합계와 인상률 칸은 서버 계산)와 증빙 원본 붙임. AI 를 부르지 않아 (2)와 나란히 들여도 된다.
- (4) 수주 전략(CR-171). 입찰 분석 흐름 끝 단계로 만들어 Go 화면에서 같이 승인한다. 전략은 바탕으로 삼은 조건을 함께 저장하고, 관리자가 확정한 Go 조건과 다르면 작성으로 넘어가는 전이에서 막고 전략을 다시 낸다.
- (5) 목차와 절 기획서(CR-172). 승인된 전략을 입력으로 받고, 기획 항목마다 근거 사실을 지정한다. 서버는 지정한 사실이 있는지만 대조하고, 그 사실이 문장을 뒷받침하는지는 지금처럼 절 검증이 본다. 목차와 기획은 한 화면에서 한 번 관리자 확인을 받은 뒤 작성한다. 기획은 목차 저장 뒤 절 몇 개씩 따로 부른다.
- (6) 따로따로 셋. (6a) 제출 언어를 정하고 영문 본문으로 바꾼다 (6b) 서식, 도식, 장 표지, 요약문은 공고 작성 지시와 기획이 요구할 때 (6c) 건의 제출물 전체를 보는 AI 리뷰 한 번(CR-174 나머지). 문서 사이 숫자 대조는 서버가 먼저 한다. 자동 재작성은 넣지 않는다. 관리자가 절을 고치면 (1) 검사가 다시 돌고 AI 리뷰 결과는 "낡음" 으로 표시된다.
- (7) CR-175 는 공고 전 영업용 별도 입구로 맨 뒤에 둔다.

버릴 것은 그대로다. 고정 최소 단어 수, 검증 실패를 합격으로 치는 동작, 한국어 초안 고정. 사람이 서는 자리는 지금 둘(Go, 마지막 검토)에서 셋(Go와 전략, 목차와 기획, 마지막 검토)이 된다.

## 안

**바꿈. 전에는 안 D ‘공통 7단계와 요구사항별 작성 방식의 결합’, 지금은 안 D′ ‘공통 7단계는 유지하고, 제출 검사와 가격 기능을 먼저 분리 도입’이다.**

공고 분석·입찰 분석 재사용, 전략 승인, 목차·절 기획, 요구별 서술·증빙·가격·양식 작성, 전체 리뷰라는 뼈대는 지킨다. 스킬 파일은 유지하고 서버가 단계와 산출물 연결을 관리한다.

   근거: [추정] 제출 시 적용되는 필수 요구에는 답·증빙 위치와 충족 판정을 연결한다. 해당 없음에는 적용 제외 근거를 남긴다. 미확인·미충족 상태의 초안을 관리자에게 보여 줄 수는 있지만 제출 가능으로 표시해서는 안 된다. 검토 대기로 넘기는 것 자체와 제출 승인도 구분한다.

3. **G1-16의 시간 기준을 F-5로 정정한다.**

   근거: [확인] F-5. 작성은 순차 실행됐고, 불합격 네 절의 구간 합은 **28분 16초**, 그중 재작성·재검증 구간은 **12분 27초**다. GENERATING에서 REVIEW까지는 **37분 11초**다.

   근거: [추정] 같은 조건의 비교에는 37분 11초와 12분 27초를 기준선으로 사용한다. 새 기획·검사 비용이 추가되고 재시도 일부가 남을 수 있으므로 12분 27초가 그대로 절약된다고 약속하지 않는다. 원재료 시험의 시간이 이보다 길 것이라는 하한 주장도 하지 않는다.

4. **G1-8의 가격 결함 표현은 F-4에 맞춰 확정한다.**

   근거: [확인] F-4와 공개 묶음의 쟁점지 보충.  
   근거: [추정] 이 결과는 CR-189 이전 결함의 근거다. CR-189 이후에도 CLIN이 비어 있다고 주장하지 않는다. 이후 결과는 재시험으로 확인한다.

5. **기준선 시험을 입력 조건별로 분리한다.**

   근거: [확인] F-1. 고객 파일 다섯 개는 실제 제출 장과 동일하며, 원재료만 받은 결과는 측정하지 않았다.  
   근거: [추정] 완성된 제출 장의 재작성 결과로 신규 작성 능력을 대표할 수 없다. 그렇다고 실제 고객이 항상 원재료만 제출한다고 단정하지도 않는다. 각 입력 조건에서 기존 흐름과 개편 흐름을 비교한다.

6. **G1-2·3·4·15의 버전·재실행 규칙을 구체화한다.**

   G2가 R2의 ‘다른 안의 가장 약한 곳’에서 지적한 내용을 받아들인다. 규칙을 서버에 둔다는 선언만으로는 최신 입력에 대한 승인과 검증을 보장하지 못한다.

   근거: [자료] `docs/기록/토론_제안서작성개편/라운드/R2_공개.md`, G2의 G1 안 약점 “전략·회사 자료·본문이 바뀔 때 어떤 승인과 검증을 다시 받아야 하는지, 늦게 도착한 이전 실행 결과를 어떻게 배제할지까지 정해야 최신 제출물의 완료를 보장할 수 있다.”

   다음은 구현할 규칙이다. 현재 기능이 이미 이렇게 동작한다는 뜻은 아니다.

   - **[추정]** 각 산출물과 검증 결과에 사용한 공고 분석·회사 근거·Go 조건·전략·기획·본문 버전을 연결한다. 현재 버전과 맞는 결과만 완료 판정에 사용한다.
   - **[추정]** 조건·수행 약속이 바뀌면 관련 전략 승인부터 다시 확인한다. 근거가 바뀌면 연결된 기획·본문·검증을 재검토한다. 본문만 수정하면 해당 본문 검증과 관련 전체 정합성 검사를 다시 한다.
   - **[추정]** 늦게 도착한 이전 실행 결과는 이력으로 남길 수 있으나 최신 승인·본문·판정을 덮어쓰지 못하게 한다. 영향 범위를 판별할 연결 정보가 없으면 변경된 부분만 안전하다고 가정하지 않는다.
   - **[추정]** 자료 부족은 담당자 보완으로, 검증 실행 장애는 미검증과 검증 재시도로, 내용 오류는 관련 부분 수정으로, 출력 오류는 재조립·재검사로 보낸다. 같은 본문을 무조건 다시 쓰게 하지 않는다.

# R3 - G2

## 안

**바꿈. 전에는 ‘공통 7단계와 산출물 종류별 실행’, 지금은 그 구조를 유지하면서 가격 기능을 먼저 분리 도입하고, 승인·재실행 범위를 명시한 수정안이다.**

기존 공고 분석·입찰 분석·장절블록·절별 검증은 재사용한다. 전략 → 목차 → 절 기획 → 종류별 작성 → 전체 리뷰의 연결도 유지한다. 한 절에 서술·증빙·가격·양식을 함께 담을 수 있게 한다.

달라지는 것은 도입 묶음과 운영 범위다. 가격 항목·입력·계산·내보내기를 전략·영문·다른 파일 출력과 분리해 앞당긴다. 평가 트리 부재만으로 공고 분석 전체를 다시 돌리지 않는다. 커버리지는 서버를 판정의 기준으로 삼고, 원본 스크립트 실행용 어댑터를 기본 구현에서 뺀다.

## 받은 반박에 대한 답

**C1의 G2-3 반박 및 ‘가장 약한 곳’ 지적:** 목차를 보이기만 하고 확인을 생략하자는 제안은 받아들이지 않는다. 승인이 회사 사실의 증거가 아니라는 것과, 승인된 결정·목차를 후속 작업의 전제로 삼는 것은 별개다. 사람은 증거를 만들어 주는 대신 적용 범위·제출 구성·수행 약속을 검토한다. 서버의 참조 존재 검사만으로 이 결정을 대신할 수는 없다.

근거: [자료] `docs/skills/sam-proposal/SKILL.md`, 87줄: “특히 Go/No-Go(2), Winning Theme(3), 목차(4)는 이후 모든 작업의 전제이므로 반드시 확인받는다.”  
근거: [추정] C1이 인용한 문장에도 목차가 포함돼 있으므로 Go와 전략만으로 충분하다는 결론은 그 인용에서 나오지 않는다. 확인 횟수가 정확성을 보장한다는 주장도 하지 않는다.

**C2의 G2-3 반박 및 ‘가장 약한 곳’ 지적:** 사람 대기가 늘 수 있다는 지적은 인정한다. 같은 화면을 쓴다고 확인 대기가 없어지는 것도 아니다. 다만 아직 고치는 비율을 모른다는 이유로 목차·기획 확인을 마지막 검토로 미루지는 않는다. 다음 방식으로 확인 부담을 제한한다.

- 기존 분석 결과와 Go 결정은 유효한 입력이 유지되면 재사용한다.
- Go·전략·목차·기획은 같은 관리자 작업 화면에서 이어 보되, 서로 다른 확인 대상을 명시한다.

**G1의 ‘승인 묶음과 변경 시 재승인 범위가 불명확하다’는 지적:** 받아들여 운영 규칙을 구체화한다. 승인 대상은 산출물 전체의 막연한 최신 상태가 아니라 확인한 버전이다. 변경 영향은 다음 원칙으로 처리한다.

| 바뀐 것 | 다시 확인할 범위 |
|---|---|
| 공고 요구·제출 지시 | 영향받는 전략·목차·기획·산출물과 제출 검사 |

| 본문·가격 입력 | 해당 내용의 사실·요구 대응 검사, 관련 문서 간 일치 검사 |
| 출력 서식·첨부 구성 | 최종 파일의 분량·표·첨부·서명 등 제출 검사 |
