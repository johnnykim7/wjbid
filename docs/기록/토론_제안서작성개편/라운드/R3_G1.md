# R3 - G1

## 안

**바꿈. 전에는 안 D ‘공통 7단계와 요구사항별 작성 방식의 결합’, 지금은 안 D′ ‘공통 7단계는 유지하고, 제출 검사와 가격 기능을 먼저 분리 도입’이다.**

공고 분석·입찰 분석 재사용, 전략 승인, 목차·절 기획, 요구별 서술·증빙·가격·양식 작성, 전체 리뷰라는 뼈대는 지킨다. 스킬 파일은 유지하고 서버가 단계와 산출물 연결을 관리한다.

바꾸는 핵심은 G1-15의 도입 묶음이다. 가격 입력·계산·내보내기를 전략·기획 완성과 영문 전환까지 기다리게 하지 않는다. 증빙 붙임, 지정 양식, 영문 작성도 각각 검증하며 도입한다. **개별 도구·파일의 사용 가능과 전체 제안서의 제출 가능은 구분한다.**

## 바꾼 것과 그 이유

1. **G1-15의 큰 작성 묶음을 나누고 가격 기능을 앞당긴다.**

   C1과 C2가 R2에서 G1-15에 제기한 반박을 받아들인다. 가격·증빙·양식·영문·파일 검증을 한 회차에 바꾸면 효과와 결함의 원인을 분리하기 어렵고, 가격 기능을 독립적으로 쓸 기회도 늦어진다.

   근거: [확인] F-4. 기존 가격 절에는 표가 있었지만 공고 가격 일정표의 품목을 한 줄도 옮기지 않았고 금액도 없었다. 그런데 사실 검증은 PASS였다.  
   근거: [자료] `docs/기록/토론_제안서작성개편/라운드/R2_공개.md`, C2의 G1-15 반박 “가격 내보내기처럼 AI 를 부르지 않는 것은 앞으로 떼어 낼 수 있다.”  
   근거: [추정] 공고 항목·고객 입력·산식·파일 출력은 영문 서술 변경과 분리해 시험할 수 있다. 이 독립성이 도입 순서를 바꾸는 이유다.

   수정한 도입 순서는 다음과 같다. 이는 **구현 순서**이며, 한 건의 제안 본문을 생성할 때 전략 승인을 먼저 받는 전제는 유지한다.

   | 순서 | 도입할 것 | 확인할 결과 |
   |---|---|---|
   | 0 | CR-189 이후 동일 입력 재시험 | 공고 항목·정부 양식·공고 사실 전달의 실제 결과와 기준선 |
   | 1 | CR-174의 필수요건·제출 검사 선행, 미검증 상태 구분 | 파일 존재·사실 PASS·요구 충족·제출 가능을 혼동하지 않음 |
   | 2 | 가격 입력·검산·내보내기 기능 | 공고 항목 누락·중복·연차, 고객 단가와 가정, 금액·합계, 출력 파일을 각각 확인 |
   | 3 | CR-171 전략 승인과 CR-172 목차·절 기획 | 확정된 조건·근거·기획 버전이 작성 입력으로 이어짐 |
   | 4 | CR-173의 증빙 붙임, 지정 양식, 영문 작성·출력을 각각 도입 | 한 기능씩 입력을 고정해 확인하고, 다음 변경의 효과와 분리 |
   | 5 | CR-174 전체 정합성 리뷰와 최종 파일 검사 완성 | 인원·장비·가격·확약의 일치와 전체 제출 요건 확인 |
   | 6 | CR-173 요약문·도식·장 표지·표준 서식 확대 | 공고 지시와 기획에 맞는 표현 개선 확인 |
   | 별도 후순위 | CR-175 회사소개서·사전 의향조사 회신·콜드메일 | 공식 제안서의 선행 조건으로 넣지 않고 공통 근거 자료를 재사용 |

   근거: [추정] 개별 가격 파일은 준비·검토에 먼저 사용할 수 있다. 그러나 가격 파일 하나가 완성됐다는 이유로 전체 제안서를 제출 가능으로 표시하지 않는다. 공고가 요구한 조직도처럼 답 자체를 구성하는 도식은 6순위 표현 고도화로 미루지 않는다.

2. **G1-7의 전체 제출 검사는 필요성에 대한 추정에서, 확인된 관문 누락을 고치는 우선 과제로 강화한다.**

   R2에서 나는 F-2만으로 다른 고객 서류 관문까지 없다고 단정할 수 없다고 했다. F-6이 그 확인을 마쳤으므로, 이 시험 건에 대해서는 그 유보를 거둔다.

   근거: [확인] F-6. 기존 검사는 REQ 번호 없는 서류 칸 다섯 곳의 파일 존재를 확인했다. 고객 업로드 SHALL 60줄은 어떤 관문에도 걸리지 않았고, REQ-089 미충족과 A-1의 PASS가 함께 기록됐다.

   다만 **“60줄은 아무 검사도 받지 않았다”로 바꾸지는 않는다.** 11줄 충족, 2줄 미충족 기록이 있고 47줄은 기록이 없다. 확인된 결함은 내용 판정의 부족과, 미충족을 남겨도 이를 제출 판단에 연결하지 않는 구조다.

   근거: [확인] F-2, F-6.  
   근거: [추정] 제출 시 적용되는 필수 요구에는 답·증빙 위치와 충족 판정을 연결한다. 해당 없음에는 적용 제외 근거를 남긴다. 미확인·미충족 상태의 초안을 관리자에게 보여 줄 수는 있지만 제출 가능으로 표시해서는 안 된다. 검토 대기로 넘기는 것 자체와 제출 승인도 구분한다.

3. **G1-16의 시간 기준을 F-5로 정정한다.**

   R2에서 C2-4에 답하며 28분 16초를 아직 추산으로 취급했던 부분은 거둔다. 감독이 확인한 구간 시간으로 받아들인다. 다만 이 전체를 재시도 비용이나 절감 가능 시간으로 읽지 않는 입장은 유지한다.

   근거: [확인] F-5. 작성은 순차 실행됐고, 불합격 네 절의 구간 합은 **28분 16초**, 그중 재작성·재검증 구간은 **12분 27초**다. GENERATING에서 REVIEW까지는 **37분 11초**다.

   근거: [추정] 같은 조건의 비교에는 37분 11초와 12분 27초를 기준선으로 사용한다. 새 기획·검사 비용이 추가되고 재시도 일부가 남을 수 있으므로 12분 27초가 그대로 절약된다고 약속하지 않는다. 원재료 시험의 시간이 이보다 길 것이라는 하한 주장도 하지 않는다.

4. **G1-8의 가격 결함 표현은 F-4에 맞춰 확정한다.**

   ‘표가 없었다’가 아니라 **‘가격표 틀은 있었으나 공고 항목과 금액이 채워지지 않았다’**가 정확하다. R2에서 제기한 이 사실 다툼은 끝낸다.

   근거: [확인] F-4와 공개 묶음의 쟁점지 보충.  
   근거: [추정] 이 결과는 CR-189 이전 결함의 근거다. CR-189 이후에도 CLIN이 비어 있다고 주장하지 않는다. 이후 결과는 재시험으로 확인한다.

5. **기준선 시험을 입력 조건별로 분리한다.**

   G1-14·15의 비교 원칙을 F-1에 맞춰 더 명확히 한다. 기존 다섯 제출 장을 그대로 사용하는 재현 시험, 회사 정보 보완 시험, 원재료 서류 시험을 구분한다.

   근거: [확인] F-1. 고객 파일 다섯 개는 실제 제출 장과 동일하며, 원재료만 받은 결과는 측정하지 않았다.  
   근거: [추정] 완성된 제출 장의 재작성 결과로 신규 작성 능력을 대표할 수 없다. 그렇다고 실제 고객이 항상 원재료만 제출한다고 단정하지도 않는다. 각 입력 조건에서 기존 흐름과 개편 흐름을 비교한다.

6. **G1-2·3·4·15의 버전·재실행 규칙을 구체화한다.**

   G2가 R2의 ‘다른 안의 가장 약한 곳’에서 지적한 내용을 받아들인다. 규칙을 서버에 둔다는 선언만으로는 최신 입력에 대한 승인과 검증을 보장하지 못한다.

   근거: [자료] `docs/기록/토론_제안서작성개편/라운드/R2_공개.md`, G2의 G1 안 약점 “전략·회사 자료·본문이 바뀔 때 어떤 승인과 검증을 다시 받아야 하는지, 늦게 도착한 이전 실행 결과를 어떻게 배제할지까지 정해야 최신 제출물의 완료를 보장할 수 있다.”

   다음은 구현할 규칙이다. 현재 기능이 이미 이렇게 동작한다는 뜻은 아니다.

   - **[추정]** 각 산출물과 검증 결과에 사용한 공고 분석·회사 근거·Go 조건·전략·기획·본문 버전을 연결한다. 현재 버전과 맞는 결과만 완료 판정에 사용한다.
   - **[추정]** 조건·수행 약속이 바뀌면 관련 전략 승인부터 다시 확인한다. 근거가 바뀌면 연결된 기획·본문·검증을 재검토한다. 본문만 수정하면 해당 본문 검증과 관련 전체 정합성 검사를 다시 한다.
   - **[추정]** 늦게 도착한 이전 실행 결과는 이력으로 남길 수 있으나 최신 승인·본문·판정을 덮어쓰지 못하게 한다. 영향 범위를 판별할 연결 정보가 없으면 변경된 부분만 안전하다고 가정하지 않는다.
   - **[추정]** 자료 부족은 담당자 보완으로, 검증 실행 장애는 미검증과 검증 재시도로, 내용 오류는 관련 부분 수정으로, 출력 오류는 재조립·재검사로 보낸다. 같은 본문을 무조건 다시 쓰게 하지 않는다.

## 받은 반박에 대한 답

**C1 — R2의 G1-15 및 ‘G1 안의 가장 약한 곳’:** 가격을 앞당기라는 반박은 받아들여 도입 순서를 바꿨다. 초기 범위는 공고 항목·고객 단가와 가정·산식·합계·내보내기다. 원가를 AI가 자동 결정하거나 낙찰본의 인상률을 복사하는 범위로 넓히지 않는다.  
근거: [확인] F-4.  
근거: [추정] 빈 가격표를 실제 입력·검산 가능한 도구로 바꾸는 작업은 영문 본문과 분리할 수 있다.

CR-175는 공식 제안서 실행 순서에서 분리하되, 이번 결정에서 도입 위치를 없애자는 부분은 받아들이지 않는다.  
근거: [자료] `docs/기록/토론_제안서작성개편/쟁점지.md`, 정할 것 “어떤 순서로 들일 것인가(계획만 있는 CR-171 ~ 175 포함).”  
근거: [추정] 별도 후순위 트랙으로 배치하면 요청 범위를 다루면서 공식 제안서 작성의 대기 조건으로 만들지 않을 수 있다.

**C2 — R2의 G1-15 및 ‘G1 안의 가장 약한 곳’:** 한 묶음에서 다섯 변화를 시험하는 문제를 인정한다. 가격, 증빙 붙임, 지정 양식, 영문 전환을 각각 확인한 뒤 전체를 결합하도록 바꿨다.  
근거: [자료] `docs/기록/토론_제안서작성개편/라운드/R2_공개.md`, C2의 G1-15 반박 “영문 효과를 따로 볼 수 없다.”  
근거: [추정] 기능별 사용 가능 여부는 먼저 확인하되 전체 제출 가능은 통합 검사로 결정한다. 이 구분으로 조기 사용과 최종 완결성을 함께 확보하려 한다.

**G2 — R2의 ‘G1 안의 가장 약한 곳’:** 변경 전파와 실패 복구가 구체적이지 않았다는 지적을 받아들였다. 위의 버전 일치·영향 범위·늦은 결과 배제·실패 원인별 복구 규칙을 추가한다.  
근거: [추정] 이전 본문 검증을 새 본문의 PASS로 사용하지 않으려면 저장 위치뿐 아니라 결과의 유효 조건이 필요하다. 근거 ID와 변경 관계를 현재 모델에서 얼마나 안정적으로 관리할 수 있는지는 여전히 확인 대상이다.

**C1 — R2의 G1-4에 단 동의의 제한:** 증빙·양식에도 장문의 7요소 기획서를 새로 쓰게 하자는 뜻은 아니다. 요구 줄별 대응표가 기획 요소의 내용을 충족하면 그 표를 해당 요소에 연결해 중복 서술을 줄인다. 불필요한 그래픽 등은 이유와 함께 해당 없음으로 둔다.  
근거: [자료] `docs/skills/sam-proposal/references/05-section-plan.md`, 그래픽 기획 “도식이 필요 없는 섹션은 "없음"이라 쓴다”  
근거: [추정] 원본 스킬의 기획 항목을 유지하면서도 작성량은 줄일 수 있다. 다만 증빙의 요구 대응·원본 위치·확약·배치를 기획과 리뷰의 공통 책임에서 빼지는 않는다.

**C2 — R2의 G1-3에 덧붙인 승인 위치:** 같은 화면에서 Go와 전략을 다루는 것은 수용 가능하다. 그러나 같은 화면이면 사람 대기가 반드시 한 번이라는 결론은 유지하지 않는다.  
근거: [확인] F-3. 기존 Go 관문은 작동했지만 전략 승인 기능의 작동을 확인한 것은 아니다. 실제 관리자 결정은 GO였다.  
근거: [자료] `docs/skills/sam-proposal/references/03-win-strategy.md`, 입력 “1·2단계 산출물 (특히 Hot Button 재료, BCC, 조건부 Go의 조건들)”
