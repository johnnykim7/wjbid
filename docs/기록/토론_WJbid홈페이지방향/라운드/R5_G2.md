# R5 - G2

## 안

바꿈. 전에는 **B′ ‘공개된 한글 공고 예시를 먼저 보여주는 공통 홈’**, 지금은 **E″ ‘공급 상태에 따라 목록과 예시의 순서를 바꾸는 공통 홈’**이다.

**첫 화면의 본문 자리는 하나로 유지한다.**

- **공개된 마감 전 한글 공고문이 있으면:** 넓은 공고 목록을 먼저 보여준다. 마감순으로 배치하고 제목·공고 유형·마감일을 진하게 표시한다. 목록 머리에는 같은 공개 대상을 센 전체 건수와 그중 7일 안 마감 건수를 둔다. 실제 분석 예시와 시작 안내는 목록 아래로 내려간다.
- **공개된 마감 전 한글 공고문이 없으면:** 현재 상태를 짧게 알리고, 검수한 실제 한글 공고문 예시 한 건을 같은 자리에 보여준다. 제목 가까이에 **‘마감된 공고의 분석 예시’와 실제 마감일**을 표시한다. 첫 화면에는 실제 요약을 읽게 하고, **“자격요건·필수서류 펼쳐 보기”** 버튼으로 같은 홈 안에서 나머지 내용을 펼친다. 회원 상세 페이지로 보내지 않는다.

근거: [확인] F-2·F-5·F-11. [추정] 현재에는 실제 결과물을 이해하게 하고, 공급 이후에는 회원이 예시를 지나지 않고 업무를 시작하게 하는 구성이다.

머리의 검색 위치는 로그인 전후 동일하게 유지한다. 비로그인 상태에서는 검색·회원 상세에 로그인이 필요함을 표시하고, 로그인·가입 자리는 로그인 후 관심 공고·내 계정 진입으로 바꾼다. 독립된 회원 현황 칸은 두지 않는다. 첫 화면에는 **“실제 참여 전에는 해당 공고의 등록·참가 요건을 확인하세요”**라는 짧은 안내를 둔다. 이는 제안 문구다.  
근거: [확인] F-6·F-7·F-8. [추정] 업무 진입 위치를 유지하면서 사이트 가입과 입찰 참가 준비를 구별한다.

아래는 **공고 읽기와 등록·자격·서류 준비 안내 → 기지·낙찰 기록 → 실제 이용 범위·요금·가입·문의** 순서다. 낙찰 숫자는 누를 수 없는 설명 자료로 두고 집계 기간·대상·통화를 밝힌다. 가입 안내에 직접 실행할 수 없는 번역·적격성 분석을 즉시 이용 혜택으로 내세우지 않는다.  
근거: [확인] F-3·F-4·F-9·F-10.

본문·공고 제목 18px, 주요 날짜·유형 16px 이상과 긴 제목 두 줄을 시안 시작값으로 유지한다. 첫 화면 행 수는 실제 제목을 적용해 정하며, **5건·8건·7일 안 마감 전부를 고정 조건으로 삼지 않는다.** 화면에 다 들어가지 않는 공고는 전체보기로 잇고, 총건수를 표시해 일부 목록임을 알린다.  
근거: [추정] 행 수보다 읽기와 전체 대상의 존재를 아는 일이 우선이다.

현재 확인 상태에서는 예시 화면이 나온다. 원천 공고 13건을 고객 공개 공고로 바꿔 표시하지 않으며, 공고문 공급은 사람이 정한다. 홈 구성만으로 그 공급 문제를 해결했다고 주장하지 않는다.  
근거: [확인] F-2·F-5.

## 바꾼 것과 그 이유

1. **예시 버튼의 목적지를 확정했다.**  
   변경 근거는 **F-11과 갈2 C1·C2·G1의 반박**이다. R4까지는 “한글 공고 예시 보기”가 기존 상세로 연결되면 로그인으로 이동한다는 약점을 해소하지 못했다. F-11은 분석 자료 자체가 비로그인 상태에서 제공되며 홈에서 그릴 수 있음을 확인했다.  
   따라서 버튼은 첫 화면에 아직 펼쳐지지 않은 **자격요건·필수서류를 홈 안에서 펼치는 동작**으로 정한다. 이미 보이는 요약을 다시 가리키거나 로그인 화면으로 보내지 않는다. 새 분석 요청 기능이나 별도 공개 서버를 만드는 안이 아니다. [확인] F-11. [추정] 버튼 이름과 결과가 일치하고, 방문자가 서비스의 실제 결과물을 직접 확인할 수 있다.

2. **공급 이후 목록의 위치를 ‘나중에 재판단’에서 ‘첫 화면 맨 위’로 정했다.**  
   변경 근거는 **갈1 C2, 갈5 C1·C2의 반박**이다. 공개 공고가 생겨도 회원이 매일 마감된 예시를 지나야 한다는 지적은 맞다.  
   공개된 마감 전 공고문 수가 0이면 예시를 먼저, 1건 이상이면 목록을 먼저 보여주는 규칙을 채택한다. 목록이 짧으면 예시가 자연스럽게 이어지며 목록 자리를 빈 높이로 채우지 않는다. [추정] 공급 변화 때마다 홈 전체의 방향을 다시 정하는 부담을 줄이고, 반복 이용자의 공고 확인을 앞당길 수 있다. 이는 목록형의 전환 성과가 입증됐다는 뜻이 아니라, 확인 가능한 공고가 생겼을 때 업무를 우선한다는 선택이다.

3. **첫 화면 등록 안내 한 줄을 받아들였다.**  
   변경 근거는 **갈4 C1·C2의 반박과 F-7**이다. 나는 준비 6단계의 부담과 짧은 확인 문장의 부담을 충분히 구별하지 않았다.  
   첫 화면에는 해당 공고의 등록·참가 요건을 확인하라는 문장만 두고, 단계별 설명은 아래에 유지한다. 모든 기업이 미등록 상태이거나 모든 공고에 같은 등록 조건이 적용된다고 말하지 않는다. [확인] F-7. [추정] 예시 읽기에서 실제 참여로 넘어갈 때 필요한 구분을 작은 공간으로 알려줄 수 있다.

4. **아래 공개 공고 목록의 ‘최대 5건’을 철회했다.**  
   변경 근거는 **갈5 G1의 반박**이다. 검증 시작값이라고 한정했어도, 안에 최대값으로 남기면 실제 제목과 공개 대상보다 숫자를 먼저 맞출 수 있다.  
   현재는 대표 예시 한 건으로 시작하고, 공급 이후에는 목록을 위로 올린다. 행 수는 동일한 글자 크기와 실제 제목을 적용한 배치에서 정한다. [추정] 다섯 건이라는 값이 현재 예시 이해나 향후 회원 업무에 필요한 상한이라는 근거는 없다.

5. **회원 진입은 유지하되, ‘회원도 매번 예시를 지난다’는 문제는 본문 순서로 해결한다.**  
   변경 근거는 **갈6 C2의 반박**이다. 공급 이후에도 예시를 본문의 중심에 고정한 점은 바꾼다. 다만 관심 공고·입찰 신청·알림을 요약하는 독립 칸까지 채택하지는 않는다.  
   [확인] F-6은 데이터를 가져올 길을 확인했지만 개인별 표시 범위와 요금제별 접근 일부는 미확인이다. [추정] 먼저 공고 목록과 기존 회원 진입을 앞에 두고, 별도 현황 칸은 실제 반복 업무가 요구하는지에 따라 판단하는 편이 적절하다.

6. **이전 유보 중 확인된 부분은 더 이상 미확인으로 남기지 않는다.**  
   F-11에 따라 홈에서 비로그인 분석 예시를 표시하는 기술적 가능성은 확인됐다. F-8의 기존 상세 페이지 로그인 조건은 그대로다. F-9에 따라 고객이 직접 번역·적격성 분석을 요청하는 경로는 없는 것으로 다룬다. F-10에 따라 낙찰 숫자에 고객 상세 링크를 붙이지 않는다. 낙찰 건수는 F-3의 공고번호 기준 99건이며, 금액 있는 88건의 합은 61,910,091달러다.  
   예시를 실제로 선정·검수한 상태와 모든 기능의 요금제별 권한까지 확인된 상태로 확대하지 않는다.

## 받은 반박에 대한 답

**갈1 C1 — 홈에서 분석 예시를 보여줄 수 있는지에 대한 사실 다툼:**  
F-11로 기술적 다툼은 정해졌다. 공개된 상세 자료에 요약·자격요건·필수서류가 포함되므로 홈에서 직접 표시할 수 있다. 기존 상세 페이지의 로그인 조건을 없애는 안도 아니다. 다만 어느 노출 공고문을 대표 예시로 쓸지, 내용이 정확한지는 별도 검수가 필요하다. 기술적으로 열린 자료라는 사실과 선정된 예시의 품질을 구별한다.

**갈1 C2 — 공급이 돌아와도 예시가 앞에 남고 홈을 다시 고쳐야 한다는 반박:**  
받아들인다. 공급 상태에 따라 같은 본문 자리에서 목록과 예시의 순서를 바꾸도록 최종 규칙을 정했다. 공개 마감 전 공고가 있으면 회원은 첫 화면에서 목록과 마감을 본다. 공개 공고가 없을 때만 예시가 주인이 된다. 공급 책임을 누가 맡는지는 이 배치 규칙으로 대신 정하지 않는다.

**갈2 C1 — 예시 버튼이 이미 보이는 내용을 반복하거나 로그인으로 보낸다는 반박:**  
기존 버튼의 모호함을 인정하고 바꾼다. “자격요건·필수서류 펼쳐 보기”는 첫 화면 요약 아래에 추가 내용을 펼친다. 펼친 뒤에는 접을 수 있게 한다. F-11로 가능한 홈 표시를 사용하는 것이므로 클릭 결과는 로그인 화면이 아니다. 가입은 별도로 찾을 수 있게 유지하지만, 예시 읽기의 동작과 섞지 않는다.

**갈2 C2 — 예시 버튼의 로그인 문제와 예시 선정·교체 부담에 대한 반박:**  
로그인 문제는 F-11에 근거한 홈 내부 펼치기로 해결한다. 같은 페이지에서 내용을 펼치는 것도 예상한 결과가 나타나는 구체적인 행동이므로, 다른 페이지로 이동해야만 주된 행동이 되는 것은 아니라고 본다. [추정]  
예시 관리 부담은 남는다. 한 건을 검수해 고정하고, 원문 정정·분석 오류·서비스 설명 변경·노출 해제 때 재검토하는 기준을 제안한다. 단지 날짜가 오래됐다는 이유로 매일 교체하지 않는다. 마감일과 예시라는 성격을 밝혀 현재 공고로 오해하지 않게 한다. 담당자는 사람이 정해야 한다.

**갈2 G1 및 B′의 약점 — 버튼 목적지가 확정되지 않았다는 반박:**  
받아들인다. 목적지는 회원 상세가 아니라 홈 내부의 분석 내용이다. F-11이 확인한 실제 결과를 표시하며, 첫 요약과 펼친 내용이 무엇인지 구분한다. 이제 ‘예시를 본다고 눌렀는데 로그인에 도착한다’는 동선을 최종안에 남기지 않는다.

**갈3 C1 — 현재 공고 0건 옆에 과거 낙찰 숫자가 없으면 떠날 수 있다는 반박:**  
가능한 우려이지만 낙찰 숫자를 아래에 두는 입장은 유지한다. 내가 주장하는 것도 ‘0 하나만 보이는 화면이 더 낫다’는 것이 아니다. 첫 화면에는 실제 한글 요약과 펼쳐 읽을 자격요건·필수서류가 있다. F-11에 따라 설명 문구만이 아니라 실제 결과물을 보여줄 수 있다.  
[추정] 현재 상태는 짧게 정확히 알리고, 서비스의 도움은 예시로 증명하는 편을 택한다. 과거 낙찰 규모는 별도의 판단 자료이므로 아래에서 충분히 설명한다. 어느 위치가 이탈을 줄이는지는 아직 측정되지 않았다.

**갈4 C1·C2 — 아래에만 두면 등록 요건을 만나지 않고 시작할 수 있다는 반박:**  
짧은 안내 한 줄을 받아들였다. 다만 문구는 “등록이 먼저다”가 아니라 **해당 공고의 등록·참가 요건을 확인하라**는 내용이다. F-7에 따른 조항 차이와 미확인 기업 상태를 존중하면서, 실제 참여에는 확인할 요건이 있음을 첫 화면에서 알린다. 상세 준비 안내는 아래에 유지한다.

**갈5 C1 — 공급이 생긴 뒤에도 공고 목록이 아래에 남는다는 반박:**  
받아들여 위치를 바꾼다. 공개 마감 전 공고가 있으면 첫 화면의 주인은 목록이다. 따라서 내 이전 동의와 ‘공급 후에도 예시 아래’라는 배치 사이의 충돌을 최종안에 남기지 않는다. 8줄 안팎을 반드시 넣는다는 결론까지 받아들이지는 않는다.

**갈5 C2 — 줄 수보다 목록의 자리가 문제라는 반박:**  
받아들인다. 마감순 목록을 먼저 보여주고, 화면에 보이는 행 수와 별개로 공개 대상의 전체 건수와 그중 7일 안 마감 건수를 표시한다. 숫자와 목록은 같은 모집단·기준 시각을 쓴다. 다 들어가지 않은 공고가 있다는 사실을 알 수 있게 하되, ‘7일 안 마감 전부를 첫 화면에’라는 조건은 채택하지 않는다.

**갈5 G1 — 최대 5건을 남기면 비교가 그 값에 맞춰질 수 있다는 반박:**  
받아들여 철회한다. 최종안에서 고정하는 것은 글자 크기·정보의 진하기·목록의 우선 위치·전체보기 경로다. 행 수는 그 조건과 실제 제목으로 정할 구현값이다. 세 건·다섯 건·여덟 건 중 어느 값의 성과가 입증됐다고 주장하지 않는다.

**갈6 C2 — 로그인한 회원의 중앙에 예시와 시작 안내가 계속 남는다는 반박:**  
가장 큰 문제인 공급 이후 예시의 선행 배치를 바꿨다. 공개 공고가 있으면 회원도 첫 화면에서 바로 목록을 보고, 관심 공고는 상단에서 진입한다.  
독립 회원 현황 칸은 여전히 채택하지 않는다. [추정] 상태 요약이 클릭을 줄일 수는 있지만, 어떤 상태를 매일 확인하는지와 칸 전체의 효용은 확인되지 않았다. F-6의 서버 기능 존재만으로 우선순위가 정해지지는 않는다. 현재 공고가 없는 상태에서도 관심 공고·내 계정 진입은 예시를 읽거나 내리지 않고 사용할 수 있게 둔다.

## 여전히 모르는 것

- **대표 예시 한 건의 품질과 선정:** F-11은 비로그인 자료 접근과 분석 내용의 존재를 확인했지만, 홈에 쓸 특정 공고문의 원문 대조·정확성·대표성까지 확인한 것은 아니다.
- **공고문 공급 운영:** 담당자, 검수·노출 주기, 이전 공급이 멈춘 이유, 재개 이후 실제 공개 공고의 양과 분야. 홈의 두 상태 규칙이 이 문제를 해결하지는 않는다.
- **예시 유지 책임:** 오류·원문 정정·노출 해제를 누가 확인하고 홈 예시에 반영할지.
- **회원의 실제 반복 업무와 접근 권한:** 개인별 관심 공고·입찰 신청·알림 중 무엇을 자주 확인하는지, 요금제별 제한이 어떻게 적용되는지. 이 결과가 독립 회원 현황 칸의 필요성을 바꿀 수 있다.
- **가입과 결제의 실제 제공 범위:** F-9가 확인한 기능 존재와 무료 등급별 이용 범위는 구별해야 한다. F-4의 실제 결제 플랜과 F-9의 월 사용 한도 집행도 미확인이다.
- **공고별 참가 요건과 기업의 준비 상태:** F-7에 남은 적용 조항·등록 소요 기간·기존 등록 여부. 회원 정보의 빈칸으로 미등록을 추정하지 않는다.
- **최종 화면의 효과:** 실제 제목과 분석 내용을 넣었을 때의 첫 화면 행 수, 가독성, 예시 펼치기 이용, 가입 후 첫 이용, 회원의 전체 공고 확인 시간과 누락. 최종안은 이 효과가 검증된 결과가 아니라, 확인된 기능과 데이터 범위에 맞춘 구성 선택이다.
