## 고객 포털 색 이름표 (CR-127)

고객 포털의 색은 이 이름표로만 쓴다. 값은 `frontend/customer-portal/src/index.css` 의 `@theme` 한 곳에 있고, Tailwind 클래스로 그대로 쓴다(`bg-brand`, `text-ink-sub`, `border-line`). 화면 코드에 16진 색이나 Tailwind 기본 팔레트 색(`gray-500`, `blue-50` 등)을 직접 쓰지 않는다. 색을 바꿀 때는 "강조색 묶음" 7개 값만 바꾼다(사용자 2026-10-10 16:13 "색상은 추후 설정으로 변경"). 디자인시스템(ds-ui) 부품의 색(`--primary`, `--ring`, `--accent` 등)도 `src/wjbid-theme.css` 에서 이 이름표를 가리킨다.

**CR-133 에서 바뀌는 곳:** 도움 구역의 자주 묻는 질문·공지사항 탭은 자주 묻는 질문 화면·공지사항 화면과 같은 목록을 읽는다(견본 공지는 지우고, 0건이면 "아직 공지가 없습니다"). "준비 중" 으로 가던 링크는 새 목적지로 간다: 등록 대행은 SAM 등록 대행 안내, 사진 안내 3개는 SAM 등록 대행·현장 설명회·무료 입찰 교실, 공고문 예시·재발주 달력은 항목별 준비 안내. 사진 안내의 정해지지 않은 일정 문구는 무료 입찰 교실 안내와 같은 말로 고친다.

**목적:** 원본에서 한글화된 공고문을 검수하고, 한글화 결과를 확인/재생성/보정하며 고객 노출을 토글한다. 구현체: [NoticeAdminDetailPage.tsx](../frontend/admin-console/src/pages/NoticeAdminDetailPage.tsx).

| 한글화 결과 | ANALYZING이면 "LLM이 공고를 한글화/요약하고 있습니다…" 스피너, COMPLETED면 contentJson 렌더, FAILED면 errorMessage | — |

> **CR-039 강제 중단**: generationStatus가 `ANALYZING`일 때만 "강제 중단" 버튼을 노출한다. 클릭 시 `POST /admin/notices/{id}/cancel` → FAILED 전환 → 재생성 버튼 disabled(=ANALYZING 조건) 해제로 재시도 가능. 무한 폴링(스피너만 도는 stuck) 탈출용. 자동 정리(스케줄러)는 화면 액션 없이 백그라운드로 동일 처리.
> **CR-040 삭제**: "삭제" 버튼은 VISIBLE(노출 중)·ANALYZING(분석 중)이 아닐 때만 활성. 클릭 시 확인 모달 → `DELETE /admin/notices/{id}` → 성공 시 목록(`/notices`)으로 이동. 서버가 가드 위반 시 409 + 사유 메시지(노출 중/분석 중) 노출. hard delete라 복구 불가 — 모달에 경고.

### 고객센터 (`/support`) 1:1 문의 (CR-132)

**목적:** 고객이 1:1 문의를 보내면 서버에 접수되고 답변은 적은 이메일로 받는다.
**바뀌는 곳:** 1:1 문의 폼과 그 결과 안내만. 페이지 머리와 자주 묻는 질문 요약은 그대로. 공통 틀은 고치지 않는다.

| 영역 | 표시/입력 데이터 | 주요 액션 |
|------|-----------------|----------|
| 1:1 문의 폼 | 이름, 이메일, 문의 유형(서버 코드 목록), 제목, 내용. 로그인 상태면 이름(담당자)과 이메일을 회원 정보로 채운다. 주소에 `type`, `title` 이 있으면 그 유형과 제목을 채우고 폼으로 내려간다(CR-133) | 문의 보내기 |
| 접수 완료 안내 (폼 자리) | "문의가 접수되었습니다." 와 "답변은 {이메일} 로 보내 드립니다." | 새 문의 쓰기: 빈 폼(로그인이면 이름·이메일은 다시 채움) |
| 접수 실패 안내 (단추 위) | 빨간 줄 "문의를 보내지 못했습니다. 잠시 뒤 다시 보내 주세요." 입력은 그대로 | 없음 |

**CR-133 (CR-132 반영 뒤):** 고객센터 속페이지 틀 안에 둔다(정본 상태 support). 폼은 왼쪽 흰 상자, 오른쪽 300px 에 "메일로도 받습니다"(고객센터 이메일)와 "먼저 찾아보세요"(자주 묻는 질문, 요금 안내, 용어 사전) 상자를 둔다. 자주 묻는 질문 요약은 빼고 이 바로가기로 대신한다. 주소로 유형과 제목이 채워졌으면 폼 위에 초록 줄 "문의 유형과 제목을 채워 두었습니다" 를 보인다.

## 서류함 `/documents` (CR-125 — 실연동)

> 기존 DUMMY 껍데기 → MemberDocument 실연동. 고정 슬롯 카드 + 기타 서류 목록.

- **고정 카드 6종**(사업자등록증·회사소개서·CAGE 증빙·재무제표·SAM 등록증·과거 수행실적): 제목 고정. 파일만 업로드/교체/삭제(파일 피커만, 입력 모달 없음).
- **기타 서류(비고정)**: "기타 서류 추가" 버튼 → 등록 모달(문서제목 필수 / 파일 필수 / 설명 선택) → `category=OTHER` POST. 다건 누적, 행별 교체·삭제.
- 요약 StatCard: 보관 N건 / 고정 미등록 N건(실데이터).
- **만료일 (CR-136)**: 고정 카드와 기타 서류 줄에 만료일과 남은 날(D-n, 만료됨)을 한 줄로 보인다. 기타 서류 등록·고치기 창에 만료일 칸(선택, 날짜 고르기 칸)을 더한다. 고정 카드는 유효기간 알림 화면에서 넣는다. 머리에 유효기간 알림 바로가기.
- **슬롯 자동채움**(입찰 상세/제안서 슬롯 화면): "서류함에서 자동 채우기" 버튼 → `auto-fill` 호출 → 슬롯 목록 갱신 + "N건 자동 채움" 토스트. 서류함에 없는 카테고리는 미충족 유지.
