# SAM.gov Bidding Agency Platform 화면 상호작용 명세서

> 설계 버전: 1.0 | 최종 수정: 2026-03-19 | 관련 CR: -

> 단계: 3. Detail Design | FE/풀스택 프로젝트에서 작성
>
> T3-3(화면 구조)이 "무엇이 있는지"를 정의한다면,
> 이 문서는 "어떻게 동작하는지"를 정의한다.
> 모든 페이지를 작성하지 않는다 — 복잡한 인터랙션이 있는 페이지만 작성한다.

---

## 작성 대상

| 페이지 | 사유 |
|--------|------|
| 공고 상세 — 입찰 신청 | 다단계 흐름 (서비스 레벨 선택 → 신청) + 자격 진단 연동 |
| 입찰 상세 — 문서 업로드 | 파일 업로드 + 진행률 + 상태 자동 전이 |
| 문서 편집 (Admin) | TipTap 에디터 + 버전 관리 + 잠금/해제 + PDF 내보내기 |
| 입찰 상세 관리 (Admin) | FSM 상태 전이 UI + 조건부 액션 |

---

## 공고 상세 — 입찰 신청 (`/search/{id}`)

### 진입 조건

- **인증**: 공고 열람은 불필요, 입찰 신청은 🔒 필요
- **권한**: CUSTOMER
- **선행 조건**: 없음 (공고 ID로 직접 접근 가능)
- **진입 불가 시**: 404 페이지 (공고 미존재)

### 데이터 로딩

| 순서 | API 호출 | 타이밍 | 실패 시 |
|------|---------|--------|--------|
| 1 | GET /opportunities/{id} | 페이지 진입 | 에러 메시지 표시, 목록으로 이동 유도 |
| 2 | GET /opportunities/{id}/requirements | 페이지 진입 | 요구사항 영역 빈 상태 표시 |
| 3 | GET /opportunities/{id}/attachments | 페이지 진입 | 첨부문서 영역 빈 상태 표시 |
| 4 | GET /bookmarks/{id}/status | 로그인 상태일 때 | 북마크 버튼 비활성 |

### 사용자 인터랙션 시나리오

#### 시나리오 1: 입찰 참여 신청 (정상 흐름)

| 단계 | 사용자 행동 | 시스템 반응 | API |
|------|-----------|-----------|-----|
| 1 | "입찰 참여" 버튼 클릭 | 미로그인 → 로그인 페이지 이동 (returnUrl 보존) | — |
| 2 | 서비스 레벨 선택 (4개 중 택 1) | 선택된 레벨 하이라이트, 포함 서비스 표시 | — |
| 3 | "신청하기" 버튼 클릭 | 확인 모달 표시 ("이 공고에 입찰하시겠습니까?") | — |
| 4 | 확인 | 로딩 스피너 → 성공 시 입찰 상세 페이지 이동 | POST /bid-requests |
| 5 | — | 토스트: "입찰 신청이 완료되었습니다" | — |

#### 시나리오 2: 중복 신청 에러

| 단계 | 조건 | 시스템 반응 |
|------|------|-----------|
| 4-1 | 동일 공고에 이미 신청 존재 (BIZ-006) | 에러 토스트: "이미 이 공고에 입찰 신청하셨습니다", 기존 입찰 상세로 이동 링크 |

#### 시나리오 3: 자격 진단 요청

| 단계 | 사용자 행동 | 시스템 반응 | API |
|------|-----------|-----------|-----|
| 1 | "자격 진단" 버튼 클릭 | 미로그인 → 로그인 페이지 | — |
| 2 | — | 로딩 스피너 + "AI가 분석 중입니다" | POST /opportunities/{id}/qualification-check |
| 3 | — | 진단 결과 표시 (충족/미충족/확인필요 항목별) | — |
| 4 | — | 면책 고지 표시 (BIZ-014) | — |

## 입찰 상세 — 문서 업로드 (`/proposals/{id}`)

### 진입 조건

- **인증**: 🔒 필요
- **권한**: CUSTOMER (본인 입찰만)
- **선행 조건**: 입찰 신청 완료 (BidRequest 존재)
- **진입 불가 시**: 403 (타인 입찰) 또는 404

### 데이터 로딩

| 순서 | API 호출 | 타이밍 | 실패 시 |
|------|---------|--------|--------|
| 1 | GET /bid-requests/{id} | 페이지 진입 | 에러 메시지, 목록으로 이동 |
| 2 | GET /bid-requests/{id}/history | 페이지 진입 | 이력 영역 빈 상태 |
| 3 | GET /bid-requests/{id}/client-documents | 페이지 진입 | 문서 영역 빈 상태 |
| 4 | GET /bid-requests/{id}/documents | 페이지 진입 | 생성 문서 영역 빈 상태 |

### 사용자 인터랙션 시나리오

#### 시나리오 1: 문서 업로드 (정상 흐름)

| 단계 | 사용자 행동 | 시스템 반응 | API |
|------|-----------|-----------|-----|
| 1 | "문서 업로드" 영역에 파일 드래그 또는 클릭 | 파일 선택 다이얼로그 | — |
| 2 | 파일 선택 (≤ 50MB) | 업로드 프로그레스바 표시 | POST /bid-requests/{id}/client-documents |
| 3 | — | 업로드 완료 → 문서 목록 갱신, 진행률 업데이트 | — |
| 4 | 모든 필수 문서 제출 완료 | "모든 필수 문서가 제출되었습니다" 안내 | — |

#### 시나리오 2: 파일 크기 초과

| 단계 | 조건 | 시스템 반응 |
|------|------|-----------|
| 2-1 | 파일 > 50MB (BIZ-011) | 에러 토스트: "파일 크기가 50MB를 초과합니다", 업로드 차단 |

### 상태별 UI 분기

| BidRequest 상태 | 문서 업로드 | 취소 버튼 | 생성 문서 |
|----------------|-----------|----------|----------|
| CREATED | 비활성 | 활성 | — |
| DOCS_PENDING | **활성** | 활성 | — |
| DOCS_RECEIVED | 비활성 | 비활성 | — |
| ANALYZING ~ GENERATING | 비활성 | 비활성 | "AI 작성 중" 표시 |
| REVIEW ~ CONFIRMED | 비활성 | 비활성 | 문서 미리보기 가능 |
| SUBMITTED | 비활성 | 비활성 | 최종 문서 보기 |
| CLOSED | 비활성 | 비활성 | — |

## 문서 편집 — Admin (`/bid-requests/{id}/documents/{docId}`)

### 진입 조건

- **인증**: 🔒 필요
- **권한**: ADMIN
- **선행 조건**: BidRequest가 REVIEW 상태, BidDocument가 DRAFT 상태
- **진입 불가 시**: 에러 메시지 + 입찰 상세로 리다이렉트

### 데이터 로딩

| 순서 | API 호출 | 타이밍 | 실패 시 |
|------|---------|--------|--------|
| 1 | GET /bid-documents/{id} | 페이지 진입 | 에러 → 입찰 상세로 이동 |
| 2 | GET /bid-documents/{id}/versions | 페이지 진입 | 버전 사이드바 빈 상태 |

### 사용자 인터랙션 시나리오

#### 시나리오 1: 문서 편집 + 저장

| 단계 | 사용자 행동 | 시스템 반응 | API |
|------|-----------|-----------|-----|
| 1 | TipTap 에디터에서 내용 수정 | 변경 감지 → "저장" 버튼 활성화 | — |
| 2 | "저장" 버튼 클릭 | 변경 요약 입력 모달 | — |
| 3 | 변경 요약 입력 + 확인 | 로딩 → 새 버전 생성 → 버전 사이드바 갱신 | POST /bid-documents/{id}/versions |
| 4 | — | 토스트: "v{N} 저장되었습니다" | — |

#### 시나리오 2: 문서 잠금 (확정)

| 단계 | 사용자 행동 | 시스템 반응 | API |
|------|-----------|-----------|-----|
| 1 | "확정" 버튼 클릭 | 확인 모달: "확정 후 편집이 불가합니다. 확정하시겠습니까?" | — |
| 2 | 확인 | 로딩 → DRAFT → LOCKED | POST /bid-documents/{id}/lock |
| 3 | — | 에디터 읽기 전용 전환, "확정" 버튼 → "잠금 해제" 변경 | — |

#### 시나리오 3: 잠금 해제

| 단계 | 사용자 행동 | 시스템 반응 | API |
|------|-----------|-----------|-----|
| 1 | "잠금 해제" 버튼 클릭 | 확인 모달 | — |
| 2 | 확인 | LOCKED → DRAFT, BidRequest도 REVIEW로 복귀 | POST /bid-documents/{id}/unlock |
| 3 | — | 에디터 편집 모드 복원 | — |

#### 시나리오 4: PDF 내보내기

| 단계 | 사용자 행동 | 시스템 반응 | API |
|------|-----------|-----------|-----|
| 1 | "PDF" 버튼 클릭 | 로딩 → PDF 생성 → 다운로드 시작 | GET /bid-documents/{id}/export/pdf |

### 상태별 UI 분기

## 입찰 상세 관리 — Admin (`/bid-requests/{id}`)

### 진입 조건

- **인증**: 🔒 필요
- **권한**: ADMIN
- **선행 조건**: 없음
- **진입 불가 시**: 404

### 데이터 로딩

| 순서 | API 호출 | 타이밍 | 실패 시 |
|------|---------|--------|--------|
| 1 | GET /admin/bid-requests/{id} (또는 /bid-requests/{id}) | 페이지 진입 | 에러 → 목록으로 이동 |
| 2 | GET /bid-requests/{id}/next-states | 페이지 진입 | 상태 전이 버튼 비활성 |
| 3 | GET /bid-requests/{id}/history | 페이지 진입 | 이력 빈 상태 |

### 사용자 인터랙션 시나리오

#### 시나리오 1: 상태 전이

| 단계 | 사용자 행동 | 시스템 반응 | API |
|------|-----------|-----------|-----|
| 1 | 허용 다음 상태 버튼 중 하나 클릭 | 노트 입력 모달 표시 | — |
| 2 | 노트 입력 (선택) + "전이 실행" 클릭 | 로딩 → 상태 변경 | POST /admin/bid-requests/{id}/transition |
| 3 | — | 상태 패널 갱신, 이력 추가, 토스트 알림 | — |

#### 시나리오 2: 금지된 전이 시도

| 단계 | 조건 | 시스템 반응 |
|------|------|-----------|
| 2-1 | FSM 화이트리스트에 없는 전이 (BIZ-001) | 에러 토스트: "현재 상태에서 해당 전이가 불가합니다" |
| 2-2 | BLOCKER 미충족 상태에서 CONFIRMED 전이 (BIZ-007) | 에러 토스트: "필수 요구사항이 미충족 상태입니다" |
